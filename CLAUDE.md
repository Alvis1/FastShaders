# FastShaders

Bi-directional TSL (Three.js Shading Language) visual shader editor. Users author and execute their own shader code inside the app, and `.fastshader` files can be shared between users — treat any loaded `.fastshader` or pasted shader source as adversarial input.

> **Before changing node visuals, the glyph system, `ShaderNode`, `NodePreviewCard`, or the Node Designer (`node-designer.html`), read [`NODE_DESIGN_REQUIREMENTS.md`](NODE_DESIGN_REQUIREMENTS.md) — it is the authoritative spec for node appearance/layout.**

## Stack

- React 18 + TypeScript + Vite (ES modules, base path `/FastShaders/`)
- `@xyflow/react` v12 — node graph editor
- `@monaco-editor/react` — code editor
- `zustand` v5 — state management
- `@babel/parser` + `@babel/traverse` — code→graph parsing
- `@dagrejs/dagre` — auto-layout (LR direction)
- `three` (WebGPU build) — shader runtime; FastShaders uses only `three/tsl`
  built-in functions including the MaterialX noise family (`mx_noise_*`,
  `mx_fractal_noise_*`, `mx_worley_noise_*`, `mx_cell_noise_float`)
- Path alias: `@/*` → `./src/*`

## Commands

- `npm run dev` — start dev server (port 5173)
- `npm run build` — typecheck + build (`tsc -b && vite build`)
- `npx tsc --noEmit` — typecheck only
- `npm test` — run the vitest suite once (CI-friendly)
- `npm run test:watch` — run vitest in watch mode
- `npm run tauri dev` / `npm run tauri build` — desktop (Tauri v2) shell; needs a local Rust toolchain. Releases are built in CI (no local Rust required)

## Deployment

**When the user says "deploy" (or "deploy to all"), it ALWAYS means: commit the pending work, push, and ship to BOTH targets** — never stop after the release pipeline:

0. **Commit + push first**: commit whatever is pending in the working tree (and push the `a-frame-shaderloader` submodule first if it changed) — "deploy" is standing authorization to commit and push; don't ask again.
1. **Release pipeline** (web on GitHub Pages + desktop binaries, in lockstep): `npm version patch && git push --follow-tags`. The `v*` tag triggers `.github/workflows/release.yml` → tests, macOS `.dmg` + Windows installers, gh-pages deploy.
2. **alvismisjuns.lv**: `npm run deploy:alvismisjuns` — builds with `FS_BASE=/fastshaders/` + the alvismisjuns CSP origins and uploads `dist-alvismisjuns/` via psftp to `https://alvismisjuns.lv/fastshaders/` (credentials in the gitignored `.vscode/sftp.json`; needs `brew install putty`). `-- --no-build` re-uploads the existing snapshot. Run it from the SAME committed/tagged state as step 1 so both hosts serve the same version — it deploys the working tree, not the last tag. The script curl-verifies the deployed version meta at the end.

- Shared test factories live in `src/test-utils.ts` (`makeNode`, `makeEdge`). Always import these instead of redefining stub builders in each test file — the helpers cast through `unknown as AppNode/AppEdge` to skip React Flow's full Node generic constraints.

    — **the Uniforms overlay is the ONE place uniforms are tuned live.** It lists only CONNECTED properties (`utils/connectedUniforms`, pure + tested): a disconnected property still emits `uniform(…)` and reaches the schema, but scrubbing it would do nothing. Names are matched by the EMITTED var name (`nodeVarNames`), never the stored one — two properties may share a name (same preset dropped twice) and codegen uniquifies the later one (`colorA` → `colorA2`), which the stored-name match silently dropped from the overlay; the stored name is the fallback that covers a code-panel Apply, where fresh node ids miss every `nodeVarNames` lookup. Live scrubbing stays overlay-local (writing back would tear down the iframe); **"Set as default" is the write-back**, baking values into the property nodes → the graph→code sync then updates the code and the export. The Output node's settings menu deliberately has NO uniforms list — it duplicated the node's own editor, and showed float properties but not colour ones. Tuning still persists, but it no longer wins SILENTLY: a row whose stored value differs from the authored default shows a `graph <n> ↺` chip carrying the GRAPH's number beside the row's own value (the PREVIEW's), so each surface displays the one the other is hiding, and clicking it adopts the graph value; the collapsed Uniforms button carries a dot so a shut overlay can't hide an override, and "Set as default" highlights with a count. The override bookkeeping runs on the CONNECTION-AGNOSTIC uniform list (`nonMicUniforms`) even though the rows don't: a value edited while its property is disconnected has no row, so a filtered list would miss it and the stale value would re-apply the instant the wire landed — the same trap, one wire away. ## Key Conventions

- **Offline/desktop**: the app must run with NO network. Monaco is bundled locally (`CodeEditor/monacoSetup.ts` — `loader.config({ monaco })` + Vite `?worker` workers; never reintroduce the jsdelivr CDN loader) and fonts are self-hosted (the `@fontsource/inter/*.css` + `@fontsource/jetbrains-mono/*.css` weights are imported directly in `main.tsx` AND `nodeEditor.tsx`, and the `fs-fontsource-woff2-only` vite plugin strips the legacy `.woff` fallback `src` from the vendored @fontsource CSS at build time so only the woff2 subsets ship — never reintroduce a jsdelivr/Google-Fonts CDN link). `FS_DESKTOP=1` — set automatically for `tauri dev`/`tauri build` via the CLI's `TAURI_ENV_*` env — switches vite to the desktop profile: base `/`, CSP meta suppressed, ShaderCarousel excluded from dist (it ships instead as a Tauri resource staged in `src-tauri/carousel-dist/`, served over LAN by the in-app bench server — see the src-tauri bullet under Subprojects), and the `__FS_DESKTOP__` define hides the Local button + SC link and shows the "VR" bench popover. Preview-iframe asset URLs resolve via `new URL(base + path, location.href)` (`resolveAssetUrl` in `tslToPreviewHTML.ts`) so they survive non-http schemes (tauri://) — don't revert to `location.origin` concatenation.
- **Feedback ("!" toolbar button)**: the red `!` in the toolbar's right cluster opens `Modals/FeedbackModal` — a composer that assembles a plain-text report and hands it to the user's own mail client via `mailto:`, with a clipboard fallback. **Nothing is uploaded, and that is a constraint rather than a preference**: the build CSP is `connect-src 'self' blob: <deploy origin>` + `form-action 'self'` (`vite.config.ts`), so a POST to Formspree / Google Forms / any hosted endpoint is blocked by the app's OWN policy; the desktop build must work with no network at all; and a third-party form would make someone else a data processor for grant-funded research feedback. A `mailto:` navigation is CSP-exempt (navigation, not a fetch) and works in every build. If a server-side endpoint is ever wanted, it needs a `connect-src` widening plus the mailto path kept underneath for the offline case — don't quietly swap one for the other. Report assembly is PURE and tested in `utils/feedbackReport.ts` (the DOM reads live in the modal): the opt-in technical block carries version/build, **graph counts (nodes, how many are connected, connections, groups, notes), cost points vs the selected headset profile, and the preview mesh (built-in geometry name, or a custom model's name + vertex count + size)**, then browser/platform/renderer/display. Counts only — no graph content leaves. Edges are counted on the UNWRAPPED graph (`unwrapCollapsedGroupEdges`), or the same project would report differently depending on which frames happened to be collapsed. `previewMesh.countMeshVertices` is a **deliberate, narrow exception** to that module's "bytes are never parsed on the trusted side" rule: it counts OBJ `v` lines or reads integers out of a length-capped glTF JSON header — no geometry built, no URI resolved, no buffer touched, every path bounded, every failure returning null. It reports the AUTHORED vertex count, not what THREE ends up with (the OBJ loader emits non-indexed geometry and `fit-bounds` then welds duplicates), so don't reason about GPU cost from it. Also: `MAILTO_SAFE_CHARS` steers over-long reports to "Copy report" because Windows' shell truncates `mailto:` URLs around 2000 chars — a silently truncated bug report is worse than none, since the user believes they sent it. `previewBackend()` RESTATES the `__fsForceWebGL2` rule that `tslToPreviewHTML` emits as source text into the iframe (it can't be imported and called); `feedbackReport.test.ts` extracts that emitted function from the generated HTML, evaluates it, and fails if the two disagree — so a change to the WebKit-forcing rule can't silently make feedback reports lie about which renderer the user was on.
- **Sync engine**: `syncSource` field in zustand (`'graph'` | `'code'`) prevents infinite sync loops. `useSyncEngine` hook manages bidirectional sync with `lastSyncedCodeRef` to skip no-op updates
- **Node values**: always use `getNodeValues(node)` from `@/types` — never cast `node.data as ...`
- **Edge IDs**: always use `generateEdgeId(source, sourceHandle, target, targetHandle)` from `@/utils/idGenerator`
- **Single ShaderNode**: one component handles all TSL node types dynamically via registry
- **Latvian i18n is a display-only overlay** (`src/i18n/`): node types, TSL identifiers, generated code, and `data.label` stay canonical English — canvas node headers deliberately show the generated varName (`mul1`), so bilingual "Latviešu (English)" labels appear only where you pick/read about a node (Add-node menu, content browser, tooltips, settings menus, node designer). `language: 'en' | 'lv'` lives in the store, persists to `fs:lang`, stamps `<html lang>`, and is toggled by the Toolbar LV button; missing translations fall back to English.
- **Node search is RANKED, and `description` is part of the corpus**: `nodeMatchRank` in `nodeRegistry.ts` is the ONE match+order rule, shared by the AddNodeMenu (`searchNodes`) and the ContentBrowser (`rankDefs`) so both surfaces order a query identically. Tiers, lower wins: exact name (label / type / `tslFunction` / Latvian label) → name prefix → name substring → the `Also: …` alias tail → English prose → Latvian prose; `NO_MATCH` filters out. Ties keep registry order (stable sort). This exists because results used to come back in raw registry order, so a node that merely MENTIONED the query in its prose could outrank the node actually named that — writing "speed multiplier" into the Time description put Time above Multiply for "multip". So: keep UI-instruction wording out of `description`, put search aliases in the `Also:` tail (`displayDescription` strips it from the UI), and never let prose repeat another node's name casually. `nodeSearch.test.ts` pins the ordering and sweeps every description for name collisions.
- **Adding a node — one placement path**: right-click canvas, **Shift+A** (opens AddNodeMenu at canvas centre; the search box autofocuses, so Arrow/Enter completes a keyboard-only add), dropping a wire on empty space, dragging a palette tile, or **clicking/Entering a palette tile**. Every tile route funnels through `tileDrag.ts` — `tileActivationProps` → `dropTileAtCanvasCenter` dispatches the SAME `fs-tile-drop` CustomEvent the touch-drag path uses, so `placeTilePayload` (including drop-on-edge splicing) stays the single implementation. Don't add a parallel placement path. AddNodeMenu rows render `def.description` (`.context-menu__item--stacked`; the modifier exists because `.context-menu__item` is a shared single-row flex used by every submenu).
- **One node, one look — the CANVAS is the reference.** A node is drawn on four surfaces: the graph canvas (`nodes/*`, the live implementation and the thing every other surface must match), the asset-browser tiles (`NodePreviewCard`), the node-editor.html overview (the same cards, plus a `GraphModal` that renders the REAL canvas components), and the Node Designer's stage (`NodeVisual` via `nodeDesigner/bridge`). Only the `shader` flow type gets there through the shared `NodeVisual` replica; `color`/`preview`/`mathPreview`/`clock`/`mic`/`output` each need a hand-written card, and **every hand-written card is a drift site**. The rules that keep them honest: (1) **a node's styling must never depend on which page draws it** — the `.react-flow .drag-num` opaque number plate was the live instance (identical widget, crisp on the canvas and washed-out on every tile; the designer only escaped by hand-mirroring the rule in `node-designer.html`), so the on-node look now sits on `.drag-num--compact` itself, which IS the on-node variant. Same shape as the `.mic-node`-scoped arm light. `.react-flow .node-base__cost-badge` is the one DELIBERATE exception (documented in NodeBase.css: the asset bar is outside the canvas and keeps the cost-gradient colour). (2) **Shared geometry/drawing beats a copied replica**: `micGeometry.ts` (mic box + socket rows), `utils/clockFace.ts` (the Time face — the card used to hold a second copy that seeded its hand from `Date.now()`, so the tile pointed somewhere a freshly dropped node never does; it draws phase 0 now), `COLOR_NODE_SIZE` + `LABEL_MAX/MIN_PX` (the colour swatch, which had an 84/2/15px twin of the canvas's 56/1.5/10px, reverse-engineered against the strip's `zoom: 0.67` — the card now renders the REAL `.color-node` classes counter-scaled by `CARD_COLOR_SCALE`, which also got it the long-name wrap/clip/fit-text rules its twin silently lacked). (3) **A `<div>` replica cannot match `:disabled`** — the inert mic light needs the explicit `--inert` class or a tile shows enabled-green beside a grey unwired canvas node. (4) **Fake handles read the real tokens** (`--handle-size`/`--handle-border`): hardcoded 10px went wrong on touch, where tokens.css bumps the real socket to 12px. (5) **Every flow type needs a dispatch branch** — `output` had none and fell through to the generic shader card, which turned a 7-input def into seven editable number boxes; the overview showed that beside a `GraphModal` rendering the real Output node. Deleting a replica is the best fix available: the slider tile's hand-built track/thumb/labels are gone, and it renders the same `<input type="range">` the canvas and designer do. (6) **A node title is capped at TWO rows, and the node WIDENS rather than growing a third.** Two rules do that together: `.node-base__title` is `overflow-wrap: normal` (never split a word) plus a 2-line clamp, and the authored designer width is applied as the PREFERRED width with `min-width: min-content` as the floor — so a designed node keeps its exact width while the content fits and grows only when it genuinely cannot. This matters because the canvas header shows the GENERATED VAR NAME, which is a single unbreakable run: `cameraPosition1` on a designer-narrow node used to shatter into `camera`/`Position`/`1` and grow a header taller than the node's own body, while that same node's tile — already refusing to break words — showed it on one line. Both `ShaderNode` and `NodeVisual`'s `exactWidth` branch set it, so the designer stage previews what the canvas will do, and every header carries a `title` so a clamped name stays readable on hover.
- **What the Node Designer can and cannot edit**: `ndData.designerNodes()` is `getAllDefinitions().filter(d => getFlowNodeType(d) === 'shader')` — the designer authors a `customGlyphs.ts` entry (glyph SVG, justify/scale/dx/dy, width/height, text scale, socket offsets) and previews it through `NodeVisual`, so a node is designable exactly when NodeVisual draws it. The **15 excluded types have no glyph to author and are not drawn by NodeVisual at all**: `output`, `time`, `micNode`, `color`/`property_color`, the 8 noise nodes, `sin`/`cos` — each renders through its own component with its own hardcoded geometry (`micGeometry.ts`, `CLOCK_SIZE`, `COLOR_NODE_SIZE`, the preview canvases). Opening one in the designer would show a stage with nothing the model can change. Making any of them designable is therefore not a filter tweak: it needs the node's geometry moved into the designer's model (and, for the mic, its absolutely-placed sockets expressed in `customGlyphs`' center-relative `sockets` vocabulary) — a real feature, not a gap.
- **Node visuals**: per-node designer overrides live in `glyphs/customGlyphs.ts` — `{ svg, justify, scale (glyph-only; spacing fixed), dx/dy (glyph nudge), width (exact, ≥24), height (exact in both layouts, ≥28; shorter than content overflows; independent of glyph scale), text (0.4–2.5× header/value/label fonts via --node-text-scale), sockets (center-relative offsets, 4px snap; op layout natively, rows layout detaches the socket from its row — values follow) }`; frame radius/border are **fixed app-wide**. Connected inputs show edge values (`min…max` ranges, bare `…` when underivable; geometry attributes have analytical ranges). Multi-channel data **arriving on a connected input** stacks the node into N cards (sibling layers behind the card, staggered negative z, single group shadow from the deepest layer). Sockets are **static** — never set `transform` on handle `:hover` (React Flow positions handles via transform) — and never stack. **Every node PREVIEW surface renders through ONE component** — `nodes/NodeVisual.tsx` (asset cards, node-editor overview, the Node Designer's stage) — so a preview can no longer drift from the editor; ShaderNode stays the live implementation NodeVisual mirrors (change them together). **Movable node art**: for glyph-less art nodes (the Colormap ramp) the same `dx`/`dy`/`scale` fields transform the art element via `nodeArtStyle` (CSS px, purely visual — sockets/rows never move); the designer drags the ramp like a glyph. The Node Designer (`node-designer.html`, a Vite entry backed by `src/nodeDesigner/`) saves via the dev-server endpoint `/__nd` (any browser), the File System Access API (Chromium), or download; see `NODE_DESIGN_REQUIREMENTS.md`
- **Node selection is a FILLED band**: every node shell (`.node-base` + its stacked `__stack-frame`, `.output-node`, `.note-node`, `.color-node`) marks selection with `box-shadow: 0 0 0 var(--node-selection-width) <colour>` — NOT `outline` + `outline-offset`, which drew a thin ring with a canvas-coloured gap inside it and read as two competing borders. Consequences to respect: box-shadow REPLACES rather than adds, so each rule must re-state `var(--shadow-node)` or selecting a node flattens it; the colour is the node's own `--node-cat` (falling back to `--border-focus`, which is what the category-less colour swatch uses); and `--node-selection-width` is deliberately NOT redefined in the dark block, since graph nodes render identically in both themes. A STACKED node suppresses its own band (`box-shadow: none`) because `.node-base__stack-frame` draws one band around the whole stack — ShaderNode also sets that inline, which wins on specificity.
- **Light theme by default, app-wide dark mode**: flat design with sharp dark shadows, CSS tokens in `tokens.css`. The toolbar sun/moon button (`codeEditorTheme`, persisted to `fs:codeEditorTheme` — the store field keeps its historical name) is the ONE dark-mode control: it themes Monaco AND stamps `data-theme="dark"` on `<html>` (via `setCodeEditorTheme` + an inline FOUC guard in `index.html`), which flips the CHROME tokens redefined in `tokens.css`'s `:root[data-theme="dark"]` block (backgrounds, text, borders, chrome shadows, `color-scheme`). **Graph nodes must render identically in both themes** — node bodies read the theme-invariant `--node-bg` (not `--bg-panel`), node text/borders are hardcoded literals or inline cost/category colors, and `--shadow-node*`/`--type-*`/`--cost-*`/`--cat-*` are deliberately NOT redefined in the dark block. Per-surface dark tweaks (hardcoded light-assuming literals that tokens can't reach) live as `:root[data-theme="dark"]` blocks in each component's own CSS; the React Flow grid color is a prop flipped in `NodeEditor.tsx`. The canvas background is user-pickable AND remembered PER THEME (`nodeEditorBgColorLight`/`Dark`; `nodeEditorBgColor` is the effective active-theme value; dark default `#1e1f22`); cost badges and 1-channel edges auto-flip via `getContrastColor(nodeEditorBgColor)` so they invert to light on the dark canvas automatically. `projectImport` applies theme BEFORE canvas color so the color lands in the right per-theme slot.
- **A-Frame pipeline**: graphToCode → tslToShaderModule → shaderloader 0.5 (runtime TDZ fix + auto-import injection + typed `export const schema` parsing — `number`/`color`/`map`) → dynamic blob import. (The old standalone `.html` export left with the A-Frame tab — the `.js` download is the only export.) Shaderloader 0.4 is FROZEN: shaders exported before 0.5 reference it from the jsdelivr CDN, so never edit it — new loader work goes in 0.5 (or a bump).
- **Preview renderer backend (WebGPU vs WebGL2)**: the sandboxed preview iframe (`tslToPreviewHTML.ts`) and the standalone podest viewer (`public/podest.html`) both inject `<a-scene>` only AFTER a WebGPU pre-flight — three r184 auto-selects WebGPU on `navigator.gpu != null` ALONE, so the pre-flight requests a real adapter (2s timeout) and hides `navigator.gpu` (→ WebGL2 via GLSLNodeBuilder, TSL compiles identically) when it can't deliver. **Safari is force-hidden to WebGL2 up front** (`__fsIsSafari` UA check) — three r184's WebGPU backend can be handed an adapter yet never paint on Safari (flat-color pane, no error). Same move the XR popup already makes. A 6s watchdog turns any remaining no-paint into a visible sticky error.
- **Podest unattended / pedestal mode** (`public/podest.html`): the viewer is meant to run for WEEKS with nobody touching it, which is a different problem from "a page that works". The presentation layer is the ⛶/⤡ fullscreen button (bottom-right) plus an optional top-centre title (auto-derived from the dropped file name, `_`→space, click it to edit text + colour; `textContent` only). **Presentation mode is deliberately WIDER than the Fullscreen API**: fullscreen needs a user gesture, and an unattended pedestal has nobody to give one after a browser auto-update — it would come back windowed with the panel over the artwork and, far worse, no wake lock, so the display blanks at the OS idle timeout and stays black for the week. So the mode is remembered (`fs:viewerPresenting`, or `?present=1` for a kiosk launcher) and `is-present` on `<html>` — not `is-fs` — is what hides the panel, hint and error banner; `is-fs` governs only the ⛶ button's own auto-fade, since in windowed presentation that button is the way back in (⛶ then Esc leaves the remembered mode). Everything that must survive the reload asks `presenting()`, never `fsElement()` — **including the release-race guard inside `requestWakeLock`**, which gated on fullscreen would release every lock the instant its promise resolved and silently undo the whole thing. Behind that sit five long-run guards, each fixing something that actually breaks on that timescale: (1) **the stage iframe is disposable** — `applyStateToStage()` replays background/spin/geometry/shader on every `fs:ready`, so the pending queue is DISCARDED rather than flushed (replaying both would recompile the shader twice) and any restart is invisible; (2) **`time` is folded back every ~4.5 h** — three's `time` is a float32 accumulating seconds since boot, so its resolution decays to 7.8 ms after a day, 62 ms after a week and 250 ms after a month (a slideshow); the stage takes `renderer._nodes.nodeFrame.time %= TIME_WRAP` where `TIME_WRAP` is an exact multiple of 2π (~16380 s), so `sin(time)`/`cos(time)` cross the fold with NO visible jump and the quantum never exceeds ~1 ms (a shader's own `time.mul(20)` multiplies it) — modulo not zeroing, so the fold stays 2π-aligned however far behind the beat has fallen; if that private path ever disappears the beat reports `wrapNeeded` (rebasing as it fires, so it can't latch) and the parent restarts the stage instead. The stage also rebases `nodeFrame.lastTime` on `visibilitychange`→visible, or the first frame after an overnight sleep would dump the whole hidden gap into `time` in one step; (3) **device loss is terminal and silent** — the stage wraps `renderer.onDeviceLost` (keeping three's own handler) AND hooks the raw `backend.device.lost` promise, because three returns early on `reason === 'destroyed'` and would never call the callback, plus a `webglcontextlost` listener; all report `fs:stage-dead`, and a 5 s `fs:beat` carrying the cumulative `info.render.calls` lets the parent catch a stall with no throw at all (best-effort: it proves the loop ran, not that pixels landed); restarts are floored at 30 s apart and after 6 in a row back off to one retry every 10 min — never a permanent give-up, since a transient driver fault must not end the exhibit (watchdog is suspended while the document is hidden — a frozen counter there is normal); (4) **the last drop is mirrored to IndexedDB** (`fs-podest`/`session`, throw-safe, shader ≤24 MB + model ≤64 MB) and replayed at boot, because a browser auto-update or power blip otherwise leaves a grey sphere — the record carries the tuned **uniform values** too (losing the exhibitor's tuning shows the wrong artwork), a drop that lands first always wins, and a user-typed title outranks the replayed one; (5) **the screen wake lock** is requested at boot, on entering presentation mode, on `visibilitychange`, and again on every 5 s watchdog tick — the platform can drop a lock on its own and a UA may refuse it until it can grant it, so the only robust pattern is to keep asking (it early-returns when a lock is already held). Also: the error relay is rate-limited IN the sandbox (identical repeats/minute + 20/minute cap) since a per-frame `console.error` would otherwise postMessage forever, banners self-dismiss after 20 s, and 90 s of idle in fullscreen returns the camera to the framing pinned by `fs:save-view` at entry (a visitor's spin must not outlive them). **Checked and deliberately NOT fixed**: the bundle's anime.js calls the undeclared `activeInstance[i].pause()` on visibilitychange, but A-Frame builds its instances with `autoplay:false` and ticks them by hand, so anime's active list is always empty and that line never runs (verified in a browser).

- **Edge interactions** (`TypedEdge` + `bezierGeometry.ts` + `NodeEditor` handlers): edges are drag-to-disconnect, and support (1) **drop-on-edge insertion** — dragging a node/tile within `DROP_ON_EDGE_RADIUS` (screen px ÷ zoom) of an edge splices it in (`findNearestEdge`/`tryInsertOnEdge`), and (2) **routing waypoints** — double-click an edge or right-click → "Add routing point" drops a draggable point the wire curves through (Catmull-Rom spline); double-click a point removes it. Waypoints live on `edge.data.waypoints` (flow coords), are **visual-only** (graphToCode/cpuEvaluator never read them; persist via localStorage autosave + undo, and are carried across a code→graph resync by endpoint match in `useSyncEngine` — like groups; a fresh `.js`/zip import starts without them). **The renderer and the drop-on-edge hit test share `bezierGeometry.ts`** so what highlights is exactly what snaps — a routed edge is measured against the SAME spline it draws (`distancePointToSpline`). `setEdgeWaypoints` pushes history once per gesture (add/remove/drag-start), never per drag-move frame. **A splice lands on the node's first FREE input, not always its first** (`edgeSplice.ts`, pure + tested): dragging an already-wired node onto a new edge used to delete whatever fed `inputs[0]`, so a half-built Multiply lost the operand you had just given it. Candidates come from `effectiveInputs(def, connected, /*trailing empty*/ true, valued)` — so a variadic fold GROWS a fresh socket instead of reporting itself full (`append` stops at its `maxOperands`), and hidden `exposedPorts` params (Image's `uv`, Mic's `gain`) stay eligible in plain registry order with `tryInsertOnEdge` calling `exposeConnectedTarget` so the new edge can't point at a socket that never mounts. Only when EVERY socket is taken does it fall back to `inputs[0]` and replace that edge — the historical behaviour. Splice-time cycle risk is unchanged by this (reachability out of the node depends on its OUTGOING edges, and the port the splice picks is incoming).
- **Drag-connect** (`dragConnect.ts` + NodeEditor drag handlers): dragging a node so its CENTER lands on another node's body proposes a connection — the hovered node rings (`fs-connect-target`), the chosen input socket rings, and a tooltip names it; releasing commits exactly what the tooltip showed (even on a sub-`DRAG_HISTORY_THRESHOLD` drop — a shown preview must not lie; the plan's endpoints are re-validated at drop against mid-drag mutations like held-pointer Cmd+Z). Direction follows the side (dragged left of the hover's center → dragged.out feeds hover.in; right → hover.out feeds dragged.in; impossible/cyclic directions fall back to the other before giving up), vertical alignment picks the best (output, input) PAIR — so multi-output sources like Data-node columns choose their column by alignment too — with FREE inputs beating occupied (occupied only replaced when nothing is free; the gesture counterpart's own existing edge doesn't count as occupying, so re-docking a feeder re-recognizes its connection instead of double-feeding a second input), and cycles are never offered. Cycle/occupancy checks run on the UNWRAPPED logical graph (`unwrapCollapsedGroupEdges`) — raw collapsed-group boundary edges would contract members into one vertex and fabricate cycles. Hit boxes follow the VISIBLE card (cost-scaled types multiply the measured box by `getCostScale`). The drop snaps the node beside its new peer (handles aligned, `CONNECT_SNAP_GAP` apart) and then MAKES ROOM (`overlapCascade.ts`): the connected pair stays fixed and overlapped nodes escape along the cheapest single axis (+10px gap) that clears ALL current offenders AND the whole settled set — the full-set check is load-bearing: a greedy per-box push ping-pongs a wide mover in the corridor between the two anchors (the exact geometry every snap creates) — with knock-on pushes rippling outward (BFS, settle-once — deterministic, terminates; a cascade beats a grid here because node footprints vary ~10× and minimal displacement preserves the user's layout). Deltas are absolute-space applied to local positions (parent-invariant), and every shifted node (plus the tile-snapped node) gets the SAME position→membership reconciliation a user drag gets (`reparentedNode` + parent-before-children reorder) — a member pushed out of its group frame detaches instead of invisibly vanishing on collapse. The plain single-pass anti-overlap nudge remains for NON-connect drops. Connect + snap + cascade + reparent ride the gesture's single `pushHistory`. Node-body hover WINS over the drop-on-edge preview AND suppresses splice-on-drop (what wasn't previewed is never committed); wire-connects and drop-connects share one `applyConnection` (single-input enforcement, hidden-socket exposure, image→normal colorSpace flip). The decision logic is pure and tested (`dragConnect.test.ts`); NodeEditor only adapts React Flow internals (measured boxes, MOUNTED handle bounds — hidden `exposedPorts` params and unmounted grow-sockets, i.e. the arithmetic folds + the variadic `append`, don't participate) and paints the preview imperatively like the edge highlight. **Palette tiles drag-connect too**: HTML5 dragover previews via the payload record tileDrag keeps from dragstart (the DnD spec hides `dataTransfer` data until drop) and the touch path streams `fs-tile-drag-move`/`-end` events (which also gave touch drags the drop-on-edge highlight); the not-yet-created node plans as a PHANTOM (`TILE_PHANTOM_ID` — def-derived ports all at the cursor, so vertical tile movement picks the hover node's socket and the tile side offers its first free port; a fresh id can't cycle or occupy), the drop swaps in the real id, connects via the same `applyConnection`, and snaps beside the peer two rAFs later (post-measure) — all under `addNode`'s single history entry. Click/Enter palette adds never preview, so they never connect (`activate` flag on the drop detail) and keep their historical unconditional splice at canvas centre. Hardening: the drop commits ONLY plans referencing `TILE_PHANTOM_ID` (a live node-drag preview can't be hijacked), stale HTML5 payload records are healed on OS-file drops (`endHtml5TileDrag`), only one touch tile drag runs at a time, the edge highlight is withheld from payloads that can't splice (saved groups, textures, input-less nodes), and the canvas `onDragLeave` falls back to a coordinate check when `relatedTarget` is null (Safari) so child-boundary crossings don't flicker the preview.

- **Noise nodes**: 8 MaterialX-backed nodes (`perlin`, `perlinVec3`, `fbm`, `fbmVec3`, `cellNoise`, `voronoi`, `voronoiVec2`, `voronoiVec3`) all use the same `pos`/`scale` parameter convention. graphToCode emits them via the `def.category === 'noise'` branch; codeToGraph parses them via `processNoiseCall`; CPU thumbnails come from `noisePreview.ts`; live GPU previews run the generated TSL through the preview iframe (`graphToCode` → `tslToPreviewHTML` → `convertToShaderModule`). `tsl-textures` was removed in favour of three.js's built-in MaterialX noise; the `texture` category backs the content-browser Textures tab (`builtinTextures.ts`) and holds exactly one (hidden) node definition — the drag-dropped Image node.
- **The Perlin family is SIGNED, and the four signed types carry a per-node range flag.** `perlin`/`perlinVec3` (`mx_noise_*`) and `fbm`/`fbmVec3` (`mx_fractal_noise_*`, which sums Perlin octaves) emit MaterialX's raw ~[-1,1]; `cellNoise` and the three `voronoi` types are already [0,1] and must NEVER carry the flag — a remap there would halve a range that was already correct. That signedness surprises people in two specific ways: `round(noise)` returns −1/0/+1 rather than 0/1, and the Output node's Discard culls on ANY non-zero so BOTH tails cull. Nodes the user ADDS now therefore default to a 0–1 remap. The whole scope rule is one storage decision: **the flag lives in `values.signed` as 0/1 and an ABSENT key means SIGNED**, so every graph saved before this, every noise member of the built-in textures/presets, and every re-imported `.js` keep emitting byte-identically (pinned by `graphToCode.test.ts`'s junk-value sweep and `registry/noiseRangeCorpus.test.ts`). `utils/noiseRange.ts` is the ONE coercion point (`SIGNED_NOISE_TYPES` + `isUnsignedNoise`), and its read is an EXACT `=== 0 || === '0'` — deliberately NOT `Number(v) < 0.5`, which maps `null`/`false`/`''`/`[]`/`0.4` all to "unsigned", and `null` is what the `fs:graph` autosave turns a non-finite into, so a coercing read would change a shader's appearance across a reload. The flag is deliberately NOT in `def.defaultValues`: on a noise node that map is the SOCKET list (`PreviewNode` builds a param handle per key), so a key there becomes a wireable dead socket with an "expose as input socket" checkbox beside it, and flips `isAtDefaultValues` to false on every legacy node — which is also why the "booleans get no expose toggle" rule is structural here rather than a special case. `resetNodeValues`' `PRESERVED_KEYS` carries `signed` so a Reset restores pos/scale without silently flipping the range back. Emission wraps the FINISHED call (`mx_noise_float(pos.mul(4)).mul(0.5).add(0.5)` — method chain, no new import), never `posExpr`, and gates on the def TYPE as well as the stored value: a tampered `.fastshader` putting `signed:0` on a voronoi node would otherwise emit a remap `codeToGraph` is required to refuse, and the round trip would grow junk nodes on every Apply. `matchNoiseUnsignedRemap` collapses that exact shape back into ONE node and is MANDATORY, not tidiness — `useSyncEngine`'s `mergeMatch` carries no `data.values` across a resync, so without it every code-panel Apply would reset the node to signed AND grow a Multiply/Add pair. The matcher is narrow on purpose: bare-Identifier callee (keeps it off dataRange's symlog `.mul(0.5).add(0.5)` tail), exactly ONE noise argument (`mx_noise_float(p, 2)` would otherwise collapse with the amplitude silently dropped), and an inline call receiver never a variable (a variable can have several consumers, so one flag couldn't mean "raw here, remapped there"). Unlike the Time-speed collapse it is SEMANTICS-PRESERVING, so it can only change how many nodes a shader is drawn with, never what it renders. **fBm is only APPROXIMATELY 0–1** — three's `mx_fractal_noise_float` sums 3 octaves from amplitude 1.0, so the remap lands ≈[-0.375, 1.375]; deliberately NOT clamped, because a clamp is a third chain link that breaks round-trip stability and flat-tops the peaks (wire a real Clamp node if you want one). A signed node shows a `±1` chip on its card (`ClockNode`'s `×speed` precedent — the SURPRISING state is the one marked). `cpuEvaluator` follows the flag for both the value and the range: that block used to assert [0,1] for the whole noise category, which is exactly why the signed GPU output was a surprise — the editor's own edge cards had been reporting 0…1 for a shader emitting −1…1. `edgeValueLabel` prefers the inferred RANGE over the probe value for any noise source, because the fixed sample UV lands on an integer lattice where Perlin is exactly 0, which on a card reads as a dead wire. The CPU thumbnail deliberately still renders 0–1 for legibility (raw signed values would clamp half of every legacy card to black, which is ambiguous as a mode signal in a way the chip is not).
- **Scientific colormaps (`colormap` node + `colormaps.ts`)**: the catalogue is the perceptually uniform / colour-vision-safe families the scivis community actually uses (viridis · magma · inferno · plasma · cividis · batlow · lajolla · L*-linear grey; cool-warm · vik · roma; two CET isoluminant maps; turbo as the one rainbow option), stored as sRGB hex ANCHORS in the GENERATED `colormapData.ts` and reconstructed piecewise-linearly. Three things are load-bearing. (1) **The LUT is baked in LINEAR light.** The catalogue is sRGB-encoded — that is what matplotlib/Crameri/CET publish — but the texture carries no colour-space tag and the renderer's working space is linear, so `buildColormapLut` converts. Interpolating sRGB values as if they were linear is the exact error that destroys the uniformity these maps exist to provide, and it is invisible: the picture merely looks "a bit washed". The SAME bug was live in Stripes/Data Viz, whose ramp endpoints went out as `vec3(hex/255, …)` while a Color node's identical hex went out as `color(0x…)` (which THREE.Color decodes); both now emit `color(0x…)`, so one hex means one colour app-wide. (2) **The half-texel inset is not cosmetic**: `t → t·(N−1)/N + 0.5/N` is what puts t=0 and t=1 on the ramp's true endpoints, and the endpoints are what people recognise a map by (`#440154`…`#fde725` IS viridis). (3) **The isoluminant entries are there for the 3D case specifically.** On a lit, spinning mesh a strong lightness ramp competes with shape-from-shading and flattens the geometry; an isoluminant map leaves luminance to the lighting and carries value in hue alone (Kindlmann et al. 2002; Kovesi, arXiv:1509.03700). It buys that by giving up fidelity — vision resolves luminance far better than hue — so both families ship and the picker labels the trade-off rather than choosing for the user. `colormaps.test.ts` pins the published endpoints AND the properties (sequential = monotone lightness, diverging = lightest centre with equally dark arms, isoluminant = flat lightness), so a regenerated table that quietly stops being perceptual fails.
- **The dataviz family is emitted by hand and is ONE-WAY through codeToGraph** (`stripes`, `dataviz`, `colormap`, `dataRange`, `isolines` — same standing as `imageNode`). Each has an empty `tslFunction` and a `CUSTOM_EMISSION_BASENAMES` entry; without that entry the var name falls through to the empty-string base and every instance collides. Two rules they all follow. **Inputs are scalars, so a non-scalar source is coerced with `.x`** (`scalarRefOf` → `shapeOfEdgeSource`): nothing in the editor validates connection types, and `vec2(<vec3>, 0.5)` is a compile error rather than a wrong picture. **Stored numbers are re-emitted through `num(Number(…))`, never `String()`** — `resolveExposedParam` interpolates the stored value verbatim, and these modules are executed by the XR popup at the app's REAL origin, so a value out of a `.fastshader` file must be a number or nothing (`numericParam` is the safe local equivalent).
- **`dataRange` decides its DOMAIN on the CPU, not per fragment** (`planNormalize` in `dataViz.ts`): min/max, robust 2–98%, zero-centred, ±3σ, log, symlog, manual. Choosing a domain is a judgement about the data and needs the whole column, which only code-gen can see — the shader then evaluates a plain affine/log/symlog chain with baked constants. The tracing is deliberately ONE HOP from a Data node's `colN` handle (`columnForHandle`, shared with the settings menus so the numbers on screen are the numbers baked in); anything else means "no statistics" and falls back to the manual domain rather than guessing. Every degenerate case resolves to something that still renders: a flat column widens to a unit domain instead of dividing by zero, and `log` over data touching zero floors the low end instead of taking log of a non-positive. The menu prints both the column's statistics and the RESOLVED domain, because an automatic mode is otherwise invisible — the Data node's own menu lists per-column ranges for the same reason (every tone control downstream is in normalized units, so without them the user tunes against numbers they cannot see).
- **`isolines` reuses the Stripes AA construction, and the ordering is the whole trick**: the derivative is taken of the CONTINUOUS phase, never of `fract(phase)` — `fract` is discontinuous once per level, so `dFdx(fract(p))` spikes exactly at each contour and draws a spurious line through the one it is meant to smooth. The derivative is floored (`.max(0.00001)`) so a flat region cannot collapse the smoothstep's two edges onto each other, and contours packed tighter than a pixel fade to their average coverage instead of aliasing into moiré. `dataVizTslContract.test.ts` builds these chains against the REAL `three/tsl` — every other test compares generated source to expected source, which cannot catch a method that does not exist (`.sign()`, `.oneMinus()`): that produces perfect-looking source and a blank preview pane.
- **Live microphone (`micNode`)**: the Mic node emits four ORDINARY NUMERIC UNIFORMS — `const mic1_bass = uniform(0);`, one per CONSUMED channel (`level`/`bass`/`mid`/`treble`, the Data node's `usedCols` rule). That shape is the entire design: the value rides the `fs:uniform` postMessage channel that already exists, so **nothing new crosses the preview sandbox boundary except numbers**, and `buildShaderModule`'s `uniformLineRe` pass turns the same line into `params.mic1_bass` plus a `{type:'number'}` schema entry with NO change to `PropertyInfo`/`collectShaderProperties` — so a downloaded `.js` has four real properties an embedding page can drive (the module header prints the six-line driver snippet and the secure-context caveat, because an undriven download is permanent silence with no error). Emitted BY HAND with an empty `tslFunction`. It claims its variable base through a dedicated ALIAS branch in graphToCode (like `dataNode`, NOT via `CUSTOM_EMISSION_BASENAMES`) — it emits `<var>_<channel>` identifiers, so each emitted channel is reserved as a `claimName` alias; without that a user property NAMED `mic1_bass` takes the name first and the emitted `const mic1_bass` becomes a duplicate declaration, a SyntaxError that fails the whole module. One-way through codeToGraph (an Apply demotes it to plain `property_float` nodes — pinned as a known shape in `engine/micNode.test.ts`), and its branch must stay BEFORE the generic `inputs.length === 0 && defaultValues` branch, which would emit `(0.8)` from the analyser settings — the same trap the Time node avoids. `micChannelForHandle` is shared by the emitter and `resolveEdgeRef` so a hand-edited handle in a `.fastshader` can never reference an undeclared variable. **The Mic node is its own React Flow component** (`MicNode.tsx`, flow type `mic`), NOT a ShaderNode. That is the whole layout story: ShaderNode derives socket positions from in-flow ROWS, so this node fought it endlessly (settings paired with outputs by index; filtering inputs to the exposed set re-flowed the card). Every node that looks deliberate — Time, the noise family — is a component that places each handle ABSOLUTELY at a chosen offset, and micNode now does the same. **Its geometry lives in `nodes/micGeometry.ts`** — a pure, import-free module read by MicNode.tsx, `MicCardContent` (the tile) AND `layoutEngine`'s footprint, so no surface can hold a stale hand-copied twin of the numbers (the tile used to, and drifted). Layout matches the design sketch: the two parameter chips stacked FULL-WIDTH at the top of the body (param sockets on the left edge aligned with them, `title` on each row naming the param), then the arm light centred below with the four outputs spread down the right edge beside it. Every placement rule in MicNode.css is scoped to `.mic-node__body`, NOT `.mic-node` — the tile renders the same body inside CardShell's frame with no `.mic-node` ancestor, which is exactly how the arm light once fell back to in-flow margins and sat on top of the chips there; the light's PLACEMENT rides a `.mic-node__btn-wrap` div (inline `top` from `MIC_BTN_TOP`) while its size/colour/blink stay in ShaderNode.css. `CardShell` takes `hideOutput` for content that places its own per-port handles — without it the shell's generic centre dot rendered as a fifth, phantom output on the mic tile. **Sockets are pinned to `z-index: 2`, above the arm light's `1`, and that is not cosmetic tidying**: React Flow positions every handle with a `transform`, a transform CREATES a stacking context, so a socket tooltip's own `z-index: 10` (TypedHandle.css) is SEALED INSIDE its handle and can only compete with siblings at the handle's own level — `auto`. The arm light's wrapper is likewise a transform-made stacking context at `z-index: 1`, so it out-painted every tooltip reaching over it and the lower outputs' labels were simply clipped away mid-word. The rule is a DESCENDANT selector (the param handles are nested one level deeper, inside MicNode's per-input wrapper, and their tooltips can be covered by the value chip above them) while the positioning pair beside it stays a CHILD selector, governing outputs only — the params keep React Flow's own centring. Consequences of living off ShaderNode: it is OUT of the Node Designer's designable set (`ndData.designerNodes()` derives exactly the ShaderNode-rendered registry), it has no `customGlyphs` entry, `layoutEngine` needs its fixed footprint, `loadGraph` re-derives `type` for graphs saved while it was still a ShaderNode, and **every extra React Flow surface must REGISTER `mic` in its `nodeTypes`** — `GraphModal` (node-editor.html) didn't, so the mic rendered there as React Flow's DEFAULT node, a bare white box with top/bottom handles; it registers the real MicNode now, safe because the arm light gates on the node being wired and no modal graph wires one. The card is deliberately NARROW (`MIC_W`) — the 64px arm light nearly fills it, because the light IS the node's face and a wide frame around it read as a box with a dot in it rather than a control. **A param carrying an edge shows the VALUE ARRIVING, not the word "wired"**: it reuses ShaderNode's exported `edgeValueLabel` (live value, inferred `min…max` range, or `…` when underivable) through the same two-step selector — subscribe to a cheap string key so a position-only graph notify bails on `Object.is`, then rebuild the map from `getState()`. It renders as PLAIN TEXT with no plate, blue when live, because on a node a fill means "you can edit this" and plain text means "this is derived"; the stored number is dead once an edge overrides it, so offering an editable box would be a lie. `NodePreviewCard` replicates the arm light as an inert `<div>`, never a `<button>` — a palette tile must not become another way to switch the microphone on — and that `<div>` needs the explicit `--inert` class, since a `<div>` can never match `:disabled` and the tile would otherwise show enabled-green beside a grey unwired canvas node. **Capture is parent-side only and gated on a click**: `getUserMedia` is denied to the preview iframe's sandbox-issued opaque origin *below* the Permissions-Policy layer, so `allow="camera *"` would not help and `allow-same-origin` would hand adversarial shader code `fs:graph`/`fs:savedGroups`/the IndexedDB caches. Since a node's presence in a graph IS its execution here (`fs:graph` restores with no gesture), `micCapture.ts` is the ONE `getUserMedia` call site and `micSession.armMic` is the ONE path to it, reachable from exactly TWO real clicks (the node's light and the preview's MicControl) — never from an effect, a message handler, a store subscription, or anything a loaded `.fastshader` can reach. **There is deliberately no persisted grant and no "remember this"**: `projectImport`'s `writeLs` block copies preview prefs straight out of an imported file, so a consent key would be one line of attacker-supplied JSON from being pre-granted; not having the key makes that unreachable. `gain` is an exposed input socket applied SHADER-side as a SEPARATE statement (`const _mic1_bass = mic1_bass.mul(g);`) — never folded into `uniform(0).mul(g)`, which would stop `uniformLineRe` matching and silently drop both the export schema property and the live uniform binding; gain 1 + unwired emits byte-identically to the ungained form. The analyser therefore does NOT apply gain (it would scale twice). `smoothing` is ALSO an exposed socket, but it resolves differently: it sets the AnalyserNode's `smoothingTimeConstant` on the CPU, so ShaderPreview's `micSettingsKey` selector resolves a wired edge with **`evaluateNodeOutput`** (the node-card evaluator) instead of emitting anything — it follows constants/sliders/arithmetic and reads 0 for GPU-only sources, and codegen must stay out of it entirely. **micNode and imageNode are the two nodes that DRAG-REVEAL their hidden param sockets (`revealHidden`) — not keyed off `usesExposedPorts`, since the Output node is in that set and deliberately does not. Without micNode there, its smoothing/gain were unreachable by wire: you had to know to tick them in the settings menu first. Both params are declared as real `def.inputs`, not just `defaultValues` keys** — ShaderNode builds sockets from `def.inputs`, so a param that lives only in `defaultValues` can be ticked "expose as input socket" and still render nothing at all (the noise nodes and Time get away with it only because they render through PreviewNode/ClockNode, which have their own socket handling). They keep their `defaultValues` entries too, so an unexposed param still shows its inline number widget, and ShaderNode filters `def.inputs` down to the exposed set exactly like `imageNode`. Mic uniforms are split out of `uniforms` in ShaderPreview BEFORE anything reads it, which in one move keeps them out of the overlay, out of `handleReset` (which would otherwise write mic-derived values to disk via `usePersistedState`, contradicting "nothing is recorded"), out of the `fs:preview-ready` re-push, and out of "Set as default". The rAF pump posts `fs:uniform` DIRECTLY and must never call `handleUniformChange`/`handleReset`; the meter is written imperatively; and disarming POSTS ZEROS, or the shader freezes on whatever the last captured frame happened to be. Arm/disarm carry a monotonic generation token written synchronously: the permission prompt is non-modal and can sit open for 30s, so mic→cancel→mic leaves two `getUserMedia` calls in flight, and without the token the loser's MediaStream is never stopped (OS indicator lit for the life of the tab). The auto-disarm on "no mic uniforms left" gates on INTENT, not on `captureRef.current` — during the prompt no capture exists yet AND `MicControl` unmounts, so a capture-gated check would let the answer install a live mic with no button anywhere to stop it. Targets come from the GENERATED CODE (avoiding an `s.nodes` subscription) but are GATED on the graph really containing a Mic node: an emitted `const mic1_bass = uniform(0);` is textually identical to a user property that happens to be named `mic1_bass`, so without the gate such a property would vanish from the Uniforms overlay in a graph with no microphone in it. ONE analyser serves the whole graph, so a second Mic node's settings are ignored (deterministically the first in node order). **podest CAN hear** (`public/podest.html`): capture lives in the TOP document — the stage iframe is the same opaque-origin sandbox and could never call `getUserMedia` — and values cross as ordinary `fs:uniform` messages, the same in-place `_propertyUniforms` write the sliders use, so a parent-held capture survives every stage restart (device loss, stall watchdog, time fold). Mic names are split OUT of the reported uniform map **before `onUniforms`**, which in one move keeps them out of the slider list, out of `state.values` and therefore out of the IndexedDB tuning record — reaching `onUniforms` would replay a frozen room-noise level at every boot (value/bounds seeding happens before the row is appended, so filtering later is too late). The arm light is bottom-left, deliberately **NOT** in the `:root.is-present` hide rule: everything else is hidden in presentation mode, but the blinking red light IS the privacy indicator and a pedestal has no visible tab strip. **A drop never arms; a drop always disarms** (both `loadShaderText` and the `fs:uniforms` branch, so a shader that fails to apply cannot leave a live mic driving names from the previous one). **Auto-arm is deliberately NOT implemented**: permission is keyed to ORIGIN, podest shares the editor's, `getUserMedia` needs no transient activation, and podest auto-replays its last drop at boot — so an auto-arm would let a shared `.js` open the microphone silently at every boot for weeks on an unattended machine. An unattended sound-reactive exhibit therefore needs a REMEMBERED-DECISION gate (a flag plus a digest of the exact shader it was granted for), which is a separate design decision, not a gap to quietly fill. The band maths is a hand-written twin of `micAnalysis.ts` (podest is a standalone vanilla page and cannot import the app's modules) — keep the floor/floor band partition in sync. **The XR popup and the LAN bench server are still deaf** (backgrounded rAF throttling; same sandbox with no parent; plain HTTP is not a secure context) — and fixing XR by capturing at the real origin would let an imported `.fastshader` open the mic using a grant given for the user's own shader, which is the one line this must not cross. **The DESKTOP build needs `src-tauri/Info.plist`, which is not optional garnish**: macOS TCC refuses a microphone request outright — no prompt, no grant, just a `NotAllowedError` — when the requesting process's `Info.plist` carries no `NSMicrophoneUsageDescription`, so without that file the Mic node works in every browser and is permanently dead in the `.dmg`. tauri-bundler picks the file up automatically because it sits beside `tauri.conf.json`. Nothing else was blocking it: wry 0.55.1's `webView:requestMediaCapturePermissionForOrigin:` handler grants unconditionally, `tauri://localhost` and `http://tauri.localhost` are both secure contexts, `csp: null` injects no policy, and the capabilities ACL governs IPC commands, not web APIs. Two consequences worth remembering — `tauri dev` runs the bare binary with NO `.app` bundle and therefore no `Info.plist` at all, so the microphone can only ever be tested from a real `tauri build`; and under today's ad-hoc signing TCC identifies the app by cdhash, so a grant will not survive an update until the build is properly signed (and if hardened runtime is ever enabled, `bundle.macOS.entitlements` must additionally grant `com.apple.security.device.audio-input`). Failure wording is shared by the two arm surfaces through `utils/micStatusMessage.ts` for one specific reason: they used to hold byte-identical copies of the switch, which is how the desktop build ended up telling users to fix a permission in an address bar it does not have — `denied` is the one status that branches on `__FS_DESKTOP__`.
- **Time node's `speed`**: the Time node's multiplier follows the SAME opt-in `exposedPorts` rules as the noise params — hidden until ticked in Node Settings, drag-revealed dimmed, auto-exposed when an edge lands, and a wired edge overrides the stored number. It lives in `defaultValues`, NOT `def.inputs`, and must stay there: `ensureBareInputNode` refuses to auto-create a node whose def declares registry inputs, so adding one would silently drop the Time node (and its edge) from `sin(time)`. graphToCode emits `time.mul(<literal|var>)` (method chain — no `mul` import, same convention as the noise `scale`); `tryParseTimeSpeed` collapses BOTH forms back into one Time node, wiring the variable form to the `speed` port. The collapse is deliberately narrow — bare `time` receiver, unshadowed, exactly one argument, and a variable that resolves to a real node — so the fixtures' `const t = time; mul(t, x)` idiom stays a genuine Multiply.
- **Asset-browser ordering**: node tiles sort by GPU points (cheapest first, every tab — not just Noise); Presets and Textures sort by member count, since a ready-made asset is a graph you open and read, and points can rank a 3-node voronoi above a 20-node arithmetic chain. Both are display-layer sorts in `ContentBrowser` — `builtinPresets.ts` keeps its tier order (and the test that pins it).
- **Time node speed**: the Time node carries a `speed` multiplier in `defaultValues`, shown ON the node as an always-visible editable `× <n>` row (`.clock-node__speed-row`) and, when the `speed` socket is wired, as the value ARRIVING through the shared `edgeValueLabel` — plain text, no plate, exactly like the Mic node's wired params. It was previously a read-only red chip in the bottom-right corner that rendered ONLY when `speed !== 1`, so at the default the node carried no sign it had a multiplier at all, which reads as the control having gone missing rather than as "it is at 1". Also settings-editable through the generic `NodeSettingsMenu` defaultValues loop. **Its sockets live INSIDE `.clock-node__canvas-wrap`** so they centre on the clock FACE: positioned against the whole node they sat exactly half a header-height too high, and moved again whenever a long varName wrapped the title to a second line. The left/right insets must always be overridden as a PAIR — only `-right` was, so the shared `transform: translateY(-50%)` override (which also strips React Flow's own `translateX(-50%)`) left the speed socket floating ~6px INSIDE the card while the output sat on the edge. `graphToCode` has a dedicated `def.type === 'time'` branch placed BEFORE the generic `inputs.length === 0 && defaultValues` branch (which would emit the invalid `time(1)` — `time` is a uniform node OBJECT, not a callable): `speed === 1`, a missing key, or any non-finite value emits the historical bare `const time1 = time;` BYTE-FOR-BYTE, so no already-exported shader changes; otherwise it emits the method chain `const time1 = time.mul(k);` (no extra import, same convention as the noise `scale` param). `codeToGraph`'s `tryParseTimeSpeed` collapses that shape back — but ONLY when the receiver is the bare `time` identifier, `time` is unshadowed, there is exactly one argument, and it folds to a numeric constant. It deliberately does NOT collapse `mul(time, k)`, `mul(time1, k)` (the human idiom — ~51 occurrences across the `Tests/` corpus, usually two muls sharing one Time node) or a non-literal multiplier (`mul(t, speed)` in builtinTextures/builtinPresets). **`ensureBareInputNode` needs its `def.defaultValues` bail-out to except `time`** — without it, adding defaultValues silently drops the Time node AND its edge from `sin(time)`/`add(pos, time, normal)` with no error. `values.speed` is adversarial at all three read sites (graphToCode, cpuEvaluator, ClockNode): `Number()` then `Number.isFinite() ? … : 1`, never `String()` and never `resolveExposedParam`. ClockNode integrates `dt * speed` into a phase accumulator (never `Date.now() * speed`, which teleports the hand on every scrub frame) with the rAF deps kept `[]`. `complexity.json` keeps `"time": 0` — `nodeCostPoints` can only express value-dependent cost for `chainable` defs, and `node.data.cost` is a creation-time snapshot frozen into saved graphs.
- **Drop-time image conversion is ASKED, not assumed** (`Modals/ImageImportModal`): dropping image(s) opens one dialog per drop — a single line, "Convert image to optimized format?", **Yes** (green) / **No**, plus "Don't ask again" persisting to `fs:imageConvert` (`imageConvertMode: 'ask'|'always'|'never'`). **That preference MUST stay reversible from the UI** — it is offered in the Image node's settings menu ("Optimize on import": Ask each time / Always / Never) and in the "?" panel, and a remembered `never` announces itself on every drop via the one-liner. Without those, ticking the box next to "No" silently pins every future drop with no way back and no signal, which reads exactly like the feature being broken. **No is not Cancel** — the image imports either way, so Escape and the backdrop mean No; the explanation lives in the node's settings menu (Format / Resolution / Size / Original) rather than in a dialog standing between a drag and the canvas. It is a question because the conversion is lossy in a way the app cannot judge: a normal map wants "keep", a photo wants "convert", and at drop time the app does not know which it has (the Data-map flag is only set afterwards). "Keep as-is" still runs the canvas round-trip — EXIF/GPS strip, device texture cap, payload budget are not preferences — it only turns off the FORMAT change (`chooseFormat`'s `allowWebp: false` keeps the image in its own family) and the power-of-two snap. When the user asked to convert and **this browser cannot encode WebP** — MEASURED on this machine 2026-08-02: Safari 26.5.2 *decodes* WebP fine (`<img>` and `createImageBitmap`) but `toBlob`/`toDataURL('image/webp')` still return `image/png`, while Chrome 150 encodes it and q=1 really is lossless — the canvas shows a top-centre ONE-LINER ("Not optimized — stored as JPEG") with a **?** opening `Modals/ImageConvertInfoModal` and a dismiss; it self-clears after 12s and can be turned off for good from that panel (`hideImageConvertNotice`, `fs:hideImageConvertNotice`). Not a modal, deliberately: it reports a browser capability, not a decision, so it must not stand between a drag and the canvas — but a capability limit the user can't see at all is worse than the fallback itself, which is how a dropped `.png` silently became a JPEG (PNG blew the 600 K budget at 1024×2048, leaving JPEG as the only candidate). The Image node's card label also shows the **stored** extension, not the dropped file's (`displayImageFileName`, pure + tested) — a re-encode routinely leaves `.png` on WebP bytes, and the card must not assert a format the node doesn't hold; the `title` keeps the name as dropped.
- **What the conversion does (WebP + power of two)**: a dropped image is re-encoded to **WebP as far as the running browser will go** — lossless WebP for sources that must stay exact (PNG, and `.webp` re-drops whose container says VP8L), lossy WebP q0.85 for photographic sources, with a quality ladder (0.85→0.75→0.65) tried before any dimension is thrown away. Support AND losslessness are **probed at runtime** on an 8×8 gradient (`probeEncodeCaps`), never inferred: WebKit silently returns PNG from a WebP request (still true in 2026, and it covers the Tauri WKWebView build, not just Safari), and the HTML spec leaves `quality` UA-defined for WebP, so Chromium's "q=1 means lossless" is an implementation detail. `chooseFormat` is a FALL-THROUGH, not a preference — making the lossless branch absolute would hand every over-budget PNG to the halving retry and land a 2048² screenshot at 256-512px. **Alpha never yields JPEG** on any capability combination (pinned by test). Dimensions are then snapped to a power of two **only where that is nearly free** (`imageCodec.ts`): nearest POT per axis, declined above `POT_MAX_UPSCALE`/`POT_MAX_DOWNSCALE`, skipped entirely for binary-alpha cutouts and low-colour sources (pixel art / UI / masks, which the resample destroys AND inflates). The snap is worth knowing about: **nothing in this stack needs POT** — three r184 has no `makePowerOfTwo`/`textureNeedsPowerOfTwo` path left (that was WebGL1/ES2) and both WebGL2 and WebGPU sample NPOT with RepeatWrapping and full mipmaps — so it is hygiene, which is why it must cost near-nothing and why the resample goes through a **wrapped border** (`POT_WRAP_MARGIN`): plain `drawImage` clamps at the edges, so a seamless tile would come back with a seam on every boundary, in a node whose Repeat setting defaults ON. The pre-snap encode is ALWAYS produced first and kept as the node's "original", and the snap is declined outright when that stash can't be made — a destructive step never ships without its escape hatch. Conversion is automatic at drop with an in-flight ghost at the drop point (transform/opacity only, so the compositor keeps it animating while the encoder blocks) and multi-file drops are **serialized** (N concurrent encoders compounded into one freeze). Honest progress is impossible — `toBlob`/`toDataURL` are single opaque calls with no callback and no cancel.
- **"Revert to original" (Image node settings)**: restores the payload the import WOULD have produced without the POT snap — same EXIF strip, same device texture cap, same 600 K budget; NEVER the raw source file (that would re-embed the GPS the canvas round-trip exists to strip, and blow every cap). Bytes live in `utils/imageOriginCache.ts` (IndexedDB, `previewMeshCache`'s throw-safe shape), **not** on `values`: `totalImageChars`/`sanitizeImageNodes` inspect only `imageB64`, so a second payload key would be invisible to the 600 K per-image cap, the 3 M project cap, the 8 M hard ceiling and the whitelist — a tampered `.fastshader` could smuggle an unbounded blob past the trust boundary — and it would ride ~101 history clones, the autosave, the clipboard and the project embed. Only `originId` (+ `srcWidth`/`srcHeight`) ride the node, all three whitelisted in `sanitizeImageNodes`. The record is **content-keyed** (a digest of the stashed payload): it survives Ctrl+D/paste, which mint fresh node ids while cloning `data`, and a re-drop under a different headset texture cap becomes a DIFFERENT record instead of silently rewriting what an existing node reverts to. Reads are re-validated as adversarial (`recordToPayload`: version, key-matches-digest, whitelist, dimensions). Device-local by design, so the row disables with an explanatory tooltip after sharing a project, in another browser, or once it ages out (32 records / 24 MB LRU). Ticking **"Data map (linear, no mipmaps)" also restores the original** — that checkbox is the only moment the app learns an image is a normal/height map (the drop cannot know), and a resampled normal map has wrong normals; both changes ride ONE `updateNodeData` so it stays a single undo entry, which is why the record is prefetched when the menu opens (`ImageNodeSettings` is its own component precisely because it needs that hook — an awaited read inside the handler would split one click into two undo steps).
- **Image node**: drag-dropped images become a hidden `imageNode` (mirrors the Data node pipeline). Payload = whitelisted `data:` URL on `values.imageB64` — **adversarial**: codegen re-encodes the decoded bytes (`decodeImageNode` → `bytesToBase64`, never the stored string), the ShaderNode thumbnail renders only `validImageDataUrl()`, malformed payloads degrade to an inert `vec3(0,0,0)`. **The payload does NOT sit in the editor's code**: graphToCode emits `img.src = "fs-asset:<node>-<hash>"; // name, WxH, size` and `utils`-style pure helpers in `engine/imageAssets.ts` splice the real `data:` URL back in at the four surfaces that RUN or EXPORT the module (preview iframe, XR popup, Output tab, Download Shader) — a word-wrapped 600K-char literal otherwise buried the shader under ~8,500 rows in Monaco and re-tokenized megabytes per graph edit. Safe because image nodes are already one-way through codeToGraph, so nothing ever read that payload back; the placeholder carries a payload hash so changing an image's BYTES still changes `code` and invalidates the code-keyed preview memos. An unknown placeholder key is left verbatim and degrades via the existing decode() fallback. Emission = FLAT module-scope statements with top-level await (never an async IIFE — codeToGraph's ReturnStatement visitor would hijack the output): `new Image()` → `try { await decode() } catch` → 1×1 fallback → `THREE.Texture` with RepeatWrapping, pinned `flipY`, sRGB or linear data-map per `values.colorSpace` ('color' | 'data'); the Fn body samples `texture(tex, uvExpr).rgb` (vec3 out; `uv` input falls back to `uv()`). **Normal-map decode**: an image wired into the Output node's `normal` socket is a tangent-space normal MAP, not a raw normal — graphToCode wraps that channel in TSL's `normalMap(...)` (which does the `*2-1` remap + TBN tangent→view transform + normalize) rather than feeding the raw [0,1] sample into `normalNode`. `normalMap()` needs LINEAR input, so `NodeEditor.onConnect` auto-switches the image to the `data` colorSpace on connect (skipped if the same image also drives an sRGB channel — one texture, one colorSpace; mutated via `setNodes` so connect+flip is a single undo step). Non-image sources feeding `normal` stay a raw normal override (unwrapped). NodeSettingsMenu has a "UV / Texture" section (values read Number-coerced by codegen): `tileX/tileY`, `offsetX/offsetY`, `repeat` (off → ClampToEdge), `flipX`/`flipY`, and the data-map toggle. All five inputs (`uv`, `tileX/tileY`, `offsetX/offsetY`) follow the SAME opt-in `exposedPorts` rules as the noise nodes (see NODE_DESIGN_REQUIREMENTS.md → "Exposed parameter sockets"): hidden until checked in the generic NodeSettingsMenu sections, auto-exposed when an edge arrives (useSyncEngine + loadGraph migration), wired edge overrides the stored value, hiding drops the port's edges. Dragging a wire within snapping distance of a node with named input sockets forces its input name-tooltips visible (floated left of each socket — TypedHandle `reveal` prop; operator cards, the Output node, and collapsed groups opt out — generic/permanent labels); noise + Image nodes additionally reveal their hidden sockets as floating dots on the card's left edge — dimmed, layout untouched — and landing the connection exposes that port permanently (`connectionReveal.ts` + `RevealSockets.tsx` + onConnect/onReconnect auto-expose; the reveal radius IS the editor's snap radius, one shared `CONNECTION_RADIUS`). - **Selection**: **Shift+click adds to the selection** (`multiSelectionKeyCode={['Shift','Meta','Control']}` — an array is "any of these", and it's module-scope because `useKeyPress` memoizes on its identity). This REQUIRES `selectionKeyCode={null}`: Shift's React Flow default is hold-to-marquee, and while it's held the Pane's `onPointerDownCapture` stopPropagation()s a pointerdown that landed on a node and opens a rubber band instead — so Shift+click would marquee rather than extend. Marquee stays mouse-only — `selectionOnDrag` is off on coarse pointers so the first finger of a two-finger pan can't start a selection box.
- **Groups**: selection groups are first-class React Flow nodes (`type: 'group'`) created via Ctrl+G or right-click → Group Selection. They have no registry entry and no shader semantics — `graphToCode`/`cpuEvaluator` ignore the *node*, but call `unwrapCollapsedGroupEdges()` from `edgeUtils.ts` at their entry to translate visually-rewritten boundary edges back to their real child endpoints, so collapse state never affects compiled output. Groups can be recolored, renamed, collapsed (members hidden via `display: none` className — *not* React Flow's `hidden: true`, which would unmount rAF loops; the toggle anchors at the frame's TOP-RIGHT corner — the pill appears at the old top-right and expanding grows leftward from the pill's top-right, `groupCollapse.test.ts` pins the round-trip), saved to a per-browser library (`fs:savedGroups`), and dragged out of containers. Members never get `extent: 'parent'` — `onNodeDragStop` reconciles `parentId` after every drag instead. **Notes are ordinary members**: Ctrl+G sweeps a selected note in, dragging one into a frame adopts it, and it then rides the group's drags/collapse/ungroup/save-to-library like any node (a note is usually the LABEL for the cluster being grouped, so leaving it outside stranded the annotation). Notes stay exempt only from the placement rules that would fight their purpose — anti-overlap nudging (it would fling a note off the nodes it was deliberately dropped over) and drop-on-edge splicing — both guarded by `isNote` in NodeEditor's drag handlers, not by bailing out of membership. `addNote` PREPENDS, so ordering matters: a note is born parentless and both adoption paths re-sort it after its parent (`groupSelection` front-inserts the container; the drag handlers run the parent-before-children lift). `groupNotes.test.ts` pins all of it. `organizeSelection` still skips notes — auto-layout has no meaningful slot for a free-floating annotation. **An expanded frame's only interactive surface is its HEADER** (drag, select, and the right-click GroupSettingsMenu): the body is `pointer-events: none` so the area inside a frame behaves like bare canvas — right-click opens the Add-node menu, drags rubber-band/pan, clicks don't select the group. This relies on React Flow already marking `.react-flow__viewport`/`.react-flow__nodes` pointer-events-none, so a pass-through frame leaves `.react-flow__pane` as the event target — which is what the Pane's `wrapHandler` guard requires before firing `onPaneContextMenu` (and it's why the touch long-press path, which dispatches a synthetic `contextmenu` on the pointerdown target, routes identically). Collapsed pills opt back in and stay fully interactive — a pill stands in for a node. The resize control opts back in too; see the pass-through block in `GroupNode.css`. **Groups resize exactly like notes**: a single `NodeResizeControl` at the BOTTOM-RIGHT with the notes' enlarged 15×15 grab box, rendered only while expanded AND selected — not React Flow's full `NodeResizer`, whose eight edge/corner handles ringed the frame and turned every near-miss along an edge into an accidental resize. So both surfaces now follow one rule: drag by the header, scale by the one corner. (Notes get that drag rule from `dragHandle: '.note-node__header'`; groups get it from the pointer-events pass-through above — different mechanism, same behaviour.)
- **Board drawings**: freehand ink annotations (DrawingLayer + DrawToolbar) are VISUAL-ONLY like notes/waypoints — invisible to graphToCode/cpuEvaluator/the sync engine. Strokes live in their own store slice, ride undo history BY REFERENCE (committed strokes are immutable; never structuredClone them), share the fs:graph autosave payload and the FASTSHADERS_PROJECT_V1 embed, and are sanitized as adversarial input on load/import (sanitizeDrawings caps). Same-opacity strokes must not compound where they cross: opacity is quantized and rendered via one SVG group-opacity isolation buffer per opacity level, and stroke colors are 6-digit hex ONLY (8-digit alpha would smuggle past the isolation).
- **An import auto-frames the canvas**: importing a shader replaces the nodes but NOT the viewport, so a project whose nodes sit anywhere but where the user is looking lands off-screen and reads as a failed import (an empty canvas). Every import surface funnels through `projectImport.ts`, which dispatches **`fs:graph-imported`** whenever the graph is actually replaced — deliberately NOT `fs:project-imported`, which also fires for a model-only zip where the graph never changed and re-framing would throw away the user's viewport. NodeEditor **ARMS** a fit on that event rather than fitting on it: a project block writes its nodes in the same tick the event fires (React hasn't rendered them), and a bare script has NO graph at all until `useSyncEngine`'s code→graph pass finishes a commit or two later — so the fit runs from the `[nodes]` effect, on the next graph the editor actually renders, behind the same double-rAF measurement guard `startNewShader` uses (`fitView` frames the MEASURED box; unmeasured nodes fit as zero-size points at maxZoom). Two details are load-bearing: the pending rAF is held in a REF torn down only on unmount, never by the effect's own cleanup — the cost pass writes the Output node's new total straight back into `nodes`, so an imported graph re-renders inside the two-frame window and a cleanup-owned rAF would be cancelled by exactly the change proving the import landed — and the arm carries a `IMPORT_FIT_TIMEOUT_MS` disarm, so an import that never yields a graph (parse errors, a byte-identical re-import that the sync engine skips) can't leave a fit primed to hijack a later unrelated edit. Desktop Work-folder loads get this for free; they go through the same `importShaderText`/`importShaderZip`.
- **History**: circular buffer (50 entries) with undo/redo via `structuredClone`, Cmd+Z/Cmd+Shift+Z shortcuts, plus visible Undo/Redo buttons in the canvas's bottom-LEFT bar (`.fs-canvas-bar` — one pill also holding the Draw tools and the zoom −/+ / fit / canvas-bg controls that replaced the React Flow Controls stack; the buttons call `undo()`/`redo()` directly — equivalent to the keyboard path, since the graph→code effect re-runs on any nodes/edges identity change regardless). **Continuous gestures must be bracketed**: `beginInteraction()`/`endInteraction()` snapshot ONCE up front and suppress `pushHistory` until the gesture ends, so a DragNumberInput scrub is one undo entry instead of one per pointermove frame — and, just as importantly, the whole graph isn't `structuredClone`d 60×/s (megabytes once images are embedded). `beginInteraction` deliberately ignores `isUndoRedo` (that flag guards the sync engine's post-undo reconciliation; a pointer gesture is always a real mutation, and honouring a stale flag would silently swallow the gesture's history). DragNumberInput brackets on first move — not pointerdown, since a press that becomes a click-to-edit would push a no-op entry — and closes the bracket on pointerup, pointercancel, and unmount.
- **Preview rebuild is debounced**: only property uniforms have a postMessage hot-update path; every other value is baked into the generated TSL, so editing one swaps `srcDoc` and re-fetches/re-parses the ~1MB A-Frame bundle under a fresh opaque origin. `useDebounced(previewCode, 200)` (trailing, so first paint isn't delayed) collapses a scrub's pointermove stream into a single rebuild on release. A "Compiling shader…" overlay covers the gap, cleared by `fs:preview-ready` (success) **or** `fs:preview-error` (failure — a broken shader never reaches the ready handshake, since `checkShaderReady` polls for bound uniforms and just gives up), with a 12s failsafe so it can never stick over the error text.
- **Custom preview mesh**: dropping a `.obj`/`.glb`/`.gltf` on the 3D preview (or importing a zip carrying one) loads it as the `custom` preview geometry. The mesh lives in the store's `previewMesh` slice — never history, the localStorage autosave, or the project embed (bytes can be tens of MB) — but IS mirrored to an **IndexedDB cache** (`utils/previewMeshCache.ts`) so it survives a reload; localStorage is the wrong store here (strings only, ~5-10 MB origin budget the graph autosave already fills). `setPreviewMesh` is the single persist chokepoint (fire-and-forget, resolves on every failure path so a quota error can't break a drop); the boot restore passes `{ persist: false }` since those bytes came out of the cache. Restore ordering is the subtle part: the read is async, so `validateGeometry` has ALREADY downgraded a stored `'custom'` to `'sphere'` and `usePersistedState`'s persist effect has written that downgrade back — which is why `bootGeometryWasCustom()` samples the key at MODULE INIT, before React mounts, and the restore re-selects `'custom'` from that snapshot. A synchronous drop or zip import always wins over the cache read. Cached bytes are re-validated as adversarial input (`recordToMesh` → the same `createPreviewMesh` constructor: extension whitelist, 64 MB cap, GLB magic, name sanitize) and get a FRESH session id so the iframe rebuilds. `validateGeometry` accepts `'custom'` only while a mesh is loaded (IMPERATIVE `useAppStore.getState()` read: the validator's identity must stay module-scope stable for `usePersistedState`, yet see a mesh a zip import committed synchronously before the `fs:project-imported` re-read). The sandboxed iframe receives models via the generalized `fs:obj-model` feed (glb rides as bytes, obj/gltf as text pre-decoded ONCE at load; keyed `custom:<id>` so a stale feed can't cross documents — every mesh change forces an iframe rebuild, and the per-rebuild structured-clone copy is the accepted price of a fresh document). Drops over the iframe are forwarded to ShaderPreview via `fs:preview-drag`/`fs:preview-drop` (podest's forwarder pattern — the iframe swallows drag events over the whole 3D view; the parent root handles chrome-area drops, and `.js`/`.zip` drops route through the shared `projectImport` path). `fit-bounds` takes an EXPLICIT `regen` flag at every attach: true rebuilds normals/UVs (OBJ — non-indexed loader output), false preserves authored GLB data (spherical UVs only when missing); podest's twin component defaults the OPPOSITE way, so never rely on either default. SECURITY: model files are adversarial — bytes cross only via postMessage + iframe-minted blob URLs, and BOTH sandboxed stages (editor preview + podest) install a `THREE.DefaultLoadingManager.setURLModifier` allowlisting `blob:`/`data:` so a hostile `.gltf`'s absolute-URL buffers/textures can't phone home (CSP is absent in dev, desktop, and podest — the modifier is the real control, not CSP); the XR popup runs at the app's REAL origin, so it installs an origin-widened variant (`blob:`/`data:`/same-origin — built-in models load by real URL there). Iframe-forwarded SHADER drops (`.js`/`.zip`) require a `window.confirm` — sandboxed code can forge `fs:preview-drop`, and a project import replaces the whole graph (model files only swap the session mesh, so they stay immediate); a combined shader+model drop is sequenced shader-first so the dropped model deterministically wins. Export: with a mesh loaded, "Download Shader" emits a zip with `models/<sanitized-name>` (`exportBundle.ts`, pure + tested); import: `importShaderZip` restores the first model entry and forces `custom` geometry (podest pairing semantics; a model-ONLY zip returns `'model'` and just loads the mesh), while model-LESS text imports CLEAR the stale mesh so it can't contaminate the next export. DRACO/meshopt-compressed GLBs are out of scope (no decoder bundled — the loader error surfaces in the iframe overlay).
- **localStorage**: auto-saves graph, split ratios (`fs:splitRatio` = the node-canvas column's share; `fs:previewSplitRatio` = the TOP pane of the right column, which is the 3D PREVIEW — it sits ABOVE the code editor. The legacy `fs:rightSplitRatio` held the CODE editor's share from when the order was reversed and is read ONCE, inverted, and never written again), shader name, headset selection, cost colors, canvas bg color, code editor theme, UI language (`fs:lang`), board drawings (inside the `fs:graph` payload; sanitized on load) + draw-tool prefs (`fs:drawColor`/`fs:drawWidth`/`fs:drawOpacity`), image-downscale warning opt-out (`fs:hideImageDownscaleWarning`), preview prefs (geometry, lighting, subdivision, bg, uniform bounds, uniform values, camera pos, rotation, playing state), saved groups (debounced 300ms), the last-opened asset-browser tab (`fs:assetTab` — validated against the live category list, so a renamed/removed category falls back to All instead of selecting a tab that renders empty), asset-bar height (`fs:assetBarHeight` — dragged by the bar's grip, or Ctrl/Cmd+wheel over the strip; the legacy `fs:assetBarCollapsed` + `fs:assetZoom` keys are read ONCE to migrate an old collapse/zoom into a height and are never written again). Reset clears camera/rotation/playing and restores lighting/subdivision/uniforms — bg color, uniform bounds, and geometry are treated as user preferences.
- **Uniform values persist by name, are never SEEDED, and any disagreement with the graph is announced** (`utils/uniformOverride.ts`, pure + tested — ShaderPreview itself has no coverage, the vitest env is `node`). Removing a property node keeps its stored value (the iframe ignores `fs:uniform` messages for unknown names), so delete + undo — and re-adding a property with the same name and the same number — restores the user's last tuning. What no longer happens is the trap that made this read as broken: the map used to be filled from the authored default the first time a uniform was **seen**, so an entry existed for users who had never opened the overlay, the `fs:preview-ready` re-push then decided the value, and editing the number on the property node had NO visible effect — on a binary channel like Discard that reads as the app being broken. An entry now exists only because the user tuned a slider or imported a file, so "no entry" means "the graph decides". A stored value that differs from the authored default is an **override**, computed by DERIVATION (`stored ≠ authored`, compared at the same 9 significant digits `uniformDefaults` bakes at, so a re-bake can't strand a badge beside a button `planUniformDefaults` refuses to act on) and never from a persisted baseline: a baseline would need a second key plus a migration, and it would still be wrong, because "the literal for this NAME moved" is not "the user edited this number" — which of two same-named properties owns the bare identifier follows the nodes ARRAY order, so a group drag can fake it. **Editing the number on a property node clears that uniform's entry outright**: `updateNodeData` is the authoring chokepoint (import, undo/redo, the code→graph sync and "Set as default" all go through `setNodes` and stay silent) and it dispatches `fs:uniform-authored` carrying the node id's emitted name — an event, not a store subscription, so the panel doesn't re-render per pointermove, and the hot `fs:uniform` post drives the preview at pointer rate instead of waiting out the 200 ms rebuild debounce. `handleReset` (the red ✕) now DELETES the current shader's entries rather than writing the defaults back — writing them back re-armed the trap for every uniform, and the old whole-map replace pruned every remembered name outside the current shader, contradicting the never-prune rule. `fs:previewUniformBounds` is validated per entry like its sibling (it was a bare cast, and `projectImport` writes it straight out of a project block) and both maps are count-capped. `projectImport` also CLEARS both keys when the imported file carries no tuning block — without the else-branch a shader inherited the previous one's tuning for every same-named property, and `property1`/`color1` are the auto-generated names, so a collision is the norm.
- **VR cost budgeting**: 6 VR headset presets with maxPoints, cost gradient visualization in CostBar
- **Alpha comes ONLY from the `opacity` channel.** Everything that can leak into it is normalised in graphToCode: a source whose shape is `!== 3` wired to an ALPHA-BEARING channel (`color`, `emissive` — the two that reach `diffuseColor`; `emissive` counts because shaderloader 0.5 copies emissiveNode→colorNode when no colour is wired) is emitted as `vec3(ref)`. Both ends leak: `vec4(float)` SPLATS (alpha = the scalar) and `vec4(vec4)` is an IDENTITY (alpha = the source's `w`, and a fresh Vec4 node's w is 0 → fully transparent). Shape is read from the PORT the edge leaves (`shapeOfEdgeSource`, honouring `dynamicOutputs`), not the node — Data Viz is out:vec3 + value:float, so node-level inference reported 3 for its scalar `value` socket and skipped the widen. `normal`/`position` are deliberately NOT widened: they never reach alpha, and widening `position` would break the Data Viz `value`→Displacement flow, where normal-mode displacement needs the height to stay scalar. Other alpha traps closed at the same time: `depthWrite:false` used to LATCH (its checkbox renders only while Transparent is on, so unchecking Transparent stranded it) and is now cleared on that transition AND gated on `transparent` at emission — on an opaque mesh it self-occludes into cutout-looking holes; `alphaTest` is coerced+clamped to ≤0.99 (three discards on `alpha <= alphaTest`, so 1.0 erases everything) and never interpolated raw from an untrusted project block. **Known follow-up, not yet fixed**: material settings from the previous graph leak onto an imported plain `.js` script (`useSyncEngine`'s `mergeMatch` copies them unconditionally, and `scriptToTSL` strips the incoming file's own — so the import is wrong in both directions).
- **Discard is a TRUTHINESS test, not a 0/1 switch** — `0.2` culls. It is emitted as a statement (`Discard(cond);` between the definitions and the return), lifted out by `extractDiscards` and routed through the tiny `__pixel` Fn, because `Discard()` needs an active TSL stack. Six things are load-bearing, each measured against three r184's real GLSL/WGSL builders (`bool(0.0)` is false, so a Float 0 correctly culls nothing — verified end-to-end in the app on both backends). (1) **The condition is shape-coerced to a scalar** (`scalarRefOf`) for every source EXCEPT the `logic` category: three compiles the condition as `bool(<ref>)` and widens a non-1-channel float to `all(<vecN>)`, which is declared only over bvecN/`vecN<bool>` — a real WebGL2 context answers `ERROR: 'all' : no matching overloaded function found`, so the whole fragment program fails to link and the mesh vanishes at EVERY value with nothing surfaced. Nothing validates connection types, so a Colour/Vec3/vec3-noise/Image source lands there routinely. Logic nodes are exempt because their vector output really IS a bvecN and `all(greaterThan(a, b))` correctly means "every channel passed"; narrowing it to `.x` would silently change the test. Scalars keep the plain ref, so every existing export is byte-identical. (2) **`cond.discard()` — the method-chaining spelling** (`addMethodChaining('discard', Discard)`) — is lifted too. It used to survive verbatim into the module, landing at plain-function scope where `.toStack()` has no stack and is a silent no-op: ZERO `discard` instructions in the compiled shader, in the preview AND the downloaded `.js`, with `codeToGraph` then dropping the line with no diagnostic so the next graph edit erased it. (3) **`extractDiscards` scans `maskNonCode(body)`** and slices from the original, so a discard inside a comment or a string is not code: scanning raw text ate the body of `/* Discard(a); */` while injecting a live cutout, and turned `const s = 'Discard(1)';` into `const s = '';` plus an unconditional cull — the mesh vanished because of a string literal. (4) **Only STATEMENT-level discards are lifted**; `const k = Discard(n);` is left verbatim (inert) instead of being sliced into a dangling `const k =` (a SyntaxError that took the module down). (5) **A bare `Discard()` is unconditional and carries NO Fn parameter and NO call argument** — passing the empty condition through emitted `__pixel(, …)`; `scriptToTSL`'s reverse walks the wrapper BODY rather than correlating args to params, or the unconditional form would vanish on Load Script. (6) The wrapper's fallback colour is `channels.color ?? channels.emissive ?? vec3(1,1,1)` and `Discard` is force-imported: the loader copies emissiveNode→colorNode only when colorNode is undefined and the wrapper always defines it, so white washed out an emissive-only shader the moment a discard was added. The graph has ONE discard socket, so `codeToGraph` warns (never silently drops) on a second `Discard()` or an unconditional one.
- **Scalar→vec3 widening on Output channels**: a 1-channel source wired to a vec3-typed channel (`color`, `emissive`, `normal`, `position`) is emitted as `vec3(ref)`, NOT bare. three's `NodeMaterial.setupDiffuseColor` does `vec4(this.colorNode)` and TSL splats a 1-channel node across all FOUR components, so a bare `mx_noise_float(...)` on Color silently became the ALPHA too (`diffuseColor.a = noise`) — the surface flickered/vanished as if Opacity or Discard were wired when neither was. Scalar-ness comes from `getNodeOutputShape` (cpuEvaluator), not the registry port type, so an `any`-typed arithmetic chain is caught as well. codeToGraph MUST mirror this: `unwrapScalarWiden` collapses a single-argument `vec3(<identifier|member>)` in a channel position back to a direct edge — unambiguous because a real Vec3 node always emits three arguments — or the round trip grows a Vec3 node with y/z = 0 and re-emits `vec3(x, 0, 0)`, turning a grey ramp red. Both sides are pinned (`graphToCode.test.ts` + a `roundTrip.test.ts` case). Vec3-shaped sources emit byte-identically to before.
- **Unknown nodes**: unrecognized TSL functions in code→graph parsing create `unknown` nodes that store `functionName` and `rawExpression` in values. These round-trip through graphToCode (emitted verbatim), render as magenta `vec3(1,0,1)` fallback in live preview, and show as orange warnings (not errors) in the code editor. The `unknown` definition lives in `NODE_REGISTRY` but is excluded from `allDefinitions` (hidden from content browser/search)
- **Preview geometries**: five options — `sphere`, `cube`, `plane` (primitives) and `teapot`, `bunny` (OBJ models in `public/models/`). `isObjGeometry()` in `tslToPreviewHTML.ts` is the single source of truth for primitive vs OBJ branching. The inline `fit-bounds` A-Frame component recomputes vertex normals (after merging vertex duplicates so per-vertex displacement doesn't split the surface), auto-detects inverted winding (the bunny is CW), generates spherical UVs from each vertex's direction so `uv()` reads cleanly on OBJ meshes, and rescales so the longest axis = 1.6 to match primitive framing. The source OBJs themselves are **pre-normalized** (bbox center at origin, longest axis exactly 1.6), so the runtime recenter/rescale is a no-op for them and `positionGeometry` ranges are comparable across all five geometries.
- **`fit-bounds` BAKES the normalization into the geometry attributes** (`FIT_BOUNDS_SCRIPT`, pinned by `previewFitBounds.test.ts`), and this is load-bearing rather than stylistic: `positionGeometry` is three's RAW position attribute, so scaling the Object3D — what this used to do — is completely invisible to the shader. A dropped model therefore fed its AUTHORED units to every position-driven preset, texture and noise-node default (all of which are tuned for the ±0.8 the pre-normalized built-in OBJs deliver), which is what shredded Vertex Wave on a 180-unit statue. The bake also has to be MEASURED in the entity's own frame — the old world-space `Box3.setFromObject` included `#preview-entity`'s resting tilt and `#spin-parent`'s live animation, so a model was scaled by its rotated hull (teapot ~19% undersized) and a dropped model's centring depended on the spin phase it happened to load at. Order matters: bake BEFORE `mergeByPosition` so its 1e-4 weld quantization is a fraction of the preview box rather than of authored units. Geometries are CLONED, never mutated (a glTF may reach one BufferGeometry from several nodes with different transforms), every local matrix in the subtree is then flattened to identity, mirrored transforms (negative determinant) get `flipWinding`, and skinned/instanced meshes deliberately fall back to the legacy Object3D path rather than desync their bind matrices. `public/podest.html` carries a hand-minified twin covered by NO sync plugin — `previewFitBounds.test.ts` runs both through the same assertions to catch drift.
- **Environment maps (`env` socket on the Output node) + `metalness`**: an image wired into Environment becomes real IBL — graphToCode emits the TEXTURE, never the sampled vec3 (`env: texture(_imageN_tex)` referencing the image node's module-scope texture var), tslCodeProcessor maps it to `envNode:` and shaderloader 0.5's `nodeProps` now assigns `material.envNode`; three's `EnvironmentNode` auto-wraps a texture-valued envNode in `pmremTexture()` (per-renderer cached prefiltered radiance + irradiance, blur driven by the Roughness channel, reflectivity by the new Metalness channel — the loader always accepted `metalnessNode`, the graph just never emitted one). The image-source emission is GUARDED on `imageAssetFor` (memoized, same call the image branch makes): the invalid-payload fallback declares NO `_tex` var, and referencing it would be a module-killing ReferenceError — that case, and any non-image source, passes through as a plain node ref instead (legal envNode; a Color node = uniform ambient environment), vec3-widened when its shape isn't 3. Unlike image→normal, connecting image→env does NOT flip colorSpace — the map stays sRGB (PMREM decodes it). `OUTPUT_CHANNELS` appends `metalness` at the END so existing return-object key order stays byte-identical; the REGISTRY input order is the separate, user-facing arrangement (Color, Emissive, Roughness, Metalness, Opacity, Discard, Normal, Environment in the Pixel section, Displacement alone in Vertex) which `PIXEL_PORTS` and the ShaderSettingsMenu's `OPTIONAL_OUTPUT_PORTS` mirror — keep all three sequences aligned. Both new sockets are opt-in (not in `OUTPUT_DEFAULT_EXPOSED`), enabled via Shader Settings or auto-exposed when an edge arrives. **The preview's Light dropdown grows an env entry** named after the attached image (`envMapName` string-selector in ShaderPreview — the cheap-string subscription pattern; falls back to the generic "Environment" label for non-image env sources): selecting it applies `LIGHT_PRESETS.env`, an EMPTY rig on purpose, because envNode supplies radiance+irradiance itself and analytic lights on top would double-light; `effLighting` degrades a persisted `'env'` to studio the moment the map is unwired, so a stored pref can never boot a lightless void. Verified headless (Chrome, three r184 WebGL2 fallback — the Safari path): the real generated module lights an unlit sphere with correct angular mapping and roughness blur. Two caveats: PMREM needs a real-sized map (mip count is log2(height)−2, so a tiny test texture renders BLACK — an 8×4 did; real equirects are fine), and the canvas import pipeline is LDR, so no HDR sun intensities. Env cost is invisible to the point system (it is a channel, not a node) — pricing it needs a ShaderCarousel calibration entry.
- **Output node stored channel values (the on-node widgets)**: every exposed channel row carries a value cell — unwired `roughness`/`metalness`/`opacity`/`discard`/`position` render a compact DragNumberInput (shown defaults 1/0/1/0/0; 0-1-clamped except Displacement, which may go negative), unwired `color`/`emissive`/`normal`/`env` render a swatch showing the channel default (color WHITE, emissive/env BLACK, normal the flat tangent-space `#8080ff` — no unset state; every color popover leads with a "Default (none)" entry that CLEARS the stored key — the way a picked normal is re-applied back to default/none) opening `inputs/PaletteColorPicker` (body-portal popover — fixed-position, zoom-independent — with palette rows + a native custom input; picks are history-bracketed via useHistoryBracket, and a module-level `closeOpenPicker` singleton closes the previous popover because KEYBOARD activation fires no pointerdown for the outside-close to see). A wired channel shows the incoming value instead (`edgeValueLabel`, plain text, blue when live) via the two-step cheap-string selector — built on **`getTargetEdges`, never raw `s.edges`**, or a feeder inside a collapsed group degrades every row to a grey `…` (the group id has no registry def). Values live on `OutputNodeData.values` (**`getNodeValues()` still hard-returns `{}` for output — readers access the field directly**), and every cell shares ONE fixed width (`.output-node__val`, 20px — the compact box's step arrows are hidden at that width; drag-scrub and click-to-edit remain) so the label column stays perfectly vertical ("1" and "0.35" would otherwise render different box widths). The codegen contract, in order of precedence: an ABSENT key emits nothing (byte-stability — every pre-widget graph and builtin emits identically); a WIRED edge always wins; emission is EXPOSURE-GATED (what the node shows is what emits — a tampered file can't emit from a hidden channel, and ShaderSettingsMenu clears a channel's value when hiding it, incl. the auto-managed opacity path); values emit as inline `float(<num>)`/`color(0x<hex>)` (adversarial: Number()+num(), hexLiteral whitelist); a stored DISCARD emits the statement `Discard(float(v));`, a stored env color is a constant ambient envNode, and a stored NORMAL color emits `normalMap(color(0x…))` — DECODED as a normal-map texel ([0,1]→[-1,1] + TBN), never fed raw to normalNode — **zero discard/displacement and the default normal `#8080ff` (the identity texel) are literal no-ops and deliberately emit NOTHING**, so the widget default and an absent key are indistinguishable in code (a non-zero discard is an unconditional truthiness cull — the mesh vanishes, by design). codeToGraph's `matchStoredChannelValue` collapses exactly those inline shapes (and the bare `return color(0x…)` color-only form) back into stored values — identifiers stay real nodes — and `applyStoredOutputValues` seeds exposure for valued channels. Two resync rules in `mergeMatch` keep Apply honest: old exposedPorts union in only the VALUED channels (unioning the parse's whole seeded list resurrected defaults the user explicitly hid), and stored values SHADOWED by a wire are carried from the old node (they can't appear in the code text, so the parse could never legitimately clear them — without the carry, any Apply wiped the value a disconnect is supposed to restore). `scriptToTSL`'s `NODE_PROP_TO_CHANNEL` maps `metalnessNode`/`envNode` back to editor channels (missing entries made Load Script silently drop them). The asset-card mirror renders the real widgets inert (`.node-preview-card__inert` pointer-events wrapper, unset swatch span).
- **World normals: `normalWorld`, not `normalLocal`, whenever a normal meets a world-space direction.** The preview nests the mesh under `#preview-entity` (a resting tilt — 45/45/0 on sphere and cube) inside `#spin-parent` (a full 360° turntable animation while playing, restored from persisted `fs:previewRotation` even when paused), so the object→world rotation is essentially never identity. `dot(normalLocal, worldViewDir)` evaluates to `dot(N_world, R·V)`: a correctly-shaped fresnel measured about a view direction rotated by the model, so the rim slides off the silhouette and — past ~78° with edge-glow's `pow(inv,3)*2` — clips to solid glow across the whole model. All four fresnel presets (edge-glow, hologram, force-field, stylized-water) and top-cover use `normalWorld`. **Displacement keeps `normalLocal`** (vertex-wave): object-space position displaced along an object-space normal is correct, and a world normal there would shear the model as it spins. Caveat worth knowing: in the fragment stage `normalWorld` resolves through the material's SHADED normal, so it reflects anything wired into the Output node's Normal channel — desirable for a fresnel, but a coupling `normalLocal` doesn't have.
