# FastShaders

Bi-directional TSL (Three.js Shading Language) visual shader editor. Users author and execute their own shader code inside the app, and `.fastshader` files can be shared between users — treat any loaded `.fastshader` or pasted shader source as adversarial input.

> **Before changing node visuals, the glyph system, `ShaderNode`, `NodePreviewCard`, or the Node Designer (`node-designer.html`), read [`NODE_DESIGN_REQUIREMENTS.md`](NODE_DESIGN_REQUIREMENTS.md) — it is the authoritative spec for node appearance/layout.**

## Stack

- React 18 + TypeScript + Vite (ES modules, base path `/FastShaders/`)
- `@xyflow/react` v12 — node graph editor
- `@monaco-editor/react` — code editor
- `zustand` v5 — state management
- `@babel/parser` + `@babel/traverse` — code→graph parsing
- `@dagrejs/dagre` — auto-layout (LR direction)
- `three` (WebGPU build) — shader runtime; FastShaders uses only `three/tsl`
  built-in functions including the MaterialX noise family (`mx_noise_*`,
  `mx_fractal_noise_*`, `mx_worley_noise_*`, `mx_cell_noise_float`)
- Path alias: `@/*` → `./src/*`

## Commands

- `npm run dev` — start dev server (port 5173)
- `npm run build` — typecheck + build (`tsc -b && vite build`)
- `npx tsc --noEmit` — typecheck only
- `npm test` — run the vitest suite once (CI-friendly)
- `npm run test:watch` — run vitest in watch mode
- `npm run tauri dev` / `npm run tauri build` — desktop (Tauri v2) shell; needs a local Rust toolchain. Releases are built in CI (no local Rust required)

## Deployment

**When the user says "deploy" (or "deploy to all"), it ALWAYS means: commit the pending work, push, and ship to BOTH targets** — never stop after the release pipeline:

0. **Commit + push first**: commit whatever is pending in the working tree (and push the `a-frame-shaderloader` submodule first if it changed) — "deploy" is standing authorization to commit and push; don't ask again.
1. **Release pipeline** (web on GitHub Pages + desktop binaries, in lockstep): `npm version patch && git push --follow-tags`. The `v*` tag triggers `.github/workflows/release.yml` → tests, macOS `.dmg` + Windows installers, gh-pages deploy.
2. **alvismisjuns.lv**: `npm run deploy:alvismisjuns` — builds with `FS_BASE=/fastshaders/` + the alvismisjuns CSP origins and uploads `dist-alvismisjuns/` via psftp to `https://alvismisjuns.lv/fastshaders/` (credentials in the gitignored `.vscode/sftp.json`; needs `brew install putty`). `-- --no-build` re-uploads the existing snapshot. Run it from the SAME committed/tagged state as step 1 so both hosts serve the same version — it deploys the working tree, not the last tag. The script curl-verifies the deployed version meta at the end.

## Key Conventions

- **Offline/desktop**: the app must run with NO network. Monaco is bundled locally (`CodeEditor/monacoSetup.ts` — `loader.config({ monaco })` + Vite `?worker` workers; never reintroduce the jsdelivr CDN loader) and fonts are self-hosted (the `@fontsource/inter/*.css` + `@fontsource/jetbrains-mono/*.css` weights are imported directly in `main.tsx` AND `nodeEditor.tsx`, and the `fs-fontsource-woff2-only` vite plugin strips the legacy `.woff` fallback `src` from the vendored @fontsource CSS at build time so only the woff2 subsets ship — never reintroduce a jsdelivr/Google-Fonts CDN link). `FS_DESKTOP=1` — set automatically for `tauri dev`/`tauri build` via the CLI's `TAURI_ENV_*` env — switches vite to the desktop profile: base `/`, CSP meta suppressed, ShaderCarousel excluded from dist (it ships instead as a Tauri resource staged in `src-tauri/carousel-dist/`, served over LAN by the in-app bench server — see the src-tauri bullet under Subprojects), and the `__FS_DESKTOP__` define hides the Local button + SC link and shows the "VR" bench popover. Preview-iframe asset URLs resolve via `new URL(base + path, location.href)` (`resolveAssetUrl` in `tslToPreviewHTML.ts`) so they survive non-http schemes (tauri://) — don't revert to `location.origin` concatenation.
- **Feedback ("!" toolbar button)**: the red `!` in the toolbar's right cluster opens `Modals/FeedbackModal` — a composer that assembles a plain-text report and hands it to the user's own mail client via `mailto:`, with a clipboard fallback. **Nothing is uploaded, and that is a constraint rather than a preference**: the build CSP is `connect-src 'self' blob: <deploy origin>` + `form-action 'self'` (`vite.config.ts`), so a POST to Formspree / Google Forms / any hosted endpoint is blocked by the app's OWN policy; the desktop build must work with no network at all; and a third-party form would make someone else a data processor for grant-funded research feedback. A `mailto:` navigation is CSP-exempt (navigation, not a fetch) and works in every build. If a server-side endpoint is ever wanted, it needs a `connect-src` widening plus the mailto path kept underneath for the offline case — don't quietly swap one for the other. Report assembly is PURE and tested in `utils/feedbackReport.ts` (the DOM reads live in the modal): the opt-in technical block carries version/build, **graph counts (nodes, how many are connected, connections, groups, notes), cost points vs the selected headset profile, and the preview mesh (built-in geometry name, or a custom model's name + vertex count + size)**, then browser/platform/renderer/display. Counts only — no graph content leaves. Edges are counted on the UNWRAPPED graph (`unwrapCollapsedGroupEdges`), or the same project would report differently depending on which frames happened to be collapsed. `previewMesh.countMeshVertices` is a **deliberate, narrow exception** to that module's "bytes are never parsed on the trusted side" rule: it counts OBJ `v` lines or reads integers out of a length-capped glTF JSON header — no geometry built, no URI resolved, no buffer touched, every path bounded, every failure returning null. It reports the AUTHORED vertex count, not what THREE ends up with (the OBJ loader emits non-indexed geometry and `fit-bounds` then welds duplicates), so don't reason about GPU cost from it. Also: `MAILTO_SAFE_CHARS` steers over-long reports to "Copy report" because Windows' shell truncates `mailto:` URLs around 2000 chars — a silently truncated bug report is worse than none, since the user believes they sent it. `previewBackend()` RESTATES the `__fsForceWebGL2` rule that `tslToPreviewHTML` emits as source text into the iframe (it can't be imported and called); `feedbackReport.test.ts` extracts that emitted function from the generated HTML, evaluates it, and fails if the two disagree — so a change to the WebKit-forcing rule can't silently make feedback reports lie about which renderer the user was on.
- **Sync engine**: `syncSource` field in zustand (`'graph'` | `'code'`) prevents infinite sync loops. `useSyncEngine` hook manages bidirectional sync with `lastSyncedCodeRef` to skip no-op updates
- **Node values**: always use `getNodeValues(node)` from `@/types` — never cast `node.data as ...`
- **Edge IDs**: always use `generateEdgeId(source, sourceHandle, target, targetHandle)` from `@/utils/idGenerator`
- **Single ShaderNode**: one component handles all TSL node types dynamically via registry
- **Latvian i18n is a display-only overlay** (`src/i18n/`): node types, TSL identifiers, generated code, and `data.label` stay canonical English — canvas node headers deliberately show the generated varName (`mul1`), so bilingual "Latviešu (English)" labels appear only where you pick/read about a node (Add-node menu, content browser, tooltips, settings menus, node designer). `language: 'en' | 'lv'` lives in the store, persists to `fs:lang`, stamps `<html lang>`, and is toggled by the Toolbar LV button; missing translations fall back to English.
- **Node search is RANKED, and `description` is part of the corpus**: `nodeMatchRank` in `nodeRegistry.ts` is the ONE match+order rule, shared by the AddNodeMenu (`searchNodes`) and the ContentBrowser (`rankDefs`) so both surfaces order a query identically. Tiers, lower wins: exact name (label / type / `tslFunction` / Latvian label) → name prefix → name substring → the `Also: …` alias tail → English prose → Latvian prose; `NO_MATCH` filters out. Ties keep registry order (stable sort). This exists because results used to come back in raw registry order, so a node that merely MENTIONED the query in its prose could outrank the node actually named that — writing "speed multiplier" into the Time description put Time above Multiply for "multip". So: keep UI-instruction wording out of `description`, put search aliases in the `Also:` tail (`displayDescription` strips it from the UI), and never let prose repeat another node's name casually. `nodeSearch.test.ts` pins the ordering and sweeps every description for name collisions.
- **Adding a node — one placement path**: right-click canvas, **Shift+A** (opens AddNodeMenu at canvas centre; the search box autofocuses, so Arrow/Enter completes a keyboard-only add), dropping a wire on empty space, dragging a palette tile, or **clicking/Entering a palette tile**. Every tile route funnels through `tileDrag.ts` — `tileActivationProps` → `dropTileAtCanvasCenter` dispatches the SAME `fs-tile-drop` CustomEvent the touch-drag path uses, so `placeTilePayload` (including drop-on-edge splicing) stays the single implementation. Don't add a parallel placement path. AddNodeMenu rows render `def.description` (`.context-menu__item--stacked`; the modifier exists because `.context-menu__item` is a shared single-row flex used by every submenu).
- **Node visuals**: per-node designer overrides live in `glyphs/customGlyphs.ts` — `{ svg, justify, scale (glyph-only; spacing fixed), dx/dy (glyph nudge), width (exact, ≥24), height (exact in both layouts, ≥28; shorter than content overflows; independent of glyph scale), text (0.4–2.5× header/value/label fonts via --node-text-scale), sockets (center-relative offsets, 4px snap; op layout natively, rows layout detaches the socket from its row — values follow) }`; frame radius/border are **fixed app-wide**. Connected inputs show edge values (`min…max` ranges, bare `…` when underivable; geometry attributes have analytical ranges). Multi-channel data **arriving on a connected input** stacks the node into N cards (sibling layers behind the card, staggered negative z, single group shadow from the deepest layer). Sockets are **static** — never set `transform` on handle `:hover` (React Flow positions handles via transform) — and never stack. The Node Designer (`node-designer.html`) saves via the dev-server endpoint `/__nd` (any browser), the File System Access API (Chromium), or download; see `NODE_DESIGN_REQUIREMENTS.md`
- **Node selection is a FILLED band**: every node shell (`.node-base` + its stacked `__stack-frame`, `.output-node`, `.note-node`, `.color-node`) marks selection with `box-shadow: 0 0 0 var(--node-selection-width) <colour>` — NOT `outline` + `outline-offset`, which drew a thin ring with a canvas-coloured gap inside it and read as two competing borders. Consequences to respect: box-shadow REPLACES rather than adds, so each rule must re-state `var(--shadow-node)` or selecting a node flattens it; the colour is the node's own `--node-cat` (falling back to `--border-focus`, which is what the category-less colour swatch uses); and `--node-selection-width` is deliberately NOT redefined in the dark block, since graph nodes render identically in both themes. A STACKED node suppresses its own band (`box-shadow: none`) because `.node-base__stack-frame` draws one band around the whole stack — ShaderNode also sets that inline, which wins on specificity.
- **Light theme by default, app-wide dark mode**: flat design with sharp dark shadows, CSS tokens in `tokens.css`. The toolbar sun/moon button (`codeEditorTheme`, persisted to `fs:codeEditorTheme` — the store field keeps its historical name) is the ONE dark-mode control: it themes Monaco AND stamps `data-theme="dark"` on `<html>` (via `setCodeEditorTheme` + an inline FOUC guard in `index.html`), which flips the CHROME tokens redefined in `tokens.css`'s `:root[data-theme="dark"]` block (backgrounds, text, borders, chrome shadows, `color-scheme`). **Graph nodes must render identically in both themes** — node bodies read the theme-invariant `--node-bg` (not `--bg-panel`), node text/borders are hardcoded literals or inline cost/category colors, and `--shadow-node*`/`--type-*`/`--cost-*`/`--cat-*` are deliberately NOT redefined in the dark block. Per-surface dark tweaks (hardcoded light-assuming literals that tokens can't reach) live as `:root[data-theme="dark"]` blocks in each component's own CSS; the React Flow grid color is a prop flipped in `NodeEditor.tsx`. The canvas background is user-pickable AND remembered PER THEME (`nodeEditorBgColorLight`/`Dark`; `nodeEditorBgColor` is the effective active-theme value; dark default `#1e1f22`); cost badges and 1-channel edges auto-flip via `getContrastColor(nodeEditorBgColor)` so they invert to light on the dark canvas automatically. `projectImport` applies theme BEFORE canvas color so the color lands in the right per-theme slot.
- **A-Frame pipeline**: graphToCode → tslToShaderModule → shaderloader 0.5 (runtime TDZ fix + auto-import injection + typed `export const schema` parsing — `number`/`color`/`map`) → dynamic blob import. (The old standalone `.html` export left with the A-Frame tab — the `.js` download is the only export.) Shaderloader 0.4 is FROZEN: shaders exported before 0.5 reference it from the jsdelivr CDN, so never edit it — new loader work goes in 0.5 (or a bump).
- **Preview renderer backend (WebGPU vs WebGL2)**: the sandboxed preview iframe (`tslToPreviewHTML.ts`) and the standalone podest viewer (`public/podest.html`) both inject `<a-scene>` only AFTER a WebGPU pre-flight — three r184 auto-selects WebGPU on `navigator.gpu != null` ALONE, so the pre-flight requests a real adapter (2s timeout) and hides `navigator.gpu` (→ WebGL2 via GLSLNodeBuilder, TSL compiles identically) when it can't deliver. **Safari is force-hidden to WebGL2 up front** (`__fsIsSafari` UA check) — three r184's WebGPU backend can be handed an adapter yet never paint on Safari (flat-color pane, no error). Same move the XR popup already makes. A 6s watchdog turns any remaining no-paint into a visible sticky error.
- **Podest unattended / pedestal mode** (`public/podest.html`): the viewer is meant to run for WEEKS with nobody touching it, which is a different problem from "a page that works". The presentation layer is the ⛶/⤡ fullscreen button (bottom-right) plus an optional top-centre title (auto-derived from the dropped file name, `_`→space, click it to edit text + colour; `textContent` only). **Presentation mode is deliberately WIDER than the Fullscreen API**: fullscreen needs a user gesture, and an unattended pedestal has nobody to give one after a browser auto-update — it would come back windowed with the panel over the artwork and, far worse, no wake lock, so the display blanks at the OS idle timeout and stays black for the week. So the mode is remembered (`fs:viewerPresenting`, or `?present=1` for a kiosk launcher) and `is-present` on `<html>` — not `is-fs` — is what hides the panel, hint and error banner; `is-fs` governs only the ⛶ button's own auto-fade, since in windowed presentation that button is the way back in (⛶ then Esc leaves the remembered mode). Everything that must survive the reload asks `presenting()`, never `fsElement()` — **including the release-race guard inside `requestWakeLock`**, which gated on fullscreen would release every lock the instant its promise resolved and silently undo the whole thing. Behind that sit five long-run guards, each fixing something that actually breaks on that timescale: (1) **the stage iframe is disposable** — `applyStateToStage()` replays background/spin/geometry/shader on every `fs:ready`, so the pending queue is DISCARDED rather than flushed (replaying both would recompile the shader twice) and any restart is invisible; (2) **`time` is folded back every ~4.5 h** — three's `time` is a float32 accumulating seconds since boot, so its resolution decays to 7.8 ms after a day, 62 ms after a week and 250 ms after a month (a slideshow); the stage takes `renderer._nodes.nodeFrame.time %= TIME_WRAP` where `TIME_WRAP` is an exact multiple of 2π (~16380 s), so `sin(time)`/`cos(time)` cross the fold with NO visible jump and the quantum never exceeds ~1 ms (a shader's own `time.mul(20)` multiplies it) — modulo not zeroing, so the fold stays 2π-aligned however far behind the beat has fallen; if that private path ever disappears the beat reports `wrapNeeded` (rebasing as it fires, so it can't latch) and the parent restarts the stage instead. The stage also rebases `nodeFrame.lastTime` on `visibilitychange`→visible, or the first frame after an overnight sleep would dump the whole hidden gap into `time` in one step; (3) **device loss is terminal and silent** — the stage wraps `renderer.onDeviceLost` (keeping three's own handler) AND hooks the raw `backend.device.lost` promise, because three returns early on `reason === 'destroyed'` and would never call the callback, plus a `webglcontextlost` listener; all report `fs:stage-dead`, and a 5 s `fs:beat` carrying the cumulative `info.render.calls` lets the parent catch a stall with no throw at all (best-effort: it proves the loop ran, not that pixels landed); restarts are floored at 30 s apart and after 6 in a row back off to one retry every 10 min — never a permanent give-up, since a transient driver fault must not end the exhibit (watchdog is suspended while the document is hidden — a frozen counter there is normal); (4) **the last drop is mirrored to IndexedDB** (`fs-podest`/`session`, throw-safe, shader ≤24 MB + model ≤64 MB) and replayed at boot, because a browser auto-update or power blip otherwise leaves a grey sphere — the record carries the tuned **uniform values** too (losing the exhibitor's tuning shows the wrong artwork), a drop that lands first always wins, and a user-typed title outranks the replayed one; (5) **the screen wake lock** is requested at boot, on entering presentation mode, on `visibilitychange`, and again on every 5 s watchdog tick — the platform can drop a lock on its own and a UA may refuse it until it can grant it, so the only robust pattern is to keep asking (it early-returns when a lock is already held). Also: the error relay is rate-limited IN the sandbox (identical repeats/minute + 20/minute cap) since a per-frame `console.error` would otherwise postMessage forever, banners self-dismiss after 20 s, and 90 s of idle in fullscreen returns the camera to the framing pinned by `fs:save-view` at entry (a visitor's spin must not outlive them). **Checked and deliberately NOT fixed**: the bundle's anime.js calls the undeclared `activeInstance[i].pause()` on visibilitychange, but A-Frame builds its instances with `autoplay:false` and ticks them by hand, so anime's active list is always empty and that line never runs (verified in a browser).
- **XR popup (preview "VR" button)**: opens the shader at the app's REAL origin (WebXR needs a top-level page; hidden on desktop builds). `tslToPreviewHTML`'s `xr` mode now (1) **auto-enters immersive VR** once `navigator.xr.isSessionSupported('immersive-vr')` confirms real support — never on the magic-window fallback, which would strand the user in pseudo-VR — while keeping an in-document `#vr-gate` button visible until a session actually starts (a `window.open`+`document.write` document may not inherit the opening click's transient activation, and an in-document gesture is what Quest Browser reliably accepts); on non-XR devices the same gate becomes a Fullscreen toggle (capability-resolved label, never a UA sniff); and (2) draws a head-locked frame-time/FPS panel (`fs-xr-stats`): a CanvasTexture quad added to the THREE camera OBJECT via `getObject3D('camera')` — a child `<a-entity>` would world-lock in XR — redrawn at ~4Hz so the readout doesn't bias the GPU cost it reports, rasterized to canvas because A-Frame's `<a-text>` fetches its MSDF font from a CDN (this app must run offline). The number is the presented frame PERIOD (includes vsync — reads 72/90/120Hz until the shader actually misses frames).
- **Edge interactions** (`TypedEdge` + `bezierGeometry.ts` + `NodeEditor` handlers): edges are drag-to-disconnect, and support (1) **drop-on-edge insertion** — dragging a node/tile within `DROP_ON_EDGE_RADIUS` (screen px ÷ zoom) of an edge splices it in (`findNearestEdge`/`tryInsertOnEdge`), and (2) **routing waypoints** — double-click an edge or right-click → "Add routing point" drops a draggable point the wire curves through (Catmull-Rom spline); double-click a point removes it. Waypoints live on `edge.data.waypoints` (flow coords), are **visual-only** (graphToCode/cpuEvaluator never read them; persist via localStorage autosave + undo, and are carried across a code→graph resync by endpoint match in `useSyncEngine` — like groups; a fresh `.js`/zip import starts without them). **The renderer and the drop-on-edge hit test share `bezierGeometry.ts`** so what highlights is exactly what snaps — a routed edge is measured against the SAME spline it draws (`distancePointToSpline`). `setEdgeWaypoints` pushes history once per gesture (add/remove/drag-start), never per drag-move frame.
- **Drag-connect** (`dragConnect.ts` + NodeEditor drag handlers): dragging a node so its CENTER lands on another node's body proposes a connection — the hovered node rings (`fs-connect-target`), the chosen input socket rings, and a tooltip names it; releasing commits exactly what the tooltip showed (even on a sub-`DRAG_HISTORY_THRESHOLD` drop — a shown preview must not lie; the plan's endpoints are re-validated at drop against mid-drag mutations like held-pointer Cmd+Z). Direction follows the side (dragged left of the hover's center → dragged.out feeds hover.in; right → hover.out feeds dragged.in; impossible/cyclic directions fall back to the other before giving up), vertical alignment picks the best (output, input) PAIR — so multi-output sources like Data-node columns choose their column by alignment too — with FREE inputs beating occupied (occupied only replaced when nothing is free; the gesture counterpart's own existing edge doesn't count as occupying, so re-docking a feeder re-recognizes its connection instead of double-feeding a second input), and cycles are never offered. Cycle/occupancy checks run on the UNWRAPPED logical graph (`unwrapCollapsedGroupEdges`) — raw collapsed-group boundary edges would contract members into one vertex and fabricate cycles. Hit boxes follow the VISIBLE card (cost-scaled types multiply the measured box by `getCostScale`). The drop snaps the node beside its new peer (handles aligned, `CONNECT_SNAP_GAP` apart) and then MAKES ROOM (`overlapCascade.ts`): the connected pair stays fixed and overlapped nodes escape along the cheapest single axis (+10px gap) that clears ALL current offenders AND the whole settled set — the full-set check is load-bearing: a greedy per-box push ping-pongs a wide mover in the corridor between the two anchors (the exact geometry every snap creates) — with knock-on pushes rippling outward (BFS, settle-once — deterministic, terminates; a cascade beats a grid here because node footprints vary ~10× and minimal displacement preserves the user's layout). Deltas are absolute-space applied to local positions (parent-invariant), and every shifted node (plus the tile-snapped node) gets the SAME position→membership reconciliation a user drag gets (`reparentedNode` + parent-before-children reorder) — a member pushed out of its group frame detaches instead of invisibly vanishing on collapse. The plain single-pass anti-overlap nudge remains for NON-connect drops. Connect + snap + cascade + reparent ride the gesture's single `pushHistory`. Node-body hover WINS over the drop-on-edge preview AND suppresses splice-on-drop (what wasn't previewed is never committed); wire-connects and drop-connects share one `applyConnection` (single-input enforcement, hidden-socket exposure, image→normal colorSpace flip). The decision logic is pure and tested (`dragConnect.test.ts`); NodeEditor only adapts React Flow internals (measured boxes, MOUNTED handle bounds — hidden `exposedPorts` params and unmounted grow-sockets, i.e. the arithmetic folds + the variadic `append`, don't participate) and paints the preview imperatively like the edge highlight. **Palette tiles drag-connect too**: HTML5 dragover previews via the payload record tileDrag keeps from dragstart (the DnD spec hides `dataTransfer` data until drop) and the touch path streams `fs-tile-drag-move`/`-end` events (which also gave touch drags the drop-on-edge highlight); the not-yet-created node plans as a PHANTOM (`TILE_PHANTOM_ID` — def-derived ports all at the cursor, so vertical tile movement picks the hover node's socket and the tile side offers its first free port; a fresh id can't cycle or occupy), the drop swaps in the real id, connects via the same `applyConnection`, and snaps beside the peer two rAFs later (post-measure) — all under `addNode`'s single history entry. Click/Enter palette adds never preview, so they never connect (`activate` flag on the drop detail) and keep their historical unconditional splice at canvas centre. Hardening: the drop commits ONLY plans referencing `TILE_PHANTOM_ID` (a live node-drag preview can't be hijacked), stale HTML5 payload records are healed on OS-file drops (`endHtml5TileDrag`), only one touch tile drag runs at a time, the edge highlight is withheld from payloads that can't splice (saved groups, textures, input-less nodes), and the canvas `onDragLeave` falls back to a coordinate check when `relatedTarget` is null (Safari) so child-boundary crossings don't flicker the preview.
- **Centralized vendoring (single source + sync)**: the A-Frame IIFE bundle (`a-frame-180-a-01.min.js`), shaderloaders (`a-frame-shaderloader-0.4.js` frozen + `a-frame-shaderloader-0.5.js` active), and orbit-controls live ONLY in `a-frame-shaderloader/js/`. The `fs-vendor-sync` vite plugin (`vite.config.ts`) copies them into `public/js/` and the bundle into `ShaderCarousel/components/three/` at dev/build start; `src/vendorSync.test.ts` fails on drift. **Never hand-edit the copies** — edit the submodule source and re-run vite. Everything runs **Three.js r184**: the bundle (super-three 0.184), `node_modules/three` (`^0.184.0`), and the carousel's standalone ESM `ShaderCarousel/lib/three/*.min.js` (the official minified builds copied from `node_modules/three`, used by static/microplane benches via import map).
- **rAF ref pattern**: PreviewNode/MathPreviewNode/EdgeInfoCard overwrite refs for animation — this is correct (avoids stale closures)
- **Canvases inside the React Flow viewport MUST be CPU-backed**: every `getContext('2d', { willReadFrequently: true })` in PreviewNode/MathPreviewNode/ClockNode is deliberate — an ACCELERATED canvas becomes its own compositing layer in Safari, WebKit's overlap compositing then promotes the surrounding nodes into layers rasterized at 1×, and the whole zoomed canvas goes blurry (empirically bisected 2026-07-11 via the `?fsdbg=nocanvas` switch in `main.tsx`, which stays available for renderer triage). Never add a plain-context or WebGL canvas to anything rendered inside `.react-flow__viewport`.
- **Noise nodes**: 8 MaterialX-backed nodes (`perlin`, `perlinVec3`, `fbm`, `fbmVec3`, `cellNoise`, `voronoi`, `voronoiVec2`, `voronoiVec3`) all use the same `pos`/`scale` parameter convention. graphToCode emits them via the `def.category === 'noise'` branch; codeToGraph parses them via `processNoiseCall`; CPU thumbnails come from `noisePreview.ts`; live GPU previews run the generated TSL through the preview iframe (`graphToCode` → `tslToPreviewHTML` → `convertToShaderModule`). `tsl-textures` was removed in favour of three.js's built-in MaterialX noise; the `texture` category backs the content-browser Textures tab (`builtinTextures.ts`) and holds exactly one (hidden) node definition — the drag-dropped Image node.
- **Time node's `speed`**: the Time node's multiplier follows the SAME opt-in `exposedPorts` rules as the noise params — hidden until ticked in Node Settings, drag-revealed dimmed, auto-exposed when an edge lands, and a wired edge overrides the stored number. It lives in `defaultValues`, NOT `def.inputs`, and must stay there: `ensureBareInputNode` refuses to auto-create a node whose def declares registry inputs, so adding one would silently drop the Time node (and its edge) from `sin(time)`. graphToCode emits `time.mul(<literal|var>)` (method chain — no `mul` import, same convention as the noise `scale`); `tryParseTimeSpeed` collapses BOTH forms back into one Time node, wiring the variable form to the `speed` port. The collapse is deliberately narrow — bare `time` receiver, unshadowed, exactly one argument, and a variable that resolves to a real node — so the fixtures' `const t = time; mul(t, x)` idiom stays a genuine Multiply.
- **Asset-browser ordering**: node tiles sort by GPU points (cheapest first, every tab — not just Noise); Presets and Textures sort by member count, since a ready-made asset is a graph you open and read, and points can rank a 3-node voronoi above a 20-node arithmetic chain. Both are display-layer sorts in `ContentBrowser` — `builtinPresets.ts` keeps its tier order (and the test that pins it).
- **Time node speed**: the Time node carries a `speed` multiplier in `defaultValues` — a settings-only number (no socket; `usesExposedPorts` excludes time), rendered automatically by the generic `NodeSettingsMenu` defaultValues loop. `graphToCode` has a dedicated `def.type === 'time'` branch placed BEFORE the generic `inputs.length === 0 && defaultValues` branch (which would emit the invalid `time(1)` — `time` is a uniform node OBJECT, not a callable): `speed === 1`, a missing key, or any non-finite value emits the historical bare `const time1 = time;` BYTE-FOR-BYTE, so no already-exported shader changes; otherwise it emits the method chain `const time1 = time.mul(k);` (no extra import, same convention as the noise `scale` param). `codeToGraph`'s `tryParseTimeSpeed` collapses that shape back — but ONLY when the receiver is the bare `time` identifier, `time` is unshadowed, there is exactly one argument, and it folds to a numeric constant. It deliberately does NOT collapse `mul(time, k)`, `mul(time1, k)` (the human idiom — ~51 occurrences across the `Tests/` corpus, usually two muls sharing one Time node) or a non-literal multiplier (`mul(t, speed)` in builtinTextures/builtinPresets). **`ensureBareInputNode` needs its `def.defaultValues` bail-out to except `time`** — without it, adding defaultValues silently drops the Time node AND its edge from `sin(time)`/`add(pos, time, normal)` with no error. `values.speed` is adversarial at all three read sites (graphToCode, cpuEvaluator, ClockNode): `Number()` then `Number.isFinite() ? … : 1`, never `String()` and never `resolveExposedParam`. ClockNode integrates `dt * speed` into a phase accumulator (never `Date.now() * speed`, which teleports the hand on every scrub frame) with the rAF deps kept `[]`. `complexity.json` keeps `"time": 0` — `nodeCostPoints` can only express value-dependent cost for `chainable` defs, and `node.data.cost` is a creation-time snapshot frozen into saved graphs.
- **Image node**: drag-dropped images become a hidden `imageNode` (mirrors the Data node pipeline). Payload = whitelisted `data:` URL on `values.imageB64` — **adversarial**: codegen re-encodes the decoded bytes (`decodeImageNode` → `bytesToBase64`, never the stored string), the ShaderNode thumbnail renders only `validImageDataUrl()`, malformed payloads degrade to an inert `vec3(0,0,0)`. **The payload does NOT sit in the editor's code**: graphToCode emits `img.src = "fs-asset:<node>-<hash>"; // name, WxH, size` and `utils`-style pure helpers in `engine/imageAssets.ts` splice the real `data:` URL back in at the four surfaces that RUN or EXPORT the module (preview iframe, XR popup, Output tab, Download Shader) — a word-wrapped 600K-char literal otherwise buried the shader under ~8,500 rows in Monaco and re-tokenized megabytes per graph edit. Safe because image nodes are already one-way through codeToGraph, so nothing ever read that payload back; the placeholder carries a payload hash so changing an image's BYTES still changes `code` and invalidates the code-keyed preview memos. An unknown placeholder key is left verbatim and degrades via the existing decode() fallback. Emission = FLAT module-scope statements with top-level await (never an async IIFE — codeToGraph's ReturnStatement visitor would hijack the output): `new Image()` → `try { await decode() } catch` → 1×1 fallback → `THREE.Texture` with RepeatWrapping, pinned `flipY`, sRGB or linear data-map per `values.colorSpace` ('color' | 'data'); the Fn body samples `texture(tex, uvExpr).rgb` (vec3 out; `uv` input falls back to `uv()`). **Normal-map decode**: an image wired into the Output node's `normal` socket is a tangent-space normal MAP, not a raw normal — graphToCode wraps that channel in TSL's `normalMap(...)` (which does the `*2-1` remap + TBN tangent→view transform + normalize) rather than feeding the raw [0,1] sample into `normalNode`. `normalMap()` needs LINEAR input, so `NodeEditor.onConnect` auto-switches the image to the `data` colorSpace on connect (skipped if the same image also drives an sRGB channel — one texture, one colorSpace; mutated via `setNodes` so connect+flip is a single undo step). Non-image sources feeding `normal` stay a raw normal override (unwrapped). NodeSettingsMenu has a "UV / Texture" section (values read Number-coerced by codegen): `tileX/tileY`, `offsetX/offsetY`, `repeat` (off → ClampToEdge), `flipX`/`flipY`, and the data-map toggle. All five inputs (`uv`, `tileX/tileY`, `offsetX/offsetY`) follow the SAME opt-in `exposedPorts` rules as the noise nodes (see NODE_DESIGN_REQUIREMENTS.md → "Exposed parameter sockets"): hidden until checked in the generic NodeSettingsMenu sections, auto-exposed when an edge arrives (useSyncEngine + loadGraph migration), wired edge overrides the stored value, hiding drops the port's edges. Dragging a wire within snapping distance of a node with named input sockets forces its input name-tooltips visible (floated left of each socket — TypedHandle `reveal` prop; operator cards, the Output node, and collapsed groups opt out — generic/permanent labels); noise + Image nodes additionally reveal their hidden sockets as floating dots on the card's left edge — dimmed, layout untouched — and landing the connection exposes that port permanently (`connectionReveal.ts` + `RevealSockets.tsx` + onConnect/onReconnect auto-expose; the reveal radius IS the editor's snap radius, one shared `CONNECTION_RADIUS`). The Output node does NOT drag-reveal hidden channels (settings-menu only). On the card, imageNode input rows show ONLY the port label (`.shader-node__in-label`) — never inline number widgets (numbers are context-menu-only). When the graph embeds images, "Download Shader" produces a `.zip` (dependency-free STORE writer, `zipWriter.ts`): the self-contained `.js` + `images/<sanitized-name>.<real-mime-ext>` + README. Import accepts `.js` AND `.zip` on every surface — Load Script, the code-panel drop, and the canvas drop — via the shared `projectImport.ts` path (`zipReader.ts` picks the `.js` carrying the FASTSHADERS_PROJECT_V1 block; the loose image files are ignored on import since the payloads ride in the `.js`). NB the raw sample renders mirrored left-right in the preview, so codegen bakes the `1-u` correction into the DEFAULT; the Flip X checkbox (unchecked by default) mirrors relative to the corrected look — checking it emits the raw `uv()`. Context menus get enlarged type via `--font-size-*` token overrides scoped on `.context-menu` (ContextMenu.css) — all submenus + DragNumberInput inherit them. Limits (`imageNode.ts`): 600K chars/image with downscale-retry, 3M chars total, 64MP source guard — bypassable via the LimitModal checkbox (`fs:ignoreImageLimits`); the 8M-char hard ceiling always applies. localStorage quota failures (graph autosave + saved groups) surface a `storage-quota` LimitModal notice instead of failing silently.
- **Selection**: **Shift+click adds to the selection** (`multiSelectionKeyCode={['Shift','Meta','Control']}` — an array is "any of these", and it's module-scope because `useKeyPress` memoizes on its identity). This REQUIRES `selectionKeyCode={null}`: Shift's React Flow default is hold-to-marquee, and while it's held the Pane's `onPointerDownCapture` stopPropagation()s a pointerdown that landed on a node and opens a rubber band instead — so Shift+click would marquee rather than extend. Nothing is lost, because `selectionOnDrag` already gives a modifier-free marquee from empty canvas (`isSelecting = selectionKeyPressed || userSelectionActive || selectionOnDrag`). Marquee stays mouse-only — `selectionOnDrag` is off on coarse pointers so the first finger of a two-finger pan can't start a selection box.
- **Groups**: selection groups are first-class React Flow nodes (`type: 'group'`) created via Ctrl+G or right-click → Group Selection. They have no registry entry and no shader semantics — `graphToCode`/`cpuEvaluator` ignore the *node*, but call `unwrapCollapsedGroupEdges()` from `edgeUtils.ts` at their entry to translate visually-rewritten boundary edges back to their real child endpoints, so collapse state never affects compiled output. Groups can be recolored, renamed, collapsed (members hidden via `display: none` className — *not* React Flow's `hidden: true`, which would unmount rAF loops; the toggle anchors at the frame's TOP-RIGHT corner — the pill appears at the old top-right and expanding grows leftward from the pill's top-right, `groupCollapse.test.ts` pins the round-trip), saved to a per-browser library (`fs:savedGroups`), and dragged out of containers. Members never get `extent: 'parent'` — `onNodeDragStop` reconciles `parentId` after every drag instead. **Notes are ordinary members**: Ctrl+G sweeps a selected note in, dragging one into a frame adopts it, and it then rides the group's drags/collapse/ungroup/save-to-library like any node (a note is usually the LABEL for the cluster being grouped, so leaving it outside stranded the annotation). Notes stay exempt only from the placement rules that would fight their purpose — anti-overlap nudging (it would fling a note off the nodes it was deliberately dropped over) and drop-on-edge splicing — both guarded by `isNote` in NodeEditor's drag handlers, not by bailing out of membership. `addNote` PREPENDS, so ordering matters: a note is born parentless and both adoption paths re-sort it after its parent (`groupSelection` front-inserts the container; the drag handlers run the parent-before-children lift). `groupNotes.test.ts` pins all of it. `organizeSelection` still skips notes — auto-layout has no meaningful slot for a free-floating annotation. **An expanded frame's only interactive surface is its HEADER** (drag, select, and the right-click GroupSettingsMenu): the body is `pointer-events: none` so the area inside a frame behaves like bare canvas — right-click opens the Add-node menu, drags rubber-band/pan, clicks don't select the group. This relies on React Flow already marking `.react-flow__viewport`/`.react-flow__nodes` pointer-events-none, so a pass-through frame leaves `.react-flow__pane` as the event target — which is what the Pane's `wrapHandler` guard requires before firing `onPaneContextMenu` (and it's why the touch long-press path, which dispatches a synthetic `contextmenu` on the pointerdown target, routes identically). Collapsed pills opt back in and stay fully interactive — a pill stands in for a node. The resize control opts back in too; see the pass-through block in `GroupNode.css`. **Groups resize exactly like notes**: a single `NodeResizeControl` at the BOTTOM-RIGHT with the notes' enlarged 15×15 grab box, rendered only while expanded AND selected — not React Flow's full `NodeResizer`, whose eight edge/corner handles ringed the frame and turned every near-miss along an edge into an accidental resize. So both surfaces now follow one rule: drag by the header, scale by the one corner. (Notes get that drag rule from `dragHandle: '.note-node__header'`; groups get it from the pointer-events pass-through above — different mechanism, same behaviour.)
- **Board drawings**: freehand ink annotations (DrawingLayer + DrawToolbar) are VISUAL-ONLY like notes/waypoints — invisible to graphToCode/cpuEvaluator/the sync engine. Strokes live in their own store slice, ride undo history BY REFERENCE (committed strokes are immutable; never structuredClone them), share the fs:graph autosave payload and the FASTSHADERS_PROJECT_V1 embed, and are sanitized as adversarial input on load/import (sanitizeDrawings caps). Same-opacity strokes must not compound where they cross: opacity is quantized and rendered via one SVG group-opacity isolation buffer per opacity level, and stroke colors are 6-digit hex ONLY (8-digit alpha would smuggle past the isolation).
- **History**: circular buffer (50 entries) with undo/redo via `structuredClone`, Cmd+Z/Cmd+Shift+Z shortcuts, plus visible Undo/Redo buttons in the canvas's bottom-LEFT bar (`.fs-canvas-bar` — one pill also holding the Draw tools and the zoom −/+ / fit / canvas-bg controls that replaced the React Flow Controls stack; the buttons call `undo()`/`redo()` directly — equivalent to the keyboard path, since the graph→code effect re-runs on any nodes/edges identity change regardless). **Continuous gestures must be bracketed**: `beginInteraction()`/`endInteraction()` snapshot ONCE up front and suppress `pushHistory` until the gesture ends, so a DragNumberInput scrub is one undo entry instead of one per pointermove frame — and, just as importantly, the whole graph isn't `structuredClone`d 60×/s (megabytes once images are embedded). `beginInteraction` deliberately ignores `isUndoRedo` (that flag guards the sync engine's post-undo reconciliation; a pointer gesture is always a real mutation, and honouring a stale flag would silently swallow the gesture's history). DragNumberInput brackets on first move — not pointerdown, since a press that becomes a click-to-edit would push a no-op entry — and closes the bracket on pointerup, pointercancel, and unmount.
- **Preview rebuild is debounced**: only property uniforms have a postMessage hot-update path; every other value is baked into the generated TSL, so editing one swaps `srcDoc` and re-fetches/re-parses the ~1MB A-Frame bundle under a fresh opaque origin. `useDebounced(previewCode, 200)` (trailing, so first paint isn't delayed) collapses a scrub's pointermove stream into a single rebuild on release. A "Compiling shader…" overlay covers the gap, cleared by `fs:preview-ready` (success) **or** `fs:preview-error` (failure — a broken shader never reaches the ready handshake, since `checkShaderReady` polls for bound uniforms and just gives up), with a 12s failsafe so it can never stick over the error text.
- **Custom preview mesh**: dropping a `.obj`/`.glb`/`.gltf` on the 3D preview (or importing a zip carrying one) loads it as the `custom` preview geometry. The mesh lives in the store's `previewMesh` slice — never history, the localStorage autosave, or the project embed (bytes can be tens of MB) — but IS mirrored to an **IndexedDB cache** (`utils/previewMeshCache.ts`) so it survives a reload; localStorage is the wrong store here (strings only, ~5-10 MB origin budget the graph autosave already fills). `setPreviewMesh` is the single persist chokepoint (fire-and-forget, resolves on every failure path so a quota error can't break a drop); the boot restore passes `{ persist: false }` since those bytes came out of the cache. Restore ordering is the subtle part: the read is async, so `validateGeometry` has ALREADY downgraded a stored `'custom'` to `'sphere'` and `usePersistedState`'s persist effect has written that downgrade back — which is why `bootGeometryWasCustom()` samples the key at MODULE INIT, before React mounts, and the restore re-selects `'custom'` from that snapshot. A synchronous drop or zip import always wins over the cache read. Cached bytes are re-validated as adversarial input (`recordToMesh` → the same `createPreviewMesh` constructor: extension whitelist, 64 MB cap, GLB magic, name sanitize) and get a FRESH session id so the iframe rebuilds. `validateGeometry` accepts `'custom'` only while a mesh is loaded (IMPERATIVE `useAppStore.getState()` read: the validator's identity must stay module-scope stable for `usePersistedState`, yet see a mesh a zip import committed synchronously before the `fs:project-imported` re-read). The sandboxed iframe receives models via the generalized `fs:obj-model` feed (glb rides as bytes, obj/gltf as text pre-decoded ONCE at load; keyed `custom:<id>` so a stale feed can't cross documents — every mesh change forces an iframe rebuild, and the per-rebuild structured-clone copy is the accepted price of a fresh document). Drops over the iframe are forwarded to ShaderPreview via `fs:preview-drag`/`fs:preview-drop` (podest's forwarder pattern — the iframe swallows drag events over the whole 3D view; the parent root handles chrome-area drops, and `.js`/`.zip` drops route through the shared `projectImport` path). `fit-bounds` takes an EXPLICIT `regen` flag at every attach: true rebuilds normals/UVs (OBJ — non-indexed loader output), false preserves authored GLB data (spherical UVs only when missing); podest's twin component defaults the OPPOSITE way, so never rely on either default. SECURITY: model files are adversarial — bytes cross only via postMessage + iframe-minted blob URLs, and BOTH sandboxed stages (editor preview + podest) install a `THREE.DefaultLoadingManager.setURLModifier` allowlisting `blob:`/`data:` so a hostile `.gltf`'s absolute-URL buffers/textures can't phone home (CSP is absent in dev, desktop, and podest — the modifier is the real control, not CSP); the XR popup runs at the app's REAL origin, so it installs an origin-widened variant (`blob:`/`data:`/same-origin — built-in models load by real URL there). Iframe-forwarded SHADER drops (`.js`/`.zip`) require a `window.confirm` — sandboxed code can forge `fs:preview-drop`, and a project import replaces the whole graph (model files only swap the session mesh, so they stay immediate); a combined shader+model drop is sequenced shader-first so the dropped model deterministically wins. Export: with a mesh loaded, "Download Shader" emits a zip with `models/<sanitized-name>` (`exportBundle.ts`, pure + tested); import: `importShaderZip` restores the first model entry and forces `custom` geometry (podest pairing semantics; a model-ONLY zip returns `'model'` and just loads the mesh), while model-LESS text imports CLEAR the stale mesh so it can't contaminate the next export. DRACO/meshopt-compressed GLBs are out of scope (no decoder bundled — the loader error surfaces in the iframe overlay).
- **localStorage**: auto-saves graph, split ratios, shader name, headset selection, cost colors, canvas bg color, code editor theme, UI language (`fs:lang`), board drawings (inside the `fs:graph` payload; sanitized on load) + draw-tool prefs (`fs:drawColor`/`fs:drawWidth`/`fs:drawOpacity`), image-downscale warning opt-out (`fs:hideImageDownscaleWarning`), preview prefs (geometry, lighting, subdivision, bg, uniform bounds, uniform values, camera pos, rotation, playing state), saved groups (debounced 300ms), the last-opened asset-browser tab (`fs:assetTab` — validated against the live category list, so a renamed/removed category falls back to All instead of selecting a tab that renders empty), asset-bar height (`fs:assetBarHeight` — dragged by the bar's grip, or Ctrl/Cmd+wheel over the strip; the legacy `fs:assetBarCollapsed` + `fs:assetZoom` keys are read ONCE to migrate an old collapse/zoom into a height and are never written again). Reset clears camera/rotation/playing and restores lighting/subdivision/uniforms — bg color, uniform bounds, and geometry are treated as user preferences. Uniform values persist by name: removing a property node from the graph keeps the stored value (the iframe ignores `fs:uniform` messages for unknown names), so re-adding a property with the same name restores the user's last tuning.
- **VR cost budgeting**: 6 VR headset presets with maxPoints, cost gradient visualization in CostBar
- **Alpha comes ONLY from the `opacity` channel.** Everything that can leak into it is normalised in graphToCode: a source whose shape is `!== 3` wired to an ALPHA-BEARING channel (`color`, `emissive` — the two that reach `diffuseColor`; `emissive` counts because shaderloader 0.5 copies emissiveNode→colorNode when no colour is wired) is emitted as `vec3(ref)`. Both ends leak: `vec4(float)` SPLATS (alpha = the scalar) and `vec4(vec4)` is an IDENTITY (alpha = the source's `w`, and a fresh Vec4 node's w is 0 → fully transparent). Shape is read from the PORT the edge leaves (`shapeOfEdgeSource`, honouring `dynamicOutputs`), not the node — Data Viz is out:vec3 + value:float, so node-level inference reported 3 for its scalar `value` socket and skipped the widen. `normal`/`position` are deliberately NOT widened: they never reach alpha, and widening `position` would break the Data Viz `value`→Displacement flow, where normal-mode displacement needs the height to stay scalar. Other alpha traps closed at the same time: `depthWrite:false` used to LATCH (its checkbox renders only while Transparent is on, so unchecking Transparent stranded it) and is now cleared on that transition AND gated on `transparent` at emission — on an opaque mesh it self-occludes into cutout-looking holes; `alphaTest` is coerced+clamped to ≤0.99 (three discards on `alpha <= alphaTest`, so 1.0 erases everything) and never interpolated raw from an untrusted project block. **Known follow-ups, not yet fixed** (see the alpha-hunt findings): `extractDiscards` scans raw text so a commented-out `Discard(` becomes live; a bare `Discard()` emits `__pixel(, …)` (SyntaxError); `const k = Discard(n)` leaves a dangling assignment; and material settings from the previous graph leak onto an imported plain `.js` script.
- **Scalar→vec3 widening on Output channels**: a 1-channel source wired to a vec3-typed channel (`color`, `emissive`, `normal`, `position`) is emitted as `vec3(ref)`, NOT bare. three's `NodeMaterial.setupDiffuseColor` does `vec4(this.colorNode)` and TSL splats a 1-channel node across all FOUR components, so a bare `mx_noise_float(...)` on Color silently became the ALPHA too (`diffuseColor.a = noise`) — the surface flickered/vanished as if Opacity or Discard were wired when neither was. Scalar-ness comes from `getNodeOutputShape` (cpuEvaluator), not the registry port type, so an `any`-typed arithmetic chain is caught as well. codeToGraph MUST mirror this: `unwrapScalarWiden` collapses a single-argument `vec3(<identifier|member>)` in a channel position back to a direct edge — unambiguous because a real Vec3 node always emits three arguments — or the round trip grows a Vec3 node with y/z = 0 and re-emits `vec3(x, 0, 0)`, turning a grey ramp red. Both sides are pinned (`graphToCode.test.ts` + a `roundTrip.test.ts` case). Vec3-shaped sources emit byte-identically to before.
- **Unknown nodes**: unrecognized TSL functions in code→graph parsing create `unknown` nodes that store `functionName` and `rawExpression` in values. These round-trip through graphToCode (emitted verbatim), render as magenta `vec3(1,0,1)` fallback in live preview, and show as orange warnings (not errors) in the code editor. The `unknown` definition lives in `NODE_REGISTRY` but is excluded from `allDefinitions` (hidden from content browser/search)
- **Preview geometries**: five options — `sphere`, `cube`, `plane` (primitives) and `teapot`, `bunny` (OBJ models in `public/models/`). `isObjGeometry()` in `tslToPreviewHTML.ts` is the single source of truth for primitive vs OBJ branching. The inline `fit-bounds` A-Frame component recomputes vertex normals (after merging vertex duplicates so per-vertex displacement doesn't split the surface), auto-detects inverted winding (the bunny is CW), generates spherical UVs from each vertex's direction so `uv()` reads cleanly on OBJ meshes, and rescales so the longest axis = 1.6 to match primitive framing. The source OBJs themselves are **pre-normalized** (bbox center at origin, longest axis exactly 1.6), so the runtime recenter/rescale is a no-op for them and `positionGeometry` ranges are comparable across all five geometries.
- **`fit-bounds` BAKES the normalization into the geometry attributes** (`FIT_BOUNDS_SCRIPT`, pinned by `previewFitBounds.test.ts`), and this is load-bearing rather than stylistic: `positionGeometry` is three's RAW position attribute, so scaling the Object3D — what this used to do — is completely invisible to the shader. A dropped model therefore fed its AUTHORED units to every position-driven preset, texture and noise-node default (all of which are tuned for the ±0.8 the pre-normalized built-in OBJs deliver), which is what shredded Vertex Wave on a 180-unit statue. The bake also has to be MEASURED in the entity's own frame — the old world-space `Box3.setFromObject` included `#preview-entity`'s resting tilt and `#spin-parent`'s live animation, so a model was scaled by its rotated hull (teapot ~19% undersized) and a dropped model's centring depended on the spin phase it happened to load at. Order matters: bake BEFORE `mergeByPosition` so its 1e-4 weld quantization is a fraction of the preview box rather than of authored units. Geometries are CLONED, never mutated (a glTF may reach one BufferGeometry from several nodes with different transforms), every local matrix in the subtree is then flattened to identity, mirrored transforms (negative determinant) get `flipWinding`, and skinned/instanced meshes deliberately fall back to the legacy Object3D path rather than desync their bind matrices. `public/podest.html` carries a hand-minified twin covered by NO sync plugin — `previewFitBounds.test.ts` runs both through the same assertions to catch drift.
- **World normals: `normalWorld`, not `normalLocal`, whenever a normal meets a world-space direction.** The preview nests the mesh under `#preview-entity` (a resting tilt — 45/45/0 on sphere and cube) inside `#spin-parent` (a full 360° turntable animation while playing, restored from persisted `fs:previewRotation` even when paused), so the object→world rotation is essentially never identity. `dot(normalLocal, worldViewDir)` evaluates to `dot(N_world, R·V)`: a correctly-shaped fresnel measured about a view direction rotated by the model, so the rim slides off the silhouette and — past ~78° with edge-glow's `pow(inv,3)*2` — clips to solid glow across the whole model. All four fresnel presets (edge-glow, hologram, force-field, stylized-water) and top-cover use `normalWorld`. **Displacement keeps `normalLocal`** (vertex-wave): object-space position displaced along an object-space normal is correct, and a world normal there would shear the model as it spins. Caveat worth knowing: in the fragment stage `normalWorld` resolves through the material's SHADED normal, so it reflects anything wired into the Output node's Normal channel — desirable for a fresnel, but a coupling `normalLocal` doesn't have.
