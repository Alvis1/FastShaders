## Testing

- Framework: **vitest** (configured in `vite.config.ts` so `@/*` alias + TS setup are inherited from the build config). Test files match `src/**/*.test.ts`; environment is `node` (no jsdom — tests target pure logic only).
- **The suite runs with `isolate: false`** (vite.config.ts), so every file in a worker SHARES that worker's module registry and globals. That halves the wall clock — a per-file worker re-imports the heavy engine graph (store → builtin textures/presets → codeToGraph → Babel) at ~350 ms a file — and with shared instances the first file a worker reaches decides who initialises the store's import cycle, which is what the costTable flake was really about (5–11 files failing differently every run while that cycle was live; `project-structure.md`, `costTable.ts`). The contract a new test must honour is therefore NOT "no global mocking" (that was never true of the whole suite; vite.config.ts's comment now points here): **every file that calls `vi.stubGlobal` (`grep -rl 'vi.stubGlobal(' src`) must restore it** (`src/stubGlobalRestore.test.ts` fails on one that does not) — `vi.unstubAllGlobals()` in an `afterEach`/`afterAll`, since a leaked stub lands on whatever file the worker runs next, and `unstubGlobals: true` in the vitest config would make that enforceable rather than aspirational. The second shared thing is the module registry: `registry/editorVisibility.test.ts` is the ONE file that calls `vi.doMock` (it has to — the shipped visibility JSON is EMPTY again since the Image node was unhidden on 2026-09-18, so every direct assertion would be vacuous), and it and `engine/unknownExpression.test.ts` (the validator's cold, parser-not-loaded state is module-scope) are the only TWO that call `vi.resetModules` — a `resetModules` clears the registry the setting exists to share. Keep store-mutating suites self-resetting in `beforeEach`, and the store's 300 ms autosave timer outlives the file that armed it: a suite that mutates the graph calls `cancelPendingGraphSave()` in its cleanup (`graphPersistence.test.ts` cancels on the way in and out). The third shared thing is the store's HISTORY FLAGS: `pushHistory` silently does nothing while `isUndoRedo` or `coalescingHistory` is up, the app's sync engine is what clears `isUndoRedo` after an undo (tests have none), and a gesture test can leave a bracket open — so a suite that undoes hands a silenced history to whichever file the worker runs next, and that file's "one undo entry" assertion fails at random (measured 2026-09-24 in `glbImportCommit.test.ts`: 1 run in ~6). Every suite that touches the undo history therefore spreads **`HISTORY_IDLE`** from `src/test-utils.ts` into its reset; `src/historyIdleReset.test.ts` fails on one that does not (a text check — it catches the forgotten reset, not every way around it) and pins that the object really does un-silence `pushHistory`.
- Shared test factories live in `src/test-utils.ts` (`makeNode`, `makeEdge`). Always import these instead of redefining stub builders in each test file — the helpers cast through `unknown as AppNode/AppEdge` to skip React Flow's full Node generic constraints. It also holds the KTX2 harness: `installInProcessWorker()` runs three's blob Workers (KTX2Loader, DRACOLoader) in `node:vm` — it stubs `Worker`, so its caller must `vi.unstubAllGlobals()`, and `stubGlobalRestore.test.ts` holds callers to that — plus `fakeRenderer()` (r184's `hasFeature` throws until `init()` resolves) and `makeKtx2Glb()`. It holds the ONE glTF/GLB fixture set, too (Phase 5): `makeGlb(doc | { jsonText }, bin?)` (the research doc's section 11 recipe: JSON padded 0x20, BIN padded 0x00; `{ jsonText }` goes in verbatim for fuzzing), `TRIANGLE_POSITIONS` + `gltfPrimitiveDoc(extra)` (asset, buffer 0, view 0, accessor 0; `extra` keys REPLACE the base's), the header-only image fixtures `pngHeaderBytes`/`jpegHeaderBytes` (an `app1Bytes` run can push the SOF past a scan window)/`webpHeaderBytes` (`VP8 `/`VP8L`/`VP8X`)/`ktx2HeaderBytes`, and `makeRealPng(w, h, rgba)`, a real decodable PNG (zlib `deflateSync` + `crc32`). `makeKtx2Glb` and `gltfTestFixtures.packGlb` build their containers through `makeGlb`, so the tree has one GLB layout; `glbFixtures.test.ts` proves every builder writes what it claims. Use these rather than a local `glb()` helper (the two in previewMesh.test.ts and projectImportZipLimits.test.ts predate them). Three r184's KTX2 test textures are committed under `src/engine/fixtures/ktx2/` (MIT, never edit) beside two GLBs from `scripts/gen-ktx2-fixture-glbs.mjs`; `ktx2Transcode.test.ts` runs the real basis transcoder over them, not a stub.
- **Every shaderloader suite gets its loader from `src/shaderloaderHarness.ts`** (a non-test module, imported only by tests). `ACTIVE_LOADERS` is `['0.6', '0.8']`: 0.6 is read from the SUBMODULE (the frozen file exports fetch; `loaderAvailable` skips it on a non-recursive checkout), 0.8 from its served `public/js` copy (vendorSync pins it to the submodule). The weld, per-mesh dispatch, schema, mesh-edge and transform suites run the SAME assertions against both, through `evalLoader` (the vm sandbox 0.6's suites always built, plus options for `AFRAME.components` / `AFRAME.THREE` stubs; by default the AFRAME stub carries a FRESH inert `gltf-model` from `inertGltfModelEntry`, because 0.8 warns when it cannot hook one and its agent-wide `Symbol.for` flag would leave a stub shared between sandboxes hookable only once) and `transformsOf` (0.6's top-level functions, or 0.8's `FastShaders.transforms`). `PINS` holds the few source anchors that necessarily moved between 0.6's object-literal component and 0.8's core functions (the dispatch slice, syncWeld→unbary, weld-before-bary); every other pinned literal is spelled identically in both files by construction, so do not add a row for one — make the 0.8 spelling match instead. Never read a loader at a suite's module top level: a copy that stops being vendored makes that read THROW, not skip. `shaderloader08Core.test.ts` covers what only 0.8 has — the core without A-Frame, against real three/webgpu inside vm, including the first end-to-end run of the component through the injectable `FastShaders.fetch`/`.importSource` (the default Blob-URL import cannot run in vm and is only source-pinned; it needs a browser).
- **Plain-JS helper text is executed through `src/lutHelperHarness.ts`** (2026-10-08; a non-test module, imported only by tests, never by the app). EVERY swap of `globalThis.THREE` in these suites goes through its `withRecordingThree(fn)`: real three/webgpu whose DataTexture records every instance (handed to `fn` too, for a loader sandbox's `THREE`), restored in `finally` — the `isolate: false` contract — and **SYNC-only**: a thenable from `fn` throws (after the restore), because an async `fn` would run its awaits after the restore, against whatever THREE the next file left. Four suites used to hand-copy the swap without that guard. `withHelpers(names, fn)` evaluates the `MODULE_HELPERS` text for `names` (their `requires` resolved) inside it; `bakeEditorModule(code)` runs a whole editor module and its shader body inside it. `tslTokenHits(text, allowed)` is a LINT, not the binding pin — it re-implements one loader regex and misses the real scan's quirks (its identifier regex backtracks onto call-name prefixes, `localDecls` ignores arrow parameters); the binding pin is `lutHelperLoaders.test.ts`, which runs the real `transformsOf(v)` for every `ACTIVE_LOADERS` version (read inside the test, never at module top level). `helperClosure(names)` lists the rows a set of names pulls in. A suite that runs a module BODY so a helper actually bakes in node calls `shader.shaderNode.jsFunc()` (`bakeEditorModule`, used by `colorRampExecution.test.ts` and `rgbCurvesNode.test.ts`): `shader()` alone only makes a call node, and three runs the body at build time, which needs a renderer.
- **A suite that pins a documented CLAIM reads `src/projectDocs.ts`, never `CLAUDE.md` directly** (2026-09-24; a non-test module imported only by tests, since it reads the filesystem). The corpus is CLAUDE.md plus every `docs/dev/*.md`, newline-joined and memoized per worker (`isolate: false`), so a guard keeps holding when a paragraph moves between the rule and its reasoning. A positive pin still fails when the claim is deleted anywhere; a NEGATIVE pin (a retracted claim that must not come back) covers every doc file. **Which suites depend on it is a search, never a number**: `grep -rl projectDocs src` (plain grep — `git grep` skips a suite nobody has added yet). CLAUDE.md once gave the count as nine while eleven depended on it (two suites added 2026-10-09 had not moved it). - **A hook whose correctness IS React's render semantics is MOUNTED, not reasoned about** (2026-10-09, `components/Preview/settledPreview.test.ts`, for `useColdRebuildKey`, whose first cut a review then broke on React's rebase of render-phase updates and on the order of passive effects): react-dom/client's `createRoot` on a stand-in container (`nodeType: 1`, `tagName`, `namespaceURI`, no-op listener methods, an `ownerDocument` with the same), the components rendering `null`, their inputs through `useSyncExternalStore` so a write renders at a zustand write's priority, every step inside React's own ASYNC `act` (the hook adopts in a microtask). A DISCRETE move is `flushSync` with `window.event` set until the microtasks it queued have run, as a browser dispatch leaves it: React reads the update priority off `window.event`, so without it the adoption renders at default priority and the rebase case the test exists for is never reached (the test asserts the second render pass that proves it was). Still the `node` env, no jsdom: React DOM's commit reads only `window.HTMLIFrameElement`, so the block stubs `window` (plus `location.href` when it also builds a preview document) and `IS_REACT_ACT_ENVIRONMENT`, and its `afterEach` restores both with `vi.unstubAllGlobals()`, and the real timers, BEFORE it fails on any `console.error` (React reports its own misuse there): a failing assertion skips whatever follows it, and under `isolate: false` the stubs would land on the next file. Async `act` drains React's queue on node's `setImmediate` (the CJS `timers` export, cached at its first use), which vitest 4.1's fake timers leave real, so `vi.useFakeTimers()` and `await act` mix; measured, not assumed. A rejected shape is mounted beside the real one, to prove each test can fail. StrictMode is one `createElement` away. `react-dom/server` cannot stand in for any of this: it renders once and runs no effects.
