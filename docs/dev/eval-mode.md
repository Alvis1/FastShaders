### Eval mode (`…/eval` — the user-study switch, `src/eval/` + `public/eval/index.html`)

- **Eval mode (`…/eval` — the user-study switch, `src/eval/` + `public/eval/index.html`)**: a research mode for the paper's SUS + telemetry study (design + references in `EVAL_MODE_PLAN.md`; deviations in its §7 are what shipped). The redirector arms a **sessionStorage** flag (`fs:evalArm`, sampled ONCE at module init — never localStorage, or the browser stays in eval mode forever) and drops the previous session record so every `/eval` visit re-runs consent; a mid-session reload of the APP url resumes instead. App-side: `EvalGate` (mounted in App.tsx behind `isEvalMode()`) shows the ConsentModal BEFORE any logging, and Agree adopts the participant code as the SHADER NAME (so the artifact inside the package is `shader/p01.js`, identifiable without opening the zip — set AFTER the clean slate, since `newGraph()` resets the name; an empty code keeps the default) and runs `cleanSlateForStudy()` — `newGraph()` alone is NOT a clean slate: the preview mesh (store + IndexedDB), `fs:previewUniformValues`/`Bounds` (persist BY NAME; auto-names collide, and both ride `buildShaderBundle()` into the study zip) and the undo history (newGraph's own entry = one Cmd+Z from the previous user's document) must all be cleared; `fs:savedGroups` deliberately survives (owner's library — study-machine hygiene is a researcher step). **Telemetry**: `evalLog(type, payload)` — no-op outside a session — called from a REVIEWED chokepoint set pinned by `evalHooks.test.ts` (store graph actions; NodeEditor's `applyConnection`/keydown-delete/`placeTilePayload`; CodeEditor's two Apply gestures — deliberately NOT `requestCodeSync`, which projectImport also calls, so imports would count as Applies; `downloadShader`). telemetry.ts must never import the store (the store imports IT — EvalGate registers a bridge for snapshots and the 250 ms-debounced `preview-rebuild`, since raw `previewCode` advances per scrub frame). Events sit on ONE monotonic clock: the journal persists a wall anchor (first page's `performance.timeOrigin`) and recovery REBASES new timestamps — without it a reload mixes two `performance.now()` epochs and every duration is garbage; recovery also re-logs current visibility/focus (a page that loads visible fires no `visibilitychange`, so the flushed pre-reload `hidden` would otherwise close presence forever), and blur INTO the app's own preview iframe is tagged `target:'iframe'` = still present. The journal is **sessionStorage** (`fs:evalJournal`) — a consent decision: it survives the reload recovery exists for, dies with the tab (the promised withdrawal), and stays out of the fs:graph localStorage quota. **The single-GLB export is never offered in a study session**: the EXPORT popover renders no Format row (the popover itself IS reachable there by right-click), `buildShaderExportChecked` returns the bundle path under `isEvalMode()` before any `.glb` call, the desktop Work folder neither lists nor opens a `.glb`, and SusModal keeps bare `buildShaderBundle()` — so the study zip is unchanged and `CONSENT_TEXT_VERSION` does not move. **EXPORT is the finish control and the action is SUBMIT** — in a study session it opens `EvalFinishModal` ("Are you finished?" → Continue working / Submit) rather than downloading a bare shader, because that is the button a participant reaches for when they think they are done; Submit opens the questionnaire and the ONE package is built at ITS submit, whose thank-you screen OFFERS the addressed email as a button, never opens it (sending from the participant's own client hands the researcher an identifying address, hence opt-in since consent-3; a mailto navigation is CSP-exempt, and the attachment is the one step mailto cannot do, hence the download first + the file named in the body) (the SUS answers belong inside it, and a second pre-questionnaire zip would give the researcher two files per participant that `eval-analysis.mjs` counts twice). The questionnaire opens with FOUR EXPERIENCE QUESTIONS (`background.ts` — Blender / Unreal / other node editors + free text / shader code, one none→expert 0–4 scale) BEFORE the SUS items: they are the covariate a usability score is read against, and asking them first keeps self-assessment from colouring the SUS. Scales required (they gate submit with the ten items), free text optional; they ride `sus.json`'s `background` block — one questionnaire, one file, so there is no new zip entry to disclose, but the sus.json disclosure line and `CONSENT_TEXT_VERSION` move together. The `!` button also opens `SusModal` instead of FeedbackModal (Brooke's original items, item-8 "awkward"; LV draft NOT yet back-translated; all 10 required; score computed into the package and shown NOWHERE the participant reads — including the mailto body); submit assembles the zip (`evalPackage.ts` — sus + raw events + derived summary + quality checks + `buildShaderBundle()` verbatim + README with formulas; `summary.csv` is formula-escaped, participant cell is typed input) → download + an OFFERED prefilled mailto to `EVAL_STUDY_EMAIL` (mailto can't attach) + the upload below, then `clearEvalMode()` — a post-submit reload must boot the NORMAL app, not re-record under the finished identity. **Delivery is THREE-WAY and the download is the floor**: the zip downloads at submit, the addressed mail is offered, AND (since 2026-08-29) the package POSTs to `EVAL_UPLOAD_URL`, the RELATIVE path `/fastshaders-eval/upload.php`, collected at `https://alvismisjuns.lv/fastshaders-eval/list.php` (HTTP-Basic). Relative means it resolves against the serving host, and only alvismisjuns has the endpoint: **from fs.sferas.lv, the study host, it 404s**, and from GitHub Pages it 405s. It is `'self'` under the CSP everywhere, so nothing is blocked; it simply reaches nothing, and both report `'failed'`. Pointing sferas at alvismisjuns needs CORS on upload.php for the OPTIONS preflight AND the POST, `https://alvismisjuns.lv` in the sferas build's `connect-src`, and an absolute URL. A package over `MAX_UPLOAD_BYTES` (64 MiB, the server template's `$MAX_BYTES`, pinned together in `evalUpload.test.ts`) is refused before any bytes ship and reported as `'too-large'` (decided synchronously by `precheckEvalUpload`, so no "Uploading…" frame). Its line names the size in MiB rounded UP (`formatMiB(…, 'up')`: a round-to-nearest formatter prints 64 beside "accepts up to 64 MB") and then gives the same hand-it-to-the-researcher instructions. `scripts/deploy-eval-endpoint.sh` renders the public `server/*.php` templates with secrets from the gitignored `.vscode/eval-endpoint.json`. The inbox MUST be the CONTAINER path `/app/eval-inbox-<token>` (the site is a Docker `php:8.5-apache` behind Traefik; host `/var/www/alvis/src` → `/app`, DocumentRoot `/app/public`) and MUST sit outside the docroot: measured, an inbox under it served stored packages by URL with no password, because `AllowOverride` is None there (so `.htaccess` is ignored) and Apache runs as the same `www-data` that owns the files (so 0700 is no barrier). Dev needs the serve-only `fs-public-entry-dev-index` vite plugin (SPA fallback otherwise swallows the `/eval/` directory URL that static hosts serve fine). **Three study entries**: `/eval`, **`/evalpro`** (adds `proQuestions.ts`'s professional block — role, years, shader frequency, GPU-budget pressure, platforms, would-you-use — between the experience questions and the SUS; opt-IN via `?pro=on` so an absent parameter never hands a student the block, and its scales gate submit while its free text never does; DRAFT content, one array to replace) and **`/evalp`** — the "pointless" no-cost-feedback arm, which forces `points=off` and removes EVERY point figure (cost bar, node badges, asset-tile badges, the Add-node menu's per-row cost, the shader-settings Total/Budget lines). Stronger than `?costbar=off` on purpose: that hides the total but leaves per-node prices to add up, so `pointsVisible` implies `costBarVisible`. Suppression is ONE CSS sweep on `:root[data-fs-points='off']` (stamped at boot by `applyEvalTaskFlags`) for the badges — a dozen components draw them — plus React gates for the two PROSE figures, where display:none would leave a blank row. DISPLAY ONLY: snapshots keep recording `costPoints` and the package keeps the cost table, or the arm where the participant cannot see the price could not be priced afterwards. Both entries need the serve-only `fs-public-entry-dev-index` plugin in dev (`PUBLIC_ENTRY_DIRS` — the three study arms; the `/textures` unlock that once sat beside them was replaced by the toolbar's optional-categories switch on 2026-09-04). Deployed to **fs.sferas.lv** via `npm run deploy:sferas` (base `/`, docroot `/var/www/fs/src` — NOT `/var/www/sferas/src`, which is a shared directory of unrelated projects). **Experiment identity (2026-08-29)**: `…/eval/?task=T7-fire&budget=200&costbar=off` — the redirector stows the query, `evalTask.ts` parses it once, and it reaches `session.json.task` + a `task-start` event; **`costbar=off` actually hides the CostBar** (the cost-feedback manipulation), and `briefBudget` is deliberately NOT the device budget. `session.json` also carries `costTable` (which price table valued the graph — a point total is meaningless without it) and `device` (cores/GPU/screen/prefs). `budget-crossed` events are edge-triggered from a store subscription, giving `overBudgetMs` for free. `preview.png` is captured at submit for blinded quality rating: the sandboxed stage cannot be read by the parent, so it is ASKED (`fs:shot`) and must re-render in the SAME task before `toDataURL` (no `preserveDrawingBuffer` = cleared at composite), with the reply magic-checked and every failure degrading to no image. The stage also posts throttled `fs:activity` pings, without which input inside the preview iframe is invisible to the parent and long shader inspection idles out of active time. Three SUS-integrity checks ship per package (`sus-in-one-sitting`, `no-edits-after-sus-open`, `response-pattern` — straight-lining always scores exactly 50) as FLAGS, never blocks. Pure/tested: `telemetryModel` (closed vocabulary, active time derived under a DECLARED 60 s idle threshold — recomputable from raw events, deliberately unclamped so the active≤wall quality check stays real; null-proto count maps), `susScore`, `evalPackage`, plus the `evalHooks` source pins. Analysis: `scripts/eval-analysis.mjs` (dependency-free) ingests the study zips → per-participant table + SUS mean/SD/95% t-CI/grade + CSV, recomputing each stored score from its raw items so a corrupt package fails loudly.
