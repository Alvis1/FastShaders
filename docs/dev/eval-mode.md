### Eval mode (`…/eval` — the user-study switch, `src/eval/` + `public/eval/index.html`)

- **Eval mode (`…/eval` — the user-study switch, `src/eval/` + `public/eval/index.html`)**: a research mode for the paper's SUS + telemetry study (design + references in `EVAL_MODE_PLAN.md`; deviations in its §7 are what shipped). The redirector arms a **sessionStorage** flag (`fs:evalArm`, sampled ONCE at module init — never localStorage, or the browser stays in eval mode forever) and drops the previous session record so every `/eval` visit re-runs consent; a mid-session reload of the APP url resumes instead. App-side: `EvalGate` (mounted in App.tsx behind `isEvalMode()`) shows the ConsentModal BEFORE any logging, and Agree adopts the participant code as the SHADER NAME (so the artifact inside the package is `shader/p01.js`, identifiable without opening the zip — set AFTER the clean slate, since `newGraph()` resets the name; an empty code keeps the default) and runs `cleanSlateForStudy()` — `newGraph()` alone is NOT a clean slate: the preview mesh (store + IndexedDB), `fs:previewUniformValues`/`Bounds` (persist BY NAME; auto-names collide, and both ride `buildShaderBundle()` into the study zip) and the undo history (newGraph's own entry = one Cmd+Z from the previous user's document) must all be cleared; `fs:savedGroups` deliberately survives (owner's library — study-machine hygiene is a researcher step). **Telemetry**: `evalLog(type, payload)` — no-op outside a session — called from a REVIEWED chokepoint set pinned by `evalHooks.test.ts` (store graph actions; NodeEditor's `applyConnection`/keydown-delete/`placeTilePayload`; CodeEditor's two Apply gestures — deliberately NOT `requestCodeSync`, which projectImport also calls, so imports would count as Applies; `downloadShader`). telemetry.ts must never import the store (the store imports IT — EvalGate registers a bridge for snapshots and the 250 ms-debounced `preview-rebuild`, since raw `previewCode` advances per scrub frame). Events sit on ONE monotonic clock: the journal persists a wall anchor (first page's `performance.timeOrigin`) and recovery REBASES new timestamps — without it a reload mixes two `performance.now()` epochs and every duration is garbage; recovery also re-logs current visibility/focus (a page that loads visible fires no `visibilitychange`, so the flushed pre-reload `hidden` would otherwise close presence forever), and blur INTO the app's own preview iframe is tagged `target:'iframe'` = still present. The journal is **sessionStorage** (`fs:evalJournal`) — a consent decision: it survives the reload recovery exists for, dies with the tab (the promised withdrawal), and stays out of the fs:graph localStorage quota. **The single-GLB export is never offered in a study session**: EXPORT there opens the finish dialog, `exportFormatFor` answers the bundle for every surface, and the popover renders no smaller export button — only the "Export model" checkbox (the popover itself IS reachable there by right-click), `buildShaderExportChecked` returns the bundle path under `isEvalMode()` before any `.glb` call, the desktop Work folder neither lists nor opens a `.glb`, and SusModal keeps bare `buildShaderBundle()` — so the study zip is unchanged and `CONSENT_TEXT_VERSION` does not move. **EXPORT is the finish control and the action is SUBMIT** — in a study session it opens `EvalFinishModal` ("Are you finished?" → Continue working / Submit) rather than downloading a bare shader, because that is the button a participant reaches for when they think they are done; Submit opens the questionnaire and the ONE package is built at ITS submit, whose thank-you screen OFFERS the addressed email as a button, never opens it (sending from the participant's own client hands the researcher an identifying address, hence opt-in since consent-3; a mailto navigation is CSP-exempt, and the attachment is the one step mailto cannot do, hence the download first + the file named in the body) (the SUS answers belong inside it, and a second pre-questionnaire zip would give the researcher two files per participant that `eval-analysis.mjs` counts twice). **No study dialog closes on a click outside it** (2026-10-02, pinned by `evalDialogs.test.ts`): the consent never did, and now neither do its Details, the finish dialog, the questionnaire or the thank-you screen — they close only through their own buttons, plus Escape where it has a safe answer. The questionnaire is long and scrolls, so a scrollbar drag or a text selection released past the panel's edge delivers its `click` to the backdrop: with a close handler there the form vanished mid-answer, and on the thank-you screen the Download and email buttons went with it. **Every study dialog goes through ONE helper, `useStudyDialog` (`src/eval/studyDialog.ts`; same test), which makes the app behind it INERT and swallows every key but Tab in the window capture phase.** Inert first (`#root.inert`, ref-counted — the dialogs are portals on `document.body`, outside it): swallowing keys alone left focus free to LEAVE the panel, and Tab from the consent walked to EXPORT behind it, where Enter opened the questionnaire before Agree and produced a package with no consent record that was downloaded AND uploaded; Shift+Tab from the questionnaire reached Monaco, where typing changed the packaged shader with nothing logged; Tab reached the canvas nodes, where the arrows moved them. The consent also makes its own panel inert while its Details dialog is open (Details is a later portal, so Shift+Tab from it landed on the hidden "I agree", and Enter recorded consent), and Submit refuses outright without `isEvalSessionActive()`, so no path can package a session that never consented. Then the keys: the canvas and the code panel bind Delete/Backspace/X/A, ⌘Z and ⌘S on `window`, so a Backspace on a focused radio deleted the selected nodes behind the questionnaire, ⌘Z in the comment box undid a graph edit, ⌘S logged a code Apply, and — once a click outside stopped closing the dialog and left focus on the page — typing "a", "x" selected and deleted the whole graph. Each was logged after `sus-open`, so `no-edits-after-sus-open` failed and the package carried a different shader than the one rated. Typing, radio arrows and the textarea's own undo are default actions and keep working; ⌘S alone is prevented, because the code panel's handler that used to prevent it no longer sees it and the browser's Save Page dialog opened over the study instead. Telemetry's own window-capture activity listener is registered at Agree, so it still runs first; so is `useKeyboardNav`'s (it mounts with the canvas), which is why that hook ALSO stands down while any `aria-modal` dialog is open, not only when the key's target is inside one — a click outside a study dialog leaves focus on the page, where Alt+Arrow walked it to a pane and the arrows moved a node behind the questionnaire. TooltipLayer listens on window capture too, registered at boot, so Escape still dismisses a tooltip on the consent; and it no longer writes a stashed `title` back over a newer one React set while the tooltip showed (the EN/LV button kept naming the language it had just left). It must be WINDOW capture: the consent swallows there, and its Details dialog registers later on the same target, so it still sees Escape (a document-capture listener never would). Details also focuses Close ONCE on open — keyed on the consent's inline `onClose`, every language switch used to move focus there, so a second Enter closed it. From Submit to the thank-you screen the questionnaire is BUSY: Escape and "Back to the editor" do nothing, every answer control and its EN/LV button are disabled, and a "Packing…" line shows, because the preview capture can take 4 s with nothing changing on screen. Dismissing the form then hid it while the submission finished unseen (no thank-you screen, no upload status, no Email button), and a change made then was dropped from the answers while its language note was read after the wait, so an all-English form could come out `mixed`; the answers AND their languages are now both taken at the click. The questionnaire opens with THREE EXPERIENCE QUESTIONS (`background.ts` — Blender / Unreal / shader programming, one none→expert 0–4 scale) BEFORE the SUS items: they are the covariate a usability score is read against, and asking them first keeps self-assessment from colouring the SUS. Before consent-9 there were four — a third asked about "other node-based editors" with a free-text "Which software?" box — and the owner REMOVED it on 2026-10-02 (the shader-knowledge question was already the fourth item and is now the third); the retired id `otherNodeEditors` must never be reused, since older packages carry it (`eval-analysis.mjs` keeps it in its CSV, never its table, and `summary.csv`'s `exp_*` columns follow `BACKGROUND_ITEMS`). Scales required (they gate submit with the ten items); they ride `sus.json`'s `background` block — one questionnaire, one file, so there is no new zip entry to disclose, but the sus.json disclosure line and `CONSENT_TEXT_VERSION` move together. The `!` button also opens `SusModal` instead of FeedbackModal (Brooke's original items, item-8 "awkward"; LV draft NOT yet back-translated; all 10 required; score computed into the package and shown NOWHERE the participant reads — including the mailto body); submit assembles the zip (`evalPackage.ts` — sus + raw events + derived summary + quality checks + `buildShaderBundle()` verbatim + README with formulas; `summary.csv` is formula-escaped, participant cell is typed input) → download + an OFFERED prefilled mailto to `EVAL_STUDY_EMAIL` (mailto can't attach) + the upload below, then `clearEvalMode()` — a post-submit reload must boot the NORMAL app, not re-record under the finished identity. **Delivery is THREE-WAY and the download is the floor**: the zip downloads at submit, the addressed mail is offered, AND (since 2026-08-29) the package POSTs to `EVAL_UPLOAD_URL`, collected at `https://alvismisjuns.lv/fastshaders-eval/list.php` (HTTP-Basic). The URL is decided per BUILD. The default is the RELATIVE path `/fastshaders-eval/upload.php`, which resolves against the serving host and is `'self'` under every CSP: alvismisjuns (apex and www) has the endpoint, GitHub Pages answers 405 and reports `'failed'`. **fs.sferas.lv, the study host, is a static nginx container with no endpoint**, so there the relative URL 404ed and every study package read "Upload failed." until the owner reported it on 2026-10-02. Its build now sets `FS_EVAL_UPLOAD_URL` to alvismisjuns's ABSOLUTE endpoint (`scripts/deploy-sferas.sh`); `vite.config.ts` validates the value (root-relative or https, so a typo fails the build rather than every upload), hands it to `evalUpload.ts` as the `__FS_EVAL_UPLOAD_URL__` define and adds its origin to that build's `connect-src`; and upload.php answers CORS for exactly `https://fs.sferas.lv` (`$ALLOWED_ORIGINS`, an exact-match allowlist, never `*`) on the OPTIONS preflight AND on every POST response, refusals included. Both halves are required: the request is not "simple" (the `X-FS-Eval-*` headers, an `application/zip` body), so the preflight comes first, and without the POST's Allow-Origin the browser hides the answer from `fetch()` — the package is STORED while the participant reads "Upload failed.". `evalUpload.test.ts` pins that every header the client sends is in `Access-Control-Allow-Headers` (a missing one fails only cross-origin, i.e. only on the study host). Both deploy scripts judge the LIVE preflight the way a browser does — a 2xx status, the study origin echoed back, and every header the client sends allowed, asked for as the template lists them (which the suite pins ⊇ the client) — because Allow-Origin alone passed a 405 that still carried it, or an Allow-Headers list one header short, either of which Chrome rejects. `deploy-sferas.sh` runs that check BEFORE it builds or uploads anything, so an endpoint that lags stops the deploy with the study host untouched (deploy the endpoint first), and after the upload it fails when the served CSP lacks the endpoint's origin; `deploy-eval-endpoint.sh` reads the template's header list before it uploads, then checks the preflight and that a foreign origin gets none. The endpoint is NOT part of the ordinary deploy: a template change goes live only through `bash scripts/deploy-eval-endpoint.sh`, and the sferas gate notices only a lagging CORS answer — any other template change (`$MAX_BYTES`, the name pattern, the key) must be deployed by hand. A package over `MAX_UPLOAD_BYTES` (64 MiB, the server template's `$MAX_BYTES`, pinned together in `evalUpload.test.ts`) is refused before any bytes ship and reported as `'too-large'` (decided synchronously by `precheckEvalUpload`, so no "Uploading…" frame). Its line names the size in MiB rounded UP (`formatMiB(…, 'up')`: a round-to-nearest formatter prints 64 beside "accepts up to 64 MB") and then gives the same hand-it-to-the-researcher instructions. `scripts/deploy-eval-endpoint.sh` renders the public `server/*.php` templates with secrets from the gitignored `.vscode/eval-endpoint.json`. The inbox MUST be the CONTAINER path `/app/eval-inbox-<token>` (the site is a Docker `php:8.5-apache` behind Traefik; host `/var/www/alvis/src` → `/app`, DocumentRoot `/app/public`) and MUST sit outside the docroot: measured, an inbox under it served stored packages by URL with no password, because `AllowOverride` is None there (so `.htaccess` is ignored) and Apache runs as the same `www-data` that owns the files (so 0700 is no barrier). Dev needs the serve-only `fs-public-entry-dev-index` vite plugin (SPA fallback otherwise swallows the `/eval/` directory URL that static hosts serve fine). **Three study entries**: `/eval`, **`/evalpro`** (adds `proQuestions.ts`'s professional block — role, years, shader frequency, GPU-budget pressure, platforms, would-you-use — between the experience questions and the SUS; opt-IN via `?pro=on` so an absent parameter never hands a student the block, and its scales gate submit while its free text never does; DRAFT content, one array to replace) and **`/evalp`** — the "pointless" no-cost-feedback arm, which forces `points=off` and removes EVERY point figure (cost bar, node badges, asset-tile badges, the Add-node menu's per-row cost, the shader-settings Total/Budget lines). Stronger than `?costbar=off` on purpose: that hides the total but leaves per-node prices to add up, so `pointsVisible` implies `costBarVisible`. Suppression is ONE CSS sweep on `:root[data-fs-points='off']` (stamped at boot by `applyEvalTaskFlags`) for the badges — a dozen components draw them — plus React gates for the two PROSE figures, where display:none would leave a blank row. DISPLAY ONLY: snapshots keep recording `costPoints` and the package keeps the cost table, or the arm where the participant cannot see the price could not be priced afterwards. Both entries need the serve-only `fs-public-entry-dev-index` plugin in dev (`PUBLIC_ENTRY_DIRS` — the three study arms; the `/textures` unlock that once sat beside them was replaced by the toolbar's optional-categories switch on 2026-09-04). Deployed to **fs.sferas.lv** via `npm run deploy:sferas` (base `/`, docroot `/var/www/fs/src` — NOT `/var/www/sferas/src`, which is a shared directory of unrelated projects). **Experiment identity (2026-08-29)**: `…/eval/?task=T7-fire&budget=200&costbar=off` — the redirector stows the query, `evalTask.ts` parses it once, and it reaches `session.json.task` + a `task-start` event; **`costbar=off` actually hides the CostBar** (the cost-feedback manipulation), and `briefBudget` is deliberately NOT the device budget. `session.json` also carries `costTable` (which price table valued the graph — a point total is meaningless without it) and `device` (cores/GPU/screen/prefs). `budget-crossed` events are edge-triggered from a store subscription, giving `overBudgetMs` for free. **Language (2026-09-28, consent-8)**: `session-start` (and `recovered`) carry the UI `language` the session began in, and every switch between Agree and Submit logs `lang-switch {from, to}` from the ONE chokepoint, the store's `setLanguage` (the toolbar calls it, and every study dialog — the consent, its Details, the finish dialog, the questionnaire and its thank-you screen — does through the ONE `src/eval/LangSwitch.tsx` button, since each is modal and the toolbar's is out of reach; a switch before Agree logs nothing, as no session runs yet, and neither does one on the thank-you screen, since Submit has already ended the session and built the package). The time is the event's `t` — wall time is `t` plus session.json's anchor, like every other event. `sus.json`'s `language` is the language the SUS was ANSWERED in (2026-10-02): the questionnaire now carries its own switch, so one form can be answered partly in each language (answers are indices and survive a switch), and the language at Submit would then pass English ratings off as the Latvian adaptation or the reverse. SusModal notes the UI language at every SUS radio's onChange; each item records its own `language` and its statement in that language, the form's `language` is that language or `'mixed'` when the answers span both (`answerLanguage.ts`), and `languageAtSubmit` is the UI language when Submit was pressed. `eval-analysis.mjs` reports `mixed` as its own bucket with a PROBLEMS line, and an older package (no per-item languages) whose language changed between the FIRST `sus-open` after the last reload and `sus-submit` as `lv?`/`en?` — answers survive closing and reopening the form, so the window starts at the first opening, but not a reload (they live in React state only), so a switch before one does not count. The email draft's one line for the participant is built at render, so it follows a switch on the thank-you screen; and `env.language` is the BROWSER's locale, not the app's. `preview.png` is captured at submit for blinded quality rating: the sandboxed stage cannot be read by the parent, so it is ASKED (`fs:shot`) and must re-render in the SAME task before `toDataURL` (no `preserveDrawingBuffer` = cleared at composite), with the reply magic-checked and every failure degrading to no image. The stage also posts throttled `fs:activity` pings, without which input inside the preview iframe is invisible to the parent and long shader inspection idles out of active time. Three SUS-integrity checks ship per package (`sus-in-one-sitting`, `no-edits-after-sus-open`, `response-pattern` — straight-lining always scores exactly 50) as FLAGS, never blocks. Pure/tested: `telemetryModel` (closed vocabulary — ONE `as const` tuple from which both the `EvalEventType` type and the journal sanitizer's allow-set derive, so adding an event is one edit and a type-only addition cannot be dropped on journal recovery; active time derived under a DECLARED 60 s idle threshold — recomputable from raw events, deliberately unclamped so the active≤wall quality check stays real; null-proto count maps), `susScore`, `evalPackage`, plus the `evalHooks` source pins. Analysis: `scripts/eval-analysis.mjs` (dependency-free) ingests the study zips → per-participant table + SUS mean/SD/95% t-CI/grade + CSV, recomputing each stored score from its raw items so a corrupt package fails loudly.


### Consent text versions (`CONSENT_TEXT_VERSION`)

- **Consent text versions (`CONSENT_TEXT_VERSION`, `src/eval/evalMode.ts`)**: the tag is recorded with the consent act, so a package says which wording its participant agreed to. **Bump it whenever the text changes materially**; `evalDisclosure.test.ts` pins only the `consent-<n>` format and that it is not `consent-2`. **consent-2** added the automatic transfer to the study server (delivery option B going live). **consent-3** corrected the collection description, which had drifted badly behind the code: the dialog promised "browser and platform version, screen size, and time zone" and closed with "Nothing else is recorded", while the package had grown a 14-field device block (unmasked GPU renderer, core count, deviceMemory — a recognised fingerprinting triple), a `preview.png` of the participant's work, a free-text comment box, and a shader bundle carrying note text, typed property names and any dropped image or 3D model INCLUDING its file name; it also stopped calling the researcher's own host "the university's server" and made the outgoing email opt-in instead of automatic. **consent-7** (2026-09-10) tightened every sentence, aligned the Latvian on the app's own term ("ēnotājs", not "šeideris") and dropped two things from the consent SUMMARY by owner decision — the "not by the university" contrast and the sentence about the optional email revealing the sender address (the disclosure and the thank-you screen still state the latter, once each, beside the button). **consent-8** (2026-09-28) added "language switches" to the disclosed event list when `lang-switch` joined the vocabulary. **consent-9** (2026-10-02) rewrote the `sus.json` disclosure line from "the four experience answers and any software you name" to "the three experience answers", when the "other node-based editors" question and its free-text box were removed — the package now collects LESS, and the disclosure has to say so.

### Gaussian splats in a study session (2026-09-25)

- **Gaussian splats in a study session (2026-09-25)** — a splat FILE is refused on every study entry path: the drop (before the pre-read gate, so no bytes are read), a zip's model entry (`zipModelOutcome`) and the IndexedDB boot restore — so a study document never loads `fs-splat-0.1.js` and the study host never serves it. The Splat Output NODE, however, is offered on the Output tab in study sessions too: the owner chose "always offered" on 2026-09-24 knowing it adds a tile to every participant's palette. With no splat allowed it cannot render, and the preview's notice says why. Nothing new is logged (the `output-activate` chokepoint simply carries `splatOutput` as its node type) and `evalHooks.test.ts` is unchanged.
