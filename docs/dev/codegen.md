### A-Frame pipeline

- **A-Frame pipeline**: graphToCode → tslToShaderModule → shaderloader 0.8 (runtime TDZ fix + auto-import injection + typed `export const schema` parsing — `number`/`color`/`map` — plus per-sub-mesh materials via an additive `parts` return key) → dynamic blob import. (The old standalone `.html` export left with the A-Frame tab — the `.js` download is the only export.) **0.4, 0.5 and 0.6 are FROZEN**: shaders exported against them reference them from the jsdelivr CDN by URL, so editing any of them would ship retroactively to already-shipped artwork (`frozenLoaders.test.ts` pins their hashes) — new loader work goes in 0.8, additively. Every NEW export references 0.8 unconditionally (`LOADER_FILE` in tslToShaderModule.ts), and every surface that runs a module loads it (the preview and its XR popup, the A-Frame tab, podest's stage and VR popup), because a conditional would leave the editor previewing on one loader while the downloaded file runs another — and since 0.8 carries what 0.6 lacks (the FastShaders core, the glTF plugin, `materialParts`), the pin is correctness, not only parity. **Three things every module carries since the switch, all MODULE-only** (`buildShaderModule`, so graphToCode, the code panel and the byte-stability snapshots never move; `moduleBaseline.test.ts` pins the module bytes): `export const threeRevision = '<rev>'` right after the imports (the number comes from the leaf `engine/threeRevision.ts`; 0.8 warns on a mismatch with the page, older loaders ignore it, and `extractFnBody` drops a pasted copy, since two such exports are a SyntaxError); `import * as THREE from 'three/webgpu'` whenever a baked texture spells `globalThis.THREE` in CODE position (rewritten to `THREE` over `maskNonCode`, so strings and comments are untouched, and skipped outright when the code already binds `THREE`); and a `three/tsl` import COMPLETED with every TSL function the code calls but neither imports nor declares, appended sorted so an existing import line never reorders, checked against `engine/tslExportNames.ts` (GENERATED by `scripts/gen-tsl-exports.mjs`; `tslExportNames.test.ts` fails on a three bump until it is re-run, and `moduleImports.test.ts` pins that no module-helper name is a three/tsl export, since that would be a module-scope redeclaration). The last two make a module import standalone on plain three.js; on either loader `globalizeBareImports` turns the namespace import back into the global, so nothing changes at run time (`moduleImports.test.ts`). A bumped `LOADER_FILE` is only real once the submodule is PUSHED and jsdelivr is purged for the new file — otherwise every export 404s for its recipient while working perfectly for the author. A FastShaders GLB carries its module in root `extras.fastshaders.module`; `shader="src: model"` (or `FastShaders.applyFromGltf`) is the ONLY way it runs — see the GLB-module bullet. Loader 0.8 additionally wraps `AFRAME.components['gltf-model'].Component.prototype.init` once to register its glTF plugin, so its `<script>` must follow the A-Frame bundle and precede the scene on every document (it does: tslToPreviewHTML's head script vs the scene-slot injection, and podest's two documents); `shaderloaderGltfPlugin.test.ts` pins the bundle's gltf-model shape the hook depends on.

### Emitted order is `emitOrder`, and it may NEVER be derived from the nodes array

- **Emitted order is `emitOrder`, and it may NEVER be derived from the nodes array** (`emitRank` in `engine/materialPartsContract.ts`, a zero-import leaf; `outputsInEmitOrder` in `utils/outputMaterials.ts`). One Output node is one material, so the order its `parts` / `materialParts` entry takes in the module has to come from somewhere — and the nodes ARRAY is not a usable order and never can be: `liftChildrenAfterParents` splices a node into a new slot on an ordinary drag-into-a-group, and `useSyncEngine` reorders on every Apply. Deriving emitted order from it would rewrite the module on a LAYOUT GESTURE — `previewCode` advances, the 3D preview recompiles, the autosave dirties, `__partPixel<n>` renumbers, and first-claim-wins flips on a duplicate mesh name — all with `errors: []` and nothing on screen to explain it. So every Output carries an explicit integer `emitOrder`, read through ONE strict accessor. **`emitRank` returns the integer ONLY, and anything else is 0**, so a `.fastshader` claiming `"3"`, `3.5`, `NaN` or an object cannot reorder anything. **The node-id tie-break belongs at the SORT, never in the accessor**: a rank is NOT unique — `unfoldOutputMaterials` seeds every node it makes from its old material index, so two folded Outputs unfolded in one document each produce a node 0 carrying `emitOrder: 0` — and `Array.prototype.sort` is stable, so without the tie-break those two fall back to array order, which is the very thing the rank replaces. `outputsInEmitOrder` is that sort (`(emitRank, id)`, duplicate ids dropped first-wins, since a plan keyed by node id cannot say anything sensible about two nodes claiming one and React Flow cannot render them either), and every cross-node plan walks it rather than whatever array the caller happened to hold. The rank has exactly THREE writers: the unfold seeds it from the old material index (node 0 → 0, `materials[k]` → k+1), `codeToGraph` from the parse's own MINT position, and `gltfSectionBuilder` as it builds. An Apply keeps the PARSE's rank rather than the old node's, because `mergeMatch` spreads the parsed node's data — which is right: the rank describes the MODULE's order, and the module is what was just parsed. **No restore path sanitizes the key, and none needs to**: `emitRank`'s strictness IS the validation and it is applied at every read, so a junk value can sit in `data` forever without ever reaching a sort. **An ABSENT rank reads as 0**, which is what keeps every document that has never been split emitting byte-identically — every rank is 0, ties keep array order, and the order is exactly what it always was. The accessor lives in a zero-import LEAF because `activeSink` (utils/sdfPartition.ts) has to elect the LOWEST-RANKED untargeted Output — the same node `defaultOutput` picks, or the two name different nodes on a split document whose empty material was reordered ahead of the real default — and sdfPartition is a leaf nothing in the store cycle may drag `outputMaterials` into (the costTable TDZ rule); a SECOND copy of the accessor is precisely what this rule forbids. `materialParts` needs no rank of its own: an index is claimed once, so ascending glTF index is already a total order — the node rank there decides only WHICH node wins a duplicate index.

### `toHsl` (RGB to HSL) exposes h/s/l as SWIZZLES of one emitted call, and `out` stays `outputs[0]`.

- **`toHsl` (RGB to HSL) exposes h/s/l as SWIZZLES of one emitted call, and `out` stays `outputs[0]`.** The node has four outputs: the vec3 `out` plus float `h`/`s`/`l`. Codegen emits ONE `const toHsl1 = toHsl(rgb);` and `resolveEdgeRef` maps h/s/l → `.x/.y/.z` of that variable — never three calls, which would inline the helper Fn three times (~2.5× the GLSL, measured through GLSLNodeBuilder) and make `complexity.json`'s flat `"toHsl": 15` a lie. `codeToGraph.resolveMemberExpr` carries the INVERSE map so `toHsl1.x` parses back to the `h` handle: without it every member expression mints a **Split node**, so each Apply would splice one between toHsl and its consumers and the graph would grow without bound — while the code text and the rendered picture stayed correct, which is why the test asserts a zero split-node count rather than relying on byte-equality. `TOHSL_HANDLE_TO_COMPONENT`/`TOHSL_COMPONENT_TO_HANDLE` (graphToCode) are a drift pair — swapping one direction silently exchanges S and L across a round trip. **`out` is deliberately NOT replaced by the three sockets**: it is the defensive default the codebase assumes everywhere (`?? 'out'`, `outputs.find(id === 'out') ?? outputs[0]`, the designer's literal `sockets['out']` key, `tryInsertOnEdge`'s `def.outputs[0]`), and a removed handle has no migration path — `applyProjectToStore` runs none of `loadGraph`'s migrations and codeToGraph re-creates `'out'` on every Apply, so a shared `.js` would carry a dead handle forever. React Flow renders such an edge as NOTHING while keeping it in the store and still emitting its code: it fails silently, with the picture intact. h/s/l are `float` (not `any`) so the Output-channel scalar→vec3 widening fires.

### Edge VALUES are read per SOURCE SOCKET, not per node

- **Edge VALUES are read per SOURCE SOCKET, not per node** (`cpuEvaluator`: `handleChannels` over `handleSlice` + `evaluateEdgeSource`/`evaluateEdgeRange`/`getEdgeOutputShape`). `evaluate` stays keyed by node id and returns the whole vector; the socket is applied at the CONSUMER. That split is load-bearing: `evaluate`/`computeRange` write a null sentinel under the node id BEFORE recursing (their cycle guards), so a per-handle cache key would give a cycle re-entering the same node through a different socket its own sentinel and it would recurse until the stack blows — reachable from a hand-edited `.fastshader`, since `topologicalSort` only warns. Handle-blindness was harmless until `toHsl` because no node returned different numbers per socket (split/dataNode/dataviz evaluate to null, a mic channel is a uniform 0), so a wrong socket degraded to an honest `…`; with three real values it would print Hue in live blue beside a Saturation wire. `portShapeForHandle` is the ONE per-handle port lookup, shared by codegen's `shapeOfEdgeSource` and the visual layer — necessary even for declared floats, because `computeShape` resolves `outputs.find(id === 'out') ?? outputs[0]` and would report the vec3 width for every socket of a node that has an `out` port (the live Data Viz `value` bug). **Every cheap-string memo key that folds `e.source` must also fold `e.sourceHandle`** (ShaderNode's `edgeKey` + its `bySource` map, Mic/Output/Clock keys, PreviewNode's `inputsKey`, MathPreviewNode's `xKey`, LiveEdgeValue's rAF deps, EdgeInfoCard's effect deps): re-wiring between two sockets of the SAME source leaves source/target/targetHandle identical, so `Object.is` bails and the surface shows the old channel forever. `TypedEdge` must read the handle off the UNWRAPPED edge, never React Flow's `sourceHandleId` prop — `unwrapCollapsedGroupEdges` rewrites the handle too, and a collapsed group's synthetic socket id matches no registry port, so the projection would fall back to the whole vector and draw a plausible, wrong-width ribbon. `preferRange` is decided on the SOURCE NODE before any projection (see the sampled-field bullet), and a noise range is PROJECTED, never re-derived. `computeShape`'s default broadcast reads the per-handle width too (`portShapeForHandle`, the append branch's rule). It used the node-level width, so `toHsl.h → mul → Color` counted 3, skipped the Output's `vec3()` widen and splatted the float into alpha: the alpha-bleed bug by a third route. `engine/socketWidthPins.test.ts` pins the widened emission (`vec3(mul1)`) for `toHsl.h` and dataviz `value`. **The Texture (Image) node needs a RUN, not an index**: its whole vector is the rgba SAMPLE (`analyticalRange` [0,1]⁴, which also makes it a FIELD), so `out` — and a null or tampered handle — projects channels [0,3) and Alpha/R/G/B one each (`utils/imageChannels.ts` is the ONE socket table, a Map-only LEAF; `IMAGE_CHANNEL_INDEX` must equal `'rgba'.indexOf` of the emitted swizzle, pinned). `handleChannels` is the projection every internal consumer uses; `handleSlice` survives for single-channel callers and is unchanged. A 4-wide `out` would make EdgeInfoCard (count = max(rangeLen, shapeLen)) draw four channel cards on a vec3 wire. No CPU VALUE is ever claimed for an image — its pixels decode asynchronously in the DOM from an adversarial payload — so every socket evaluates to null and only the bound is shown (`engine/imageChannelSpans.test.ts`).

### A SAMPLED FIELD's value is not its range, and that has to survive every operator below it

- **A SAMPLED FIELD's value is not its range, and that has to survive every operator below it** (`analyticalRange` + `getFieldUpstreamSet` in `cpuEvaluator`, `preferRange` in `edgeValueLabel`). `uv`, `screenUV`, the geometry attributes and the whole noise family vary across the surface, so `evaluate` returns ONE arbitrary sample of them — the uv centre, or the integer lattice where Perlin is exactly 0. `computeRange` special-cases each with an analytical interval, but then took a finite deterministic eval as a degenerate range for everything DOWNSTREAM, which collapsed the whole chain: a `mul` between a `0…1` gradient and a `-1…1` noise reported a flat `0.00` sitting between two inputs that each read as a range, and the same `0` then propagated through clamp, mul and add to the Output. Reported from the canvas as "the value range goes in and comes out 0, although it is visible that it is not just zero". The block comment above that section had always CLAIMED interval arithmetic carried those chains; it never ran, because `evaluate` learned to sample noise on the CPU after the shortcut was written and short-circuited it from then on. **The gate is one predicate used twice**: `analyticalRange(node)` is the single table of field types (returning their bounds), and `getFieldUpstreamSet` seeds a memoized forward BFS from `!== null` — so a field added to the table is a seed by construction and cannot be forgotten. Three consequences. The deterministic shortcut still runs for every field-FREE chain, so constants keep their exact degenerate range (`2 × 5` is `10`, not a widened interval). Interval arithmetic is an over-approximation, so a long chain reports a BOUND rather than the true span (the dependency problem — `x - x` is not 0 to an interval); that is the honest trade against a number that is simply wrong. And the ops that had no interval rule became reachable for the first time, so `exp`/`log2`/`pow`/`mod`/`dot`/`hsl`/`toHsl` gained one and `length`/`distance` lost their flat `[0, Infinity]` — without those, `pow(oneMinus(dot(…)), k)` (all four fresnel presets) would have gone from a wrong number to a bare `…`. MEASURED across all 32 built-ins: 184 of 858 edge labels change, **zero** lose information, and 22 that read `…` now report a real bound. `edgeValueLabel` asks the same set, so the node ROWS and the wire CHIPS agree — they disagreed before, which is what made the defect visible. A sampled IMAGE (`imageNode`) is a field too, seeded at [0,1]⁴ (GLB Phase 4): an Image-fed label reads `0…1` where it read `…`, and everything below an image takes the interval path instead of `portRange`'s `[0,1]` guess for an unknown upstream.

### Every input port needs a registry `defaultValues` entry unless 0 is genuinely its neutral value.

- **Every input port needs a registry `defaultValues` entry unless 0 is genuinely its neutral value.** `resolveArguments` (graphToCode) resolves an unwired port as stored value → `def.defaultValues[id]` → `chainIdentity` (chainable only) → the bare string `'0'`. That last fallback is silent and was wrong for six nodes: `clamp(x, 0, 0)` pinned the output to a constant, `remap(x, 0, 0, 0, 0)` divided by zero, `hsl(0, 0, 0)` rendered BLACK beside a card showing red (saturation 0 and lightness 0 each annihilate independently, so wiring a hue ramp — the node's whole purpose — still rendered black), `mix(0, 0, 0)` discarded a wired B, and `log2(0)`/`smoothstep(0, 0, x)` are hard **WGSL/Tint compile errors** that kill the entire module on the WebGPU preview path while GLSL merely degrades to undefined behaviour (which is why the damage looked machine-specific). All six now declare identities that MATCH `cpuEvaluator`'s own per-port fallbacks — the evaluator's numbers were right all along and the registry simply never declared them. Two guards enforce it now: `engine/unwiredDefaults.test.ts` snapshots what every node emits unwired and asserts the RULES (log2's argument is never 0, smoothstep's edges differ, clamp's min ≠ max…), and `registry/builtinByteStability.test.ts` pins the emitted code of all 32 built-in textures/presets (8 + 24 — its own floor assertion is still the `>= 23` of the 15-preset era, so it would not notice nine assets vanishing), which is the check each of these fixes previously needed by hand. `registryDrift.test.ts` section (b) used to catalogue these as "deliberate divergences" — that framing is what hid the class, so it now asserts registry and evaluator AGREE. Deliberately left at 0: the vec constructors, eight of the nine unary maths, the comparisons, the chainable folds (they use `chainIdentity`), and `length`/`distance`. **`defaultValues` is the SOCKET LIST on PreviewNode/ClockNode/SoundNode-rendered nodes** (the 8 noise nodes, `time`, `soundNode`) — a key there becomes a wireable dead socket, so never add one for emission purposes. A unary can declare a default through the optional 4th element of the `.map()` tuple (`['log2', 'Log2', '…', { x: 1 }]`) rather than being lifted into its own def — registry ORDER is the add-menu tie-break — but `descriptionSplice.ts`'s `isStringTuple` must keep accepting that arity or the Node Designer silently loses the ability to rename it.

### `select`'s condition is a TRUTHINESS test, like Output.discard.

- **`select`'s condition is a TRUTHINESS test, like Output.discard.** three builds it as `bool(cond)` (ConditionalNode), so `0.2` takes the TRUE branch on the GPU; `cpuEvaluator` used `>= 0.5` and therefore showed the OPPOSITE branch for any condition in (0, 0.5) — a window noise sources land in constantly now that the editor remaps them to 0…1. Second instance of the trap already documented for Discard; if a third appears, look for a `>= 0.5` beside a `bool()`.

### `resolveExposedParam` consults the registry before its hardcoded `?? 1`.

- **`resolveExposedParam` consults the registry before its hardcoded `?? 1`.** It is the OTHER resolution path (noise `pos`/`scale`, the uv params) and never read `def.defaultValues` at all, so a node whose stored `values` are missing a key emitted `uv(1)` plus a full 1-radian rotation while the evaluator assumed 0. Unreachable from today's creation paths (both `newNodeValues` and codeToGraph seed `values` from defaultValues) — it is hardening for legacy graphs and hand-edited `.fastshader` input, and it matters more the more defs declare defaults.

### Emit `mix(a, b, t)` as a FUNCTION — never the `a.mix(b, t)` chain.

- **Emit `mix(a, b, t)` as a FUNCTION — never the `a.mix(b, t)` chain.** TSL registers the method as `mixElement = (t, e1, e2) => mix(e1, e2, t)` (three's `MathNode.js`), so **the RECEIVER lands in the FACTOR slot**. `color(lo).mix(color(hi), t)` therefore built `mix(highColour, t, lowColour)` — the low colour used as a per-channel blend factor and the scalar `t` as an endpoint. Verified by dumping the built node (`.mix` wraps its result in a VarNode; unwrap `.node`): the chained form gives `a=#ffd24d, b=SplitNode, c=#1b2a4a`, the function form `a=#1b2a4a, b=#ffd24d, c=SplitNode`. With a dark low end the output sat within ~2% of the high colour across the whole range, so **the Data Stripes / Data Viz ramp was effectively a constant and the low swatch did nothing**; the Stripes and Isolines moiré fades were inverted the same way. All four sites emit the function form now, `dataVizTslContract.test.ts` pins the operand ROLES structurally against the real `three/tsl` (a text assertion cannot catch this — the buggy source looks perfect), and `mix` is imported wherever they emit. **`mix` is NOT the only one** — this line used to claim it was, and that was wrong. Measured against the shipped r184: `a.smoothstep(b, c)` builds `smoothstep(b, c, a)` and `a.step(b)` builds `step(b, a)`, i.e. all THREE displace the receiver, while `a.clamp(b, c)` and `a.pow(b)` really are positional. (Nothing was broken by the error — Isolines' `.smoothstep(float(0.0), hw)` means `smoothstep(0, hw, d)`, which is what it wants — but the guidance was.) `dataVizTslContract.test.ts` now pins the free-vs-method operand roles for all three as executable fact. The safe rule when emitting a named function you have not measured: **write the free-function form**, which is positional for every one of them; that is why `utils/dataRangeFormula.ts`'s emitter never chains a named function at all. Check `addMethodChaining` before assuming any other one is positional.

### Alpha comes ONLY from the `opacity` channel.

- **Alpha comes ONLY from the `opacity` channel.** Everything that can leak into it is normalised in graphToCode: a source whose shape is `!== 3` wired to an ALPHA-BEARING channel (`color`, `emissive` — the two that reach `diffuseColor`; `emissive` counts because the loader copies emissiveNode→colorNode when no colour is wired — a rule from 0.5 that 0.6 and 0.8 carry (0.8 is the only vendored one)) is emitted as `vec3(ref)`. Both ends leak: `vec4(float)` SPLATS (alpha = the scalar) and `vec4(vec4)` is an IDENTITY (alpha = the source's `w`, and a fresh Vec4 node's w is 0 → fully transparent). Shape is read from the PORT the edge leaves (`shapeOfEdgeSource`, honouring `dynamicOutputs`), not the node — Data Viz is out:vec3 + value:float, so node-level inference reported 3 for its scalar `value` socket and skipped the widen. `normal`/`position` are deliberately NOT widened: they never reach alpha, and widening `position` would break the Data Viz `value`→Displacement flow, where normal-mode displacement needs the height to stay scalar. Other alpha traps closed at the same time: `depthWrite:false` used to LATCH (its checkbox renders only while Transparent is on, so unchecking Transparent stranded it) and is now cleared on that transition AND gated on `transparent` at emission — on an opaque mesh it self-occludes into cutout-looking holes; `alphaTest` is coerced+clamped to ≤0.99 (three discards on `alpha <= alphaTest`, so 1.0 erases everything) and never interpolated raw from an untrusted project block. The old both-directions import leak (previous graph's settings carried onto an imported plain `.js`, the incoming file's own settings stripped) is FIXED: `scriptToTSLWithSettings` returns the imported file's sanitized settings, `projectImport` applies them before the sync pass, and `mergeMatch` keeps old settings only when the new node carries none — with one deliberate consequence: a bare editor-TSL import (no return-object settings) now CLEARS the previous shader's material settings instead of inheriting them.

### Discard is a TRUTHINESS test, not a 0/1 switch

- **Discard is a TRUTHINESS test, not a 0/1 switch** — `0.2` culls. It is emitted as a statement (`Discard(cond);` between the definitions and the return), lifted out by `extractDiscards` and routed through the tiny `__pixel` Fn, because `Discard()` needs an active TSL stack. Six things are load-bearing, each measured against three r184's real GLSL/WGSL builders (`bool(0.0)` is false, so a Float 0 correctly culls nothing — verified end-to-end in the app on both backends). (1) **The condition is shape-coerced to a scalar** (`scalarRefOf`) for every source EXCEPT the `logic` category: three compiles the condition as `bool(<ref>)` and widens a non-1-channel float to `all(<vecN>)`, which is declared only over bvecN/`vecN<bool>` — a real WebGL2 context answers `ERROR: 'all' : no matching overloaded function found`, so the whole fragment program fails to link and the mesh vanishes at EVERY value with nothing surfaced. Nothing validates connection types, so a Colour/Vec3/vec3-noise/Image source lands there routinely. Logic nodes are exempt because their vector output really IS a bvecN and `all(greaterThan(a, b))` correctly means "every channel passed"; narrowing it to `.x` would silently change the test. Scalars keep the plain ref, so every existing export is byte-identical. (2) **`cond.discard()` — the method-chaining spelling** (`addMethodChaining('discard', Discard)`) — is lifted too. It used to survive verbatim into the module, landing at plain-function scope where `.toStack()` has no stack and is a silent no-op: ZERO `discard` instructions in the compiled shader, in the preview AND the downloaded `.js`, with `codeToGraph` then dropping the line with no diagnostic so the next graph edit erased it. (3) **`extractDiscards` scans `maskNonCode(body)`** and slices from the original, so a discard inside a comment or a string is not code: scanning raw text ate the body of `/* Discard(a); */` while injecting a live cutout, and turned `const s = 'Discard(1)';` into `const s = '';` plus an unconditional cull — the mesh vanished because of a string literal. (4) **Only STATEMENT-level discards are lifted**; `const k = Discard(n);` is left verbatim (inert) instead of being sliced into a dangling `const k =` (a SyntaxError that took the module down). (5) **A bare `Discard()` is unconditional and carries NO Fn parameter and NO call argument** — passing the empty condition through emitted `__pixel(, …)`; `scriptToTSL`'s reverse walks the wrapper BODY rather than correlating args to params, or the unconditional form would vanish on Load Script. (6) The wrapper's fallback colour is `channels.color ?? channels.emissive ?? vec3(1,1,1)` and `Discard` is force-imported: the loader copies emissiveNode→colorNode only when colorNode is undefined and the wrapper always defines it, so white washed out an emissive-only shader the moment a discard was added. The graph has ONE discard socket, so `codeToGraph` warns (never silently drops) on a second `Discard()` or an unconditional one.

### Scalar→vec3 widening on Output channels

- **Scalar→vec3 widening on Output channels**: a 1-channel source wired to a vec3-typed channel (`color`, `emissive`, `normal`, `position`) is emitted as `vec3(ref)`, NOT bare. three's `NodeMaterial.setupDiffuseColor` does `vec4(this.colorNode)` and TSL splats a 1-channel node across all FOUR components, so a bare `mx_noise_float(...)` on Color silently became the ALPHA too (`diffuseColor.a = noise`) — the surface flickered/vanished as if Opacity or Discard were wired when neither was. Scalar-ness comes from `getNodeOutputShape` (cpuEvaluator), not the registry port type, so an `any`-typed arithmetic chain is caught as well. codeToGraph MUST mirror this: `unwrapScalarWiden` collapses a single-argument `vec3(<identifier|member>)` in a channel position back to a direct edge — unambiguous because a real Vec3 node always emits three arguments — or the round trip grows a Vec3 node with y/z = 0 and re-emits `vec3(x, 0, 0)`, turning a grey ramp red. Both sides are pinned (`graphToCode.test.ts` + a `roundTrip.test.ts` case). Vec3-shaped sources emit byte-identically to before.

### Unknown nodes

- **Unknown nodes**: unrecognized TSL functions in code→graph parsing create `unknown` nodes that store `functionName` and `rawExpression` in values. These round-trip through graphToCode (emitted verbatim), render as magenta `vec3(1,0,1)` fallback in live preview, and show as orange warnings (not errors) in the code editor. The `unknown` definition lives in `NODE_REGISTRY` but is excluded from `allDefinitions` (hidden from content browser/search)

### `hsl`/`toHsl` are NOT `three/tsl` exports — graphToCode emits its own branchless helper `Fn` at module scope

- **`hsl`/`toHsl` are NOT `three/tsl` exports — graphToCode emits its own branchless helper `Fn` at module scope**, and force-imports the `mul`/`add`/`sub`/`abs`/`mod`/`clamp`/`select`/… that only the helper BODY uses (`HSL_HELPER_LINES`/`TO_HSL_HELPER_LINES`; the import collector explicitly skips these two defs, since importing the node's own name would fail). `codeToGraph`'s visitors run over the WHOLE Program, so it `path.skip()`s a `const hsl|toHsl = Fn(…)` declarator BY NAME — without it the helper's own mul/sub/clamp statements parse back as standalone nodes and every Apply grows the graph. Emitted name and skip name are a DRIFT PAIR the guard test cannot catch: `codeToGraph.test.ts` feeds a synthetic `const hsl = Fn(…)`, so renaming the emitted helper keeps it green while real round-trips explode. The general rule: **anything graphToCode emits at module scope is graph content to codeToGraph until explicitly excluded** — the same class as the image node's ban on an async IIFE (its ReturnStatement visitor would hijack the output), and the next hand-emitted helper needs its own skip.

### Module-scope helpers live in ONE table — `engine/moduleHelpers.ts`

- **Module-scope helpers live in ONE table — `engine/moduleHelpers.ts`** (2026-09-02, keyed by helper NAME since 2026-09-03). The hsl/toHsl drift pair above is now structural: a helper is a `{ lines, imports }` entry whose name is either a def's `tslFunction` (with `tslImportModule` `''`) or a VARIANT of a def carrying `alias: { type, ports?, values? }` — the helper a MODE selects (`values.mode`, see the helper-variant convention) or one picked by the wired position's WIDTH (Box). graphToCode records every CALLEE it emits and then emits those helpers in table order, force-importing their `imports`; codeToGraph skips any `const <name> = Fn(` declarator whose name is in `MODULE_HELPER_NAMES` and resolves a call to a variant (or to a LEGACY name of a folded node — `smoothUnion`) through `HELPER_ALIASES` to its owning def, stamping the alias's `values` and mapping the arguments by its `ports`. **Every helper name is RESERVED from the variable namer** (`usedNames` is seeded with `MODULE_HELPER_NAMES`): a node variable is `<base><n>` and `sdBox2`/`sdBox3` are helpers, so a second Box node used to be named `sdBox2` — `const sdBox2 = sdBox2(…)` shadows the Fn it calls and throws a temporal-dead-zone ReferenceError at runtime (measured). `moduleHelpers.test.ts` Babel-parses each body and fails on a free-function call the `imports` list omits, checks every key resolves to a def (directly or through its alias), and round-trips every distance-field node byte-identically. Bodies use FREE functions only — the `.mix()`/`.smoothstep()`/`.step()` receiver-displacement rule.

### Imperative TSL (`Loop`, `If`, `.assign`) needs an ACTIVE STACK, and the module the loader runs has none

- **Imperative TSL (`Loop`, `If`, `.assign`) needs an ACTIVE STACK, and the module the loader runs has none** (measured 2026-09-02 against singularity's black-hole raymarcher). `buildShaderModule` strips the outer `Fn(() => {` and shaderloader calls the default export as a PLAIN FUNCTION, so a `Loop(...)` or `acc.assign(...)` at body level is a silent no-op — three warns "No stack defined for assign operation" only in Node; the preview just shows the un-looped constant. That is the same fact the `__pixel` Discard wrapper already encodes. An imperative block therefore has to be a **self-invoked `Fn(() => { …; return v; })()`** — one const in the flat chain — and that is the shape a future raymarch/loop node must emit. Two things were fixed to let that shape live: `parseBody` used to match `^return` on EVERY line and so hijacked the nested Fn's return as the colour channel (deleting it from the body and leaving the Fn void — a `getTypeFromLength` crash in the minified bundle); it now counts brace depth on the masked body (`nestedFnReturn.test.ts`). And `codeToGraph` used to drop a `Loop`/`If`/`Switch` statement in SILENCE while walking INTO its callback — the body's `const`s became flat top-level nodes, every accumulator aliased to its initial value, and the next Apply re-emitted a constant with `errors: []`; it now warns and `path.skip()`s the whole block (root callee resolved through an `If(...).Else(...)` chain) and warns on `.assign`-family statements naming the variable (`loopStatements.test.ts`). Still true and deliberate: the GRAPH cannot hold a loop (`isSafeExprNode` refuses arrow functions in an `unknown` node — unknown = pure data expression), so pasted imperative code survives in the preview only until the next graph→code sync overwrites the panel. Known side bug, unfixed: an `unknown` node's `rawExpression` keeps the ORIGINAL local names (`step(rLen, 0.13)`) while the re-emit renames `rLen` → `length1`, so the module throws `rLen is not defined`.

### A zero-input node's `defaultValues` KEY ORDER is a positional codegen contract in BOTH directions, and nothing…

- **A zero-input node's `defaultValues` KEY ORDER is a positional codegen contract in BOTH directions, and nothing in `nodeRegistry.ts` says so.** graphToCode's generic `inputs.length === 0 && def.defaultValues` branch emits `Object.keys(def.defaultValues)[0]` as the sole constructor argument (`graphToCode.ts`), and codeToGraph maps call argument `i` onto `Object.keys(def.defaultValues)[i]` — using that key as a real port id, so an identifier argument gets an EDGE wired to it. So the constructor value must stay FIRST: `slider`'s `{ value, min, max }` and `property_float`'s `{ value, name }` are the two multi-key defs riding on it today, and any future zero-input def joins them. Alphabetizing the literal or prepending a key is a tidy-up edit that silently changes what the node emits and what a parsed literal is stored under — `slider` would emit its `min`. The test pin covers float/int/slider/color only, so a reordered `property_float` passes CI. Order-INDEPENDENT and not to be confused with these: `property_color` is matched by name in a dedicated branch on both sides, the noise family's `{ pos, scale }` is wired by name in `processNoiseCall`, and `uv` declares real `def.inputs` so it never reaches `defaultKeys`.

### A baked lookup texture that is SAMPLED LINEARLY must be `HalfFloatType`, never `FloatType`

- **A baked lookup texture that is SAMPLED LINEARLY must be `HalfFloatType`, never `FloatType`**: WebGPU refuses to filter 32-bit float textures without the `float32-filterable` device feature, which the A-Frame bundle never requests — so a float32 LUT looks right on the WebGL2 preview and breaks only on WebGPU (exactly the split the WGSL/GLSL toggle exists to expose). `bakeHalfFloatTexture` (graphToCode) is the shared emitter for every linearly-sampled bake — the Stripes phase ramp, the Data-Viz value ramp, the 256-texel colormap LUT — and the phase ramp is normalized to [0,1] before encoding so float16's ~11-bit mantissa stays smooth. The Data node is the deliberate exception: it wants EXACT per-column values, so it keeps `FloatType` + Nearest, which needs no feature flag.
