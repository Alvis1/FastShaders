### A-Frame pipeline

- **A-Frame pipeline**: graphToCode → tslToShaderModule → shaderloader 0.8 (runtime TDZ fix + auto-import injection + typed `export const schema` parsing — `number`/`color`/`map` — plus per-sub-mesh materials via an additive `parts` return key) → dynamic blob import. (The old standalone `.html` export left with the A-Frame tab — the `.js` download is the only export.) **0.4, 0.5 and 0.6 are FROZEN**: shaders exported against them reference them from the jsdelivr CDN by URL, so editing any of them would ship retroactively to already-shipped artwork (`frozenLoaders.test.ts` pins their hashes) — new loader work goes in 0.8, additively. Every NEW export references 0.8 unconditionally (`LOADER_FILE` in tslToShaderModule.ts), and every surface that runs a module loads it (the preview and its XR popup, the A-Frame tab, podest's stage and VR popup), because a conditional would leave the editor previewing on one loader while the downloaded file runs another — and since 0.8 carries what 0.6 lacks (the FastShaders core, the glTF plugin, `materialParts`), the pin is correctness, not only parity. **Three things every module carries since the switch, all MODULE-only** (`buildShaderModule`, so graphToCode, the code panel and the byte-stability snapshots never move; `moduleBaseline.test.ts` pins the module bytes): `export const threeRevision = '<rev>'` right after the imports (the number comes from the leaf `engine/threeRevision.ts`; 0.8 warns on a mismatch with the page, older loaders ignore it, and `extractFnBody` drops a pasted copy, since two such exports are a SyntaxError); `import * as THREE from 'three/webgpu'` whenever a baked texture spells `globalThis.THREE` in CODE position (rewritten to `THREE` over `maskNonCode`, so strings and comments are untouched, and skipped outright when the code already binds `THREE`); and a `three/tsl` import COMPLETED with every TSL function the code calls but neither imports nor declares, appended sorted so an existing import line never reorders, checked against `engine/tslExportNames.ts` (GENERATED by `scripts/gen-tsl-exports.mjs`; `tslExportNames.test.ts` fails on a three bump until it is re-run, and `moduleImports.test.ts` pins that no module-helper name is a three/tsl export, since that would be a module-scope redeclaration). The last two make a module import standalone on plain three.js; on either loader `globalizeBareImports` turns the namespace import back into the global, so nothing changes at run time (`moduleImports.test.ts`). A bumped `LOADER_FILE` is only real once the submodule is PUSHED and jsdelivr is purged for the new file — otherwise every export 404s for its recipient while working perfectly for the author. A FastShaders GLB carries its module in root `extras.fastshaders.module`; `shader="src: model"` (or `FastShaders.applyFromGltf`) is the ONLY way it runs — see the GLB-module bullet. Loader 0.8 additionally wraps `AFRAME.components['gltf-model'].Component.prototype.init` once to register its glTF plugin, so its `<script>` must follow the A-Frame bundle and precede the scene on every document (it does: tslToPreviewHTML's head script vs the scene-slot injection, and podest's two documents); `shaderloaderGltfPlugin.test.ts` pins the bundle's gltf-model shape the hook depends on. `buildShaderModule` runs its own `fixTDZ` (tslCodeProcessor), and its step 1 — removing `const X = X;` — is ONE regex pass with a backreference plus a set test over the imported names. A RegExp compiled per imported name rescans the whole body, about 40 full-body scans on a large graph, on every path that builds a runnable module: each debounced preview rebuild, each Download Shader and, undebounced, every graph edit while the A-Frame tab is open.

### Emitted order is `emitOrder`, and it may NEVER be derived from the nodes array

- **Emitted order is `emitOrder`, and it may NEVER be derived from the nodes array** (`emitRank` in `engine/materialPartsContract.ts`, a zero-import leaf; `outputsInEmitOrder` in `utils/outputMaterials.ts`). One Output node is one material, so the order its `parts` / `materialParts` entry takes in the module has to come from somewhere — and the nodes ARRAY is not a usable order and never can be: `liftChildrenAfterParents` splices a node into a new slot on an ordinary drag-into-a-group, and `useSyncEngine` reorders on every Apply. Deriving emitted order from it would rewrite the module on a LAYOUT GESTURE — `previewCode` advances, the 3D preview recompiles, the autosave dirties, `__partPixel<n>` renumbers, and first-claim-wins flips on a duplicate mesh name — all with `errors: []` and nothing on screen to explain it. So every Output carries an explicit integer `emitOrder`, read through ONE strict accessor. **`emitRank` returns the integer ONLY, and anything else is 0**, so a `.fastshader` claiming `"3"`, `3.5`, `NaN` or an object cannot reorder anything. **The node-id tie-break belongs at the SORT, never in the accessor**: a rank is NOT unique — `unfoldOutputMaterials` seeds every node it makes from its old material index, so two folded Outputs unfolded in one document each produce a node 0 carrying `emitOrder: 0` — and `Array.prototype.sort` is stable, so without the tie-break those two fall back to array order, which is the very thing the rank replaces. `outputsInEmitOrder` is that sort (`(emitRank, id)`, duplicate ids dropped first-wins, since a plan keyed by node id cannot say anything sensible about two nodes claiming one and React Flow cannot render them either), and every cross-node plan walks it rather than whatever array the caller happened to hold. The rank has exactly THREE writers: the unfold seeds it from the old material index (node 0 → 0, `materials[k]` → k+1), `codeToGraph` from the parse's own MINT position, and `gltfSectionBuilder` as it builds. An Apply keeps the PARSE's rank rather than the old node's, because `mergeMatch` spreads the parsed node's data — which is right: the rank describes the MODULE's order, and the module is what was just parsed. **No restore path sanitizes the key, and none needs to**: `emitRank`'s strictness IS the validation and it is applied at every read, so a junk value can sit in `data` forever without ever reaching a sort. **An ABSENT rank reads as 0**, which is what keeps every document that has never been split emitting byte-identically — every rank is 0, ties keep array order, and the order is exactly what it always was. The accessor lives in a zero-import LEAF because `activeSink` (utils/sdfPartition.ts) has to elect the LOWEST-RANKED untargeted Output — the same node `defaultOutput` picks, or the two name different nodes on a split document whose empty material was reordered ahead of the real default — and sdfPartition is a leaf nothing in the store cycle may drag `outputMaterials` into (the costTable TDZ rule); a SECOND copy of the accessor is precisely what this rule forbids. `materialParts` needs no rank of its own: an index is claimed once, so ascending glTF index is already a total order — the node rank there decides only WHICH node wins a duplicate index.

### `toHsl` (RGB to HSL) exposes h/s/l as SWIZZLES of one emitted call, and `out` stays `outputs[0]`.

- **`toHsl` (RGB to HSL) exposes h/s/l as SWIZZLES of one emitted call, and `out` stays `outputs[0]`.** The node has four outputs: the vec3 `out` plus float `h`/`s`/`l`. Codegen emits ONE `const toHsl1 = toHsl(rgb);` and `resolveEdgeRef` maps h/s/l → `.x/.y/.z` of that variable — never three calls, which would inline the helper Fn three times (~2.5× the GLSL, measured through GLSLNodeBuilder) and make `complexity.json`'s flat `"toHsl": 15` a lie. `codeToGraph.resolveMemberExpr` carries the INVERSE map so `toHsl1.x` parses back to the `h` handle: without it every member expression mints a **Split node**, so each Apply would splice one between toHsl and its consumers and the graph would grow without bound — while the code text and the rendered picture stayed correct, which is why the test asserts a zero split-node count rather than relying on byte-equality. `TOHSL_HANDLE_TO_COMPONENT`/`TOHSL_COMPONENT_TO_HANDLE` (graphToCode) are a drift pair — swapping one direction silently exchanges S and L across a round trip. **`out` is deliberately NOT replaced by the three sockets**: it is the defensive default the codebase assumes everywhere (`?? 'out'`, `outputs.find(id === 'out') ?? outputs[0]`, the designer's literal `sockets['out']` key, `tryInsertOnEdge`'s `def.outputs[0]`), and a removed handle has no migration path — `applyProjectToStore` runs none of `loadGraph`'s migrations and codeToGraph re-creates `'out'` on every Apply, so a shared `.js` would carry a dead handle forever. React Flow renders such an edge as NOTHING while keeping it in the store and still emitting its code: it fails silently, with the picture intact. h/s/l are `float` (not `any`) so the Output-channel scalar→vec3 widening fires.

### Edge VALUES are read per SOURCE SOCKET, not per node

- **Edge VALUES are read per SOURCE SOCKET, not per node** (`cpuEvaluator`: `handleChannels` over `handleSlice` + `evaluateEdgeSource`/`evaluateEdgeRange`/`getEdgeOutputShape`). `evaluate` stays keyed by node id and returns the whole vector; the socket is applied at the CONSUMER. That split is load-bearing: `evaluate`/`computeRange` write a null sentinel under the node id BEFORE recursing (their cycle guards), so a per-handle cache key would give a cycle re-entering the same node through a different socket its own sentinel and it would recurse until the stack blows — reachable from a hand-edited `.fastshader`, since `topologicalSort` only warns. Handle-blindness was harmless until `toHsl` because no node returned different numbers per socket (split/dataNode/dataviz evaluated to null and a Sound channel was a uniform 0 then; Split is a pass-through, a Data column and Sound range sources, since 2026-10-27), so a wrong socket degraded to an honest `…`; with three real values it would print Hue in live blue beside a Saturation wire. `portShapeForHandle` is the ONE per-handle port lookup, shared by codegen's `shapeOfEdgeSource` and the visual layer — necessary even for declared floats, because `computeShape` resolves `outputs.find(id === 'out') ?? outputs[0]` and would report the vec3 width for every socket of a node that has an `out` port (the live Data Viz `value` bug). **Every cheap-string memo key that folds `e.source` must also fold `e.sourceHandle`** (ShaderNode's `edgeKey` + its `bySource` map, Sound/Output/Clock keys, PreviewNode's `inputsKey`, MathPreviewNode's `xKey`, LiveEdgeValue's and EdgeInfoCard's `useFrameLoop` deps): re-wiring between two sockets of the SAME source leaves source/target/targetHandle identical, so `Object.is` bails and the surface shows the old channel forever. `TypedEdge` must read the handle off the UNWRAPPED edge, never React Flow's `sourceHandleId` prop — `unwrapCollapsedGroupEdges` rewrites the handle too, and a collapsed group's synthetic socket id matches no registry port, so the projection would fall back to the whole vector and draw a plausible, wrong-width ribbon. `range` (edgeValueLabel's field flag) is decided on the SOURCE NODE before any projection (see the sampled-field bullet), and a noise range is PROJECTED, never re-derived. `computeShape`'s default broadcast reads the per-handle width too (`portShapeForHandle`, the append branch's rule). It used the node-level width, so `toHsl.h → mul → Color` counted 3, skipped the Output's `vec3()` widen and splatted the float into alpha: the alpha-bleed bug by a third route. `engine/socketWidthPins.test.ts` pins the widened emission (`vec3(mul1)`) for `toHsl.h` and dataviz `value`. **The Texture (Image) node needs a RUN, not an index**: its whole vector is the rgba SAMPLE (`analyticalRange` [0,1]⁴, which also makes it a FIELD), so `out` — and a null or tampered handle — projects channels [0,3) and Alpha/R/G/B one each (`utils/imageChannels.ts` is the ONE socket table, a Map-only LEAF; `IMAGE_CHANNEL_INDEX` must equal `'rgba'.indexOf` of the emitted swizzle, pinned). `handleChannels` is the projection every internal consumer uses; `handleSlice` survives for single-channel callers and is unchanged. A 4-wide `out` would make EdgeInfoCard (count = max(rangeLen, shapeLen)) draw four channel cards on a vec3 wire. No CPU VALUE is ever claimed for an image — its pixels decode asynchronously in the DOM from an adversarial payload — so every socket evaluates to null and only the bound is shown (`engine/imageChannelSpans.test.ts`).
  - **A Split reads its SOURCE SOCKET for an own-member source** (`SPLIT_SOCKET_AWARE` in graphToCode — Fresnel, Color Ramp, toHsl, the Texture node `imageNode`, Sound `soundNode`, Data Viz `dataviz` and the Data node `dataNode`; 2026-10-08, the last four 2026-10-11). The split branch of `resolveEdgeRef` emitted `<bare var>.<comp>` and ignored the Split input's `sourceHandle`, so Facing → Split.x emitted `fresnel1.x` (the FRESNEL value), Alpha → Split.x `colorRamp1.x` (red), and toHsl s/l → Split.x `toHsl1.x` (hue — a live bug since toHsl gained sockets). Now a SCALAR socket is its own `.x` and has no `.y/.z/.w` (null: the consumer reads as unwired); a vector socket swizzles the bare variable, so Color Ramp's Color → Split.w reads alpha rather than failing. On Apply the own-member text parses back to a DIRECT edge from that socket and the Split is dropped — same value, then stable. Every other source keeps the bare-variable text byte-identical. Since 2026-10-11 the set also holds the sources whose sockets are variables of their own or channels of one sample: Image Alpha/R/G/B → Split.x reads `image1.a`/`.r`/`.g`/`.b` (it read `image1.x`, red, while the card showed the right channel), Data Viz Value → Split.x reads `_dataviz1_t` (it read the ramp colour's red), and Sound / Data → Split.x read `sound1_<ch>` / `data1_colN` (they named `sound1` / `data1`, which nothing declares — a ReferenceError, so the shader failed to load; the Data node case was not in the audit). Every `out` source (narrow or wide image, Data Viz Color) stays `<bare>.<comp>`, byte-identical: of all 480 registry source-socket × Split graphs, 60 change and 0 `out` sources move (re-checked in review; `engine/splitSourceSocket.test.ts`). An Apply of the image forms stays inert, because image nodes are one-way; the new Data/Sound/Data Viz split forms are one-way through codeToGraph like their direct forms, and an Apply drops the Split.
  - **One scalar narrowing, `narrowRef`** (graphToCode, used by `scalarRefOf` and the SDF Output Field/Density sites): appending `.x` to Color Ramp's `colorRamp1.rgb` gave `colorRamp1.rgb.x`, a nested member `resolveMemberExpr` cannot read, so Discard, the Splat scalars and SDF Field/Density lost the wire on Apply. A non-scalar Color Ramp source narrows to `.x` of the BARE variable (the same red). Like every vec3 → scalar edge, that splices ONE Split on the first Apply and is byte-identical from the second.
  - **`resolveRefExpr`** (codeToGraph): identifier OR member, one helper (`resolveReturnSource` calls it first). It replaced identifier-only reads at the SDF Output's captured chain (now through `unwrapScalarWiden`, so `const rm1Color = vec3(fresnel1.y)` keeps its wire), the march params, the Noise position (an unrepresentable position is now a WARNING instead of a silent drop) and UV tiling (an identifier or member tiling argument wires into `tilingU`/`tilingV`). A CONSTANT march field written as an expression-bodied arrow (`Fn(([p]) => fresnel1.y)`) is routed like a return. All found by the consumer sweep (`ownMemberConsumers.test.ts`); they dropped wires from ANY source, with no message. UV `rotation` stays ONE-WAY: a wired rotation emits the expanded rotation chain, which parses back as its own nodes.

### A SAMPLED FIELD's value is not its range, and that has to survive every operator below it

- **A SAMPLED FIELD's value is not its range, and that has to survive every operator below it** (`analyticalRange` + `getFieldUpstreamSet` in `cpuEvaluator`, `range` in `edgeValueLabel`). `uv`, `screenUV`, the geometry attributes and the whole noise family vary across the surface, so `evaluate` returns ONE arbitrary sample of them — the uv centre, or the integer lattice where Perlin is exactly 0. `computeRange` special-cases each with an analytical interval, but then took a finite deterministic eval as a degenerate range for everything DOWNSTREAM, which collapsed the whole chain: a `mul` between a `0…1` gradient and a `-1…1` noise reported a flat `0.00` sitting between two inputs that each read as a range, and the same `0` then propagated through clamp, mul and add to the Output. Reported from the canvas as "the value range goes in and comes out 0, although it is visible that it is not just zero". The block comment above that section had always CLAIMED interval arithmetic carried those chains; it never ran, because `evaluate` learned to sample noise on the CPU after the shortcut was written and short-circuited it from then on. **The gate is one predicate used twice**: `analyticalRange(node)` is the single table of field types (returning their bounds), and `getFieldUpstreamSet` seeds a memoized forward BFS from `!== null` — so a field added to the table is a seed by construction and cannot be forgotten. Three consequences. The deterministic shortcut still runs for every field-FREE chain, so constants keep their exact degenerate range (`2 × 5` is `10`, not a widened interval). Interval arithmetic is an over-approximation, so a long chain reports a BOUND rather than the true span (the dependency problem — `x - x` is not 0 to an interval); that is the honest trade against a number that is simply wrong. And the ops that had no interval rule became reachable for the first time, so `exp`/`log2`/`pow`/`mod`/`dot`/`hsl`/`toHsl` gained one and `length`/`distance` lost their flat `[0, Infinity]` — without those, `pow(oneMinus(dot(…)), k)` (all four fresnel presets) would have gone from a wrong number to a bare `…`. MEASURED across all 32 built-ins: 184 of 858 edge labels change, **zero** lose information, and 22 that read `…` now report a real bound. `edgeValueLabel` asks the same set, so the node ROWS and the wire CHIPS agree — they disagreed before, which is what made the defect visible. A sampled IMAGE (`imageNode`) is a field too, seeded at [0,1]⁴ (GLB Phase 4): an Image-fed label reads `0…1` where it read `…`, and everything below an image takes the interval path instead of what `portRange` gave an unknown upstream (an invented `[0,1]` until 2026-10-27; unknown since — see "An edge label is what the SHADER holds"). **Per-entry reasons of `analyticalRange`.** `normalWorld` is unit BY CONSTRUCTION (three builds `normalView.transformDirection(cameraViewMatrix)`, which ends in `normalize()`); without its entry the four fresnel presets' `dot` edges read a bare `…`. The per-channel box cannot express |v| = 1 — it is only the tightest axis-aligned bound. `vertexColor` is a RANGE and never an `evaluate` case returning white, because white is only what the missing-attribute fallback emits; four channels, to match `portShapeForHandle`'s vec4. `wireframe` is a field because it depends on screen-space derivatives, which the CPU has no equivalent of. The noise entry follows the per-node range flag: asserting [0,1] for the whole category made edge cards report `0…1` for a shader emitting -1…1. And `length`/`distance` take the interval norm rather than a flat `[0, Infinity]`, or Circle's `distance(uv, 0.5)` loses its label under the deterministic gate.

### An edge label is what the SHADER holds on that wire

- **An edge label is what the SHADER holds on that wire — a point equals it, a range CONTAINS every value of it** (2026-10-27). Reported as "if on the UV node I make U 10, it does not show on the edge, although the preview is certainly overblown": `analyticalRange` held UV at a fixed [0,1]² while graphToCode emits `mul(uv(), vec2(U, V))` and a turn about (½, ½). An audit of every node family then measured 59 more ways a label misstated its wire — each re-measured by an independent check that ran the evaluator and read three r184's built WGSL/GLSL — and they were fixed in the evaluator and the label layer alone (no emitted byte moved). The rules that came out of it:
  - **Unknown is unknown.** `portRange` used to turn a wired upstream with no range into an invented `[0, 1]`, so distance(Position (world), Camera Position) read 0…1 for a wire that is 7…9, Split chains invented bounds, and an SDF's whole inside vanished. It is now ±∞ on each of the upstream's channels — `…` on a label — and the self-bounding rules (clamp, sin, fract, smoothstep, normalize, the comparisons, hsl…) still bound it. `sanitizeRange` makes every cached interval NaN-free and never inverted (a 0·∞ corner is an unknown end). And in `evaluate`, a WIRED socket whose upstream has no finite value makes the node's own value unknown (`wiredUnknown`) — `scalarInput` used to fall back to the STORED number behind the wire, which printed Mix's inline 0.5 blend under a Position (world) factor in live blue. Measured on the 32 built-ins + 12 recipes (912 wires): 79 labels that read `…` gained a bound, 15 lost a number, and all 15 were world-space or camera chains whose number had been invented.
  - **Every source NODE with values is in the field table** (`analyticalRange`, still the one field-seed predicate — the data-viz nodes that read uv().x when unwired are bounded by rules of their own instead, and a LiveEdgeValue tick falls back to that interval when the point is unknown, as the resting label does): `rayDirection` as a unit vector; `positionWorld`, `positionView`, `cameraPosition`, `cameraNear`/`cameraFar` as UNBOUNDED (they have values, the editor just cannot bound them — an exported page has its own camera); a Data node's columns at their own samples (`dataColumnRanges`, handle `colN` → column N); Sound at 0…1 × its gain per socket (a live uniform is a range, armed or not — the static 0 read as a dead wire). Model-space positions are ±1, not fit-bounds' ±0.8: the built-in sphere has radius 1 and the plane is 2×2 (fit-bounds touches dropped models only). Still NOT modelled: a skinned/animated model (fit-bounds scales its root, so its positions stay in authored units), positionLocal under a displacement (the fragment stage reads the displaced position), a position root inside a raymarch scope (the ray point spans the Window), and UVs outside the unit square — the generated spherical UVs of the Bunny or a UV-less OBJ reach just under 1.5 at the seam (measured u ≤ 1.108 on the Bunny), and a model's own TEXCOORD is unbounded. Labels are graph-level; they cannot know which mesh the pane shows. Sound and the camera seed the field set because a label must take their RANGE, but they are uniforms — one value across the surface — so the Image UV hand-off asks `getSurfaceFieldUpstreamSet`, which leaves them out (a Sound-built vec2 had been wired into an Image's UV, painting the mesh one flickering colour).
  - **UV is computed in `computeRange`** (time-aware, so a wired U or Turn ticks) from `exposedParamRange` (resolveExposedParam's own rule: junk reads 1): tiling as corner products, the turn by interval products with `sinInterval`/`cosInterval` — exact for a constant turn. analyticalRange keeps its [0,1]² entry as the field SEED.
  - **Widths convert as TSL converts them** (`toTslWidth`, NodeBuilder.format): a scalar splats, vec2 → vec3 pads 0, → vec4 pads w = 1, a wider value truncates — in every point AND range op. The `a[i % a.length]` cycling showed vec2(2,3) × vec3(1,1,1) as (2,3,2) where the shader holds (2,3,0). OperatorNode takes the wider operand except `%` (mod), which keeps the FIRST operand's width; MathNode takes the widest.
  - **Split is a pass-through** of the upstream's BARE variable, padded as SplitNode pads (vec2.z = 0, vec3.w = 1, a scalar answers every component) — it had NO case, so every Split wire read `…` and the next node invented 0…1. A wire codegen resolves to nothing (a dangling Split, one fed by another Split, .y/.z/.w of a scalar socket of a `SPLIT_SOCKET_AWARE` source — the set now lives in cpuEvaluator, graphToCode imports it) is UNWIRED at the consumer, exactly as the shader emits it: `deadSplitWire` filters them out of `evalEdgeIndex`, while `getTargetEdges` keeps drawing the socket wired. A socket reads its FIRST wire, as graphToCode's `inEdge` does: `evalEdgeIndex` keeps one edge per (target, socket) and only then drops it when dead — filtering the dead ones first had a label read a second wire the shader never sees. And a node's SHAPE counts every effective operand (`computeShape` over `appendOperands`): a vec2 in a Divide's growth socket `c` read as a scalar, so an Append after it emitted `vec2(div1, 3)` for a three-channel value. The walk's cycle guard is the CURRENT path, popped on return, with a memo for a node met again on another path — one walk-wide `visited` read such a node as a scalar (the wrong Box helper on a vec3; a vec4 Append passed bare into Color, its w in alpha) — and Mod's width is its X, Select's its two branches (`WIDTH_PORTS`, as OperatorNode '%' and ConditionalNode type them; a scalar Mod over a vec3 divisor had skipped the Output's vec3() wrap). The card cells (`useWiredLabels`, ShaderNode's graph info, the noise thumbnails' inputs) and the time/field/live sets (`ctx.evalEdges`) read the same first live wire, so an ignored wire neither labels a socket nor animates a constant.
  - **Point semantics follow the GPU**: division and mod are IEEE (x/0 is ±∞, mod is FLOORED, x − y·floor(x/y), as three emits it on both backends — JS `%` truncates; an all-INT pair is integer arithmetic, the next section); sqrt/log2/pow outside their domain are NaN/−∞ (pow of a negative base too — WGSL defines it through exp2(e·log2 b); a constant one does not even compile), never a clamped 0, a floored −33 or Math.pow's (−2)² = 4; `round` is WGSL's half-to-even; smoothstep with equal edges has no value (WebGPU rejects the module); clamp with low > high has none; normalize(0) is NaN; a Colour is LINEAR light (`color(0x…)` runs THREE.Color's sRGB→linear: #808080 is 0.216, not 0.5); HSL wraps any hue (the helper's mod(h·6, 6)); Select reads a comparison vector with all(); `vecN(...)` spreads a vector argument as JoinNode does; Transform/Repeat read their vec3 sockets (the twin still read the retired tx…lz ids); a vec2 into a vec3 socket pads with 0; a constant with a missing or junk value is the default codegen emits; Int rounds (`int(2.4)` is 2 wherever three converts it).
  - **Interval rules that were unsound** now contain the shader: division by a divisor reaching 0 (an invented [0,1] — now unknown, or one-sided when the numerator's sign is known: 0.05/length(uv − ½) is 0.07…∞, which a later clamp still bounds); clamp (an x wholly outside printed "2…1"; now the formula at the low and high corners, per channel); mix (the union of A and B assumed t in 0…1; now the 8 corners — signed Perlin into t extrapolates); remap (unclamped, as TSL's is); hsl (l ∓ ½|s|·|1 − |2l − 1|| at L's ends and kinks — Saturation 3 reaches −1…2) and toHsl (S unknown out of gamut); the Voronoi family (a SQUARED distance, 3/3/3.5 — node-types.md) and fBm (three octaves, ±1.75). Tightened, still sound: sin/cos (exact over spans under a period: sin(uv·π) is 0…1), fract within one step, smoothstep between constant edges, mod within one period, the comparisons where the intervals cannot overlap.
  - **Distance fields**: the eight non-circle primitives share ONE twin (`sdfPrimitiveAt`), and their range is the Lipschitz bound — an exact distance moves no faster than its point, so over the position box it lies in f(centre) ± half-diagonal (× 1 + 1e-6: the helpers' constants are rounded); a swept shape parameter leaves it unknown, and so does a setting outside the shape's exact-distance domain (a Star below 2 points or at Sharpness ≤ 1, a negative Octahedron size — measured |Δf|/|Δp| up to 800). Every twin reads Position as the helpers' swizzles do: a scalar answers every component (SplitNode), a vec2's z is 0 — a typed 0.5 had put a Torus's label inside where the shader drew outside — and the Lipschitz box is measured in those coordinates (a scalar half-width moves the vec3 point √3 times as far). Transform, Mirror, Revolve, Repeat, Repeat around, Deform and Extrude carry positions/distances by sound rules of their own.
  - **Data viz**: Colormap is 0…1 per channel (a ClampToEdge LUT), Isolines 0…1, Stripes/Data Viz the hull of their two ramp ends (× Stripes' line darkening) with Data Viz's `value` socket its own t, and Data Range maps its input through the SAME plan codegen bakes (`planNormalize` over the one-hop column statistics — every plan is increasing), clamped when `clamp` is on; a custom formula has no interval rule.
  - **The label layer** (`utils/edgeValueText.ts`, `edgeValueLabel`, LiveEdgeValue): a range prints rounded OUTWARD — the printed interval always contains the true one — at a precision that follows its span (`0…0.3`, `-0.5…0.5`, `0…11`), and never collapses a true range into one number (UV × 0.3 read "0", a signed −0.4…0.4 field "0", −0.5…0.5 "0…1"). The fixed-width Output, Splat Output and SDF Output cells print whole numbers, still outward (`compact`). A field fed by Time ticks its INTERVAL (`range` → `liveEdgeRangeText`, as EdgeInfoCard always did) — UV + Time read "0…1" forever. Blue marks a point value only.
  - **The guard is `engine/edgeValueTruth.test.ts`**: every finding as a regression, and SOUNDNESS SWEEPS — for each op, and each SDF primitive and domain operator, the interval over a field must contain the evaluator's own value at sampled constant points inside it. An unsound rule fails there whatever node it sits on. Still open (codegen, not labels): a Color compared with a number compares RED only (OperatorNode does not treat 'color' as a vector); `vec3(uv, 0.25, 0.5)` drops Z (JoinNode); a preview-tuned uniform is not on the label. (Int-first arithmetic, open here at first, is the next section.)

### An INT that meets a FLOAT is a FLOAT

- **An INT that meets a FLOAT is a FLOAT** (owner, 2026-10-27: "int — always change to float where there is float"). three r184 types each operation itself: OperatorNode takes the FIRST operand's type on a tie, MathNode its widest input with its own tie-break, and every other operand is CONVERTED to that type — a constant rounded (`generateConst`), anything else truncated. So an Int wired first turned its float partner into an int: Int 4 × 0.3 built `( 4 * 0 )` (measured 0 on both backends), Int 3 ÷ Float 2 was 1, an Int-fed Raymarch field compared `d < eps` as ints, and a float function of an Int (`sin(int)`) does not compile on GLSL ES at all. The rule lives in `engine/intPromotion.ts`, a LEAF all three engines read through ONE adapter, cpuEvaluator's `intGraphOver`:
  - **graphToCode wraps the int in `float(…)` where it meets a float** — in `resolveEdgeRef`, the ONE choke point every consumer resolves its wires through (the unknown node's bound references read `resolveEdgeRefInner`, the un-promoted ref, because their stored text already spells its own conversion). An int stays an int only where EVERY operand is one: Add/Subtract/Multiply/Divide/Mod/Abs/Clamp over int WIRES alone (Int 7 ÷ Int 2 is still the integer 3), a Split of an int (SplitNode answers every component of a scalar with the scalar itself), and a socket declared `int` (UV's Channel). NOT Min/Max: on WebGL three builds a scalar second operand as a float (`min( 4, 3.0 )`, MathNode's WebGL branch), which GLSL rejects — so they are promoted like any float function. An UNWIRED operand is a JS number, which TSL types as a FLOAT literal (`getValueType`), so a stored 0.3 promotes its int partner, and a wire codegen resolves to NOTHING (`deadSplitWire`: a dangling Split, a Split of a Split, a socket that is not a swizzle) is unwired here too. Only the Int node produces an int and it has no inputs, so every all-int chain is a constant — so its value is known at codegen, and **an all-int operation whose value (or any partial result of its fold) leaves ±2147483647 is a FLOAT operation** (`intValue` in `isIntSource`): 50000 × 50000 wrapped to −1794967296 on WebGL and, shared, failed to compile on WebGPU ("value 2500000000 cannot be represented as 'i32'"); promoted, both hold 2.5e9 (measured). The Int LITERAL is clamped to the same symmetric range (`intLiteral`: rounded, then clamped — GLSL ES rejects the literal 2147483648, and `abs` of −2147483648 overflows), its label shows the clamp, and the Int card commits it the same way (a typed 5000000000 stores 2147483647). **The Int is emitted WHOLE** (`int(2)` for a stored 2.4): three rounds `int(2.4)` only where it builds an int, so `float(int(2.4))` — the promotion — ran 2.4 while the label said 2. `float` is imported only when a wrapper reaches the module text — a socket read CPU-side (Sound's Smoothing) or ignored by its mode (SDF Deform's `h` under Twist) resolves its wire too, and an unused import would differ from the round trip's. A graph with no Int node emits byte-identically (no built-in holds one).
  - **A scalar COMPARISON meeting a number is a float too** (`promotesLogicWire`, the same choke point): Greater Than / Less Than / Equal build a bool in TSL, and `mul(greaterThan1, 2)` was bool × float — measured: GLSL `'*' : wrong operand types`, an invalid WebGPU module, while its label read 2. It is wrapped `float(…)` wherever it is resolved except where a bool is the point — a Select's `condition`, an Output's `discard` — and the Output vec3 channels' old `vec3(float(<ref>))` keeps its exact bytes. A VECTOR comparison (bvecN) is left alone: `float()` would keep only x. Measured on both backends: × 2 → 2, + Float 0.5 → 1.5, Less Than → 0, Mix's factor → 0.9, Select → its branch, a comparison over a Perlin compiles.
  - **codeToGraph strips the wrapper back off** (`stripIntPromotions`, a pre-pass before anything else reads the AST) in ANY position — an argument, a channel value, a return, a Raymarch field's arrow body, a method receiver — or every Apply grows a Float node between the Int and its consumer: the Float constructor's own parse of `float(<ref>)` is a Float 0 with a dead wire. It strips every `float(<ref>)` whose ref is provably SCALAR, not only an int: for a scalar the conversion is the identity (or the int → float graphToCode adds back), so EDITING the Int a wrapper names (`int(4)` → `float(4.5)`) keeps the wire — stripping ints alone had silently zeroed it. Scalar is decided per BINDING (Babel scope), never per name, and only for a binding nothing reassigns; an imported input (`time`) counts; a def declared float is scalar only as a source or a REDUCER of a vector (Length, Dot, the distance fields) — Smoothstep and Remap are declared float but compute per component, so they count only over scalars (stripping `float(<vector smoothstep>)` had dropped its x); a COMPARISON's ref strips whatever its operands, being graphToCode's own wrapper. A ref that is not provably scalar keeps the old parse (`float(vec)` is its x, and `.x` would drop an int → float). A local named `float` does not stop it: in graphToCode's text a Property named `float` is renamed by fixTDZ, and `float(…)` means three's conversion (guarding on it had disconnected the Int on Apply). The pre-pass's scope crawl THROWS on a duplicate declaration, so it sits under the same try/catch contract as the main traverse (a parse error, never a throw out of codeToGraph).
  - **A conversion the graph cannot hold is announced, decided on the BUILT graph**: there is no conversion node, so a HAND-WRITTEN `float(a)` that made an operation on Ints ALONE a float one (`div(float(a), b)` for the fraction, `const c = float(a)` then `div(c, b)`, `float(a).x`, a `.toVar()`'d or inline `int(2)` partner) is read as the Int and the operation becomes whole-number. The pre-pass records the DIVIDE and MOD calls that read a conversion — directly or through other int-preserving operations, whose result carries it on (`add(float(a), b)` then `div(c, b)` names the div's line, where the value changes; Add, Multiply, Abs and Clamp keep their value whole-number or not, so they never warn); `processCall` records which node each became (`CALL_NODE_IDS`); `lostIntConversions` warns where that node is an int in the finished graph. Deciding on the AST had both false alarms (a Noise node's `pos.mul(scale)`, which folds into the node's own sockets; a call inside an unknown function or a dropped Loop; Isolines' own `.sub(offset)`) and misses (inline `int()`, `.toVar()`, a swizzle). graphToCode never emits that shape.
  - **cpuEvaluator computes what the shader computes**: wherever a float takes part the arithmetic is float (it always was — JS); an all-int Divide truncates toward zero, an all-int Mod is the remainder, and an operation past the i32 range is float here as it is in the shader. Where the backends DISAGREE the label is unknown, never a guess — measured on Chrome/M4 Max: an all-int ÷ 0 or % 0 is a constant division (three inlines Int literals), which WebGPU rejects ("integer division by zero is invalid") and ANGLE folds to INT_MAX; a negative operand of an all-int Mod is truncated by WGSL (−7 % 3 = −1) but folded to 0 by ANGLE (GLSL ES leaves it undefined).
  - **The guard is `engine/intPromotion.test.ts`**: the emission, parse and evaluator cases, the hand-written warnings, and a SWEEP — every registry socket, fed by a bare Int, a Split of an Int and an all-int Add, must round-trip to the same fixed point a Float source does. The sweep is what found the arrow-body and `return` positions the first stripper missed. The shader side was measured, not reasoned (2026-10-27 review): each case through three r184's own GLSL/WGSL builders and the real WebGPURenderer on both backends, the pre-change controls reproducing the 0 and the GLSL `sin(int)` failure. Found then and NOT caused by ints (a Float source failed the same way), all fixed the next days: a wire into UV's Channel was ignored (the next section); Dot and Normalize fed only scalars, and a constant SDF Field, failed to compile on WebGPU ("WGSL has no scalar `dot` or `normalize`" below, and sdf-and-raymarch.md); an Int beyond the i32 range was labelled with a value no backend holds (above).

### A wired UV Channel chooses its map IN the shader

- **A wired UV Channel chooses its map IN the shader** (2026-10-27). three r184's `uv(index)` names its attribute from a JS NUMBER at build time (`'uv' + (index > 0 ? index : '')`), so the old emission `uv(int1)` compared a node with 0 and read channel 0 whatever the wire held — measured on both backends. A stored channel still emits `uv(2)`, byte-identically; a WIRED one emits `fsUvChannel(<ref>)`, a module helper (`engine/moduleHelpers.ts`, `UV_CHANNEL_HELPER`, an alias of the UV def with `ports: ['channel']`) that selects among `uv()`, `uv(1)`, `uv(2)` and `uv(3)` by the wire ROUNDED — three's own `int()` rounds a constant but truncates a run-time value, so Float 1.7 picked map 2 as a constant and map 1 as a uniform, and a computed 0.99999994 picked map 0. Any other value reads channel 0; a map the mesh lacks reads (0, 0) with three's console warning (the preview surfaces `console.error` only), so a wired channel on a one-map mesh logs uv1–uv3 as missing. Measured on Chrome/M4 Max, WebGL2 and WebGPU alike, through the real WebGPURenderer on a mesh carrying uv/uv1/uv2: Int 0–2 read their maps, Int 3 (0, 0), 5 and −1 channel 0, Float 1.7/1.4 maps 2/1, a Property uniform 2/1.7/1.4/0.99999994 maps 2/2/1/1, tiling applies after the choice. UV is the one helper-alias owner that is a `three/tsl` export: its emission branch imports `uv` itself and the generic import loop skips the type (`moduleHelpers.test.ts` says so). The parse reads `fsUvChannel(ref)` back through the alias, and `tryParseUVTiling` reads a referenced channel as a WIRE in `mul(uv…(ref), vec2(…))` too — it read only a literal channel, so a channel wire under tiling was lost on every Apply. Guard: `engine/uvChannel.test.ts`.

### WGSL has no scalar `dot` or `normalize`

- **WGSL has no scalar `dot` or `normalize`** (2026-10-28) — GLSL has, so `dot(float1, float2)` and `normalize(float1)` drew on WebGL and took the whole module down on WebGPU ("no matching call to 'dot(abstract-float, abstract-float)'"). Their sockets are declared vec3, so when EVERY operand is CERTAINLY a scalar — an unwired number, or a wire `certainlyScalar` vouches for: a source or reducer declared float (Float, Time, the noises, Length, Dot, a distance field, a Split or channel socket), or Smoothstep, Remap or an any-typed operation over certain scalars, never a declared vector, an Append or an unknown expression (the declared type alone widened a vec4 Smoothstep and dropped its w) — graphToCode emits each as `vec3(<arg>)` (`VECTOR_ONLY_FNS`, the generic call branch): what a scalar in a vec3 socket means, and what three already builds the moment one operand is a vector (MathNode takes the widest), so a call with a vector operand keeps its exact bytes. `cross` needs none: three builds both of its operands as vec3 itself. The label follows — `dot(2, 3)` is 18, not 6; `normalize(2)` is (1/√3, 1/√3, 1/√3), a vec3 as the registry always declared — and codeToGraph reads the widening back (`stripIntPromotions`, on EXIT, so a promotion inside it is read first): a single-argument `vec3(X)` that is a direct argument of `dot`/`normalize` is X — a real Vec3 node always emits three arguments — but only when X is what graphToCode widens (provably scalar, a comparison, a number): a hand-written `vec3(<vec4>)` NARROWS, and stripping it changed the value on Apply. An UNWIRED Normalize declares `v: 1` (registry and evaluator alike): `normalize(vec3(0))` has no direction, and WebGPU rejects the constant zero vector at compile time — a freshly dropped Normalize had taken the module down. Measured on both backends: dot(2, 3) → 18, normalize(2) → 0.577, a lone Dot → 0, a lone Normalize → 0.577, an Int into Dot → 0. Guard: `engine/vectorOnlyFns.test.ts`.

### Every input port needs a registry `defaultValues` entry unless 0 is genuinely its neutral value.

- **Every input port needs a registry `defaultValues` entry unless 0 is genuinely its neutral value.** `resolveArguments` (graphToCode) resolves an unwired port as stored value → `def.defaultValues[id]` → `chainIdentity` (chainable only) → the bare string `'0'`. That last fallback is silent and was wrong for six nodes: `clamp(x, 0, 0)` pinned the output to a constant, `remap(x, 0, 0, 0, 0)` divided by zero, `hsl(0, 0, 0)` rendered BLACK beside a card showing red (saturation 0 and lightness 0 each annihilate independently, so wiring a hue ramp — the node's whole purpose — still rendered black), `mix(0, 0, 0)` discarded a wired B, and `log2(0)`/`smoothstep(0, 0, x)` are hard **WGSL/Tint compile errors** that kill the entire module on the WebGPU preview path while GLSL merely degrades to undefined behaviour (which is why the damage looked machine-specific). All six now declare identities that MATCH `cpuEvaluator`'s own per-port fallbacks (and Normalize declares `v: 1` since 2026-10-28 — the previous section) — the evaluator's numbers were right all along and the registry simply never declared them. Two guards enforce it now: `engine/unwiredDefaults.test.ts` snapshots what every node emits unwired and asserts the RULES (log2's argument is never 0, smoothstep's edges differ, clamp's min ≠ max…), and `registry/builtinByteStability.test.ts` pins the emitted code of all 32 built-in textures/presets (8 + 24 — and it asserts that total EXACTLY, `toBe(32)`: as a floor it read `>= 23` long after 32 assets shipped, so nine could have vanished unnoticed), which is the check each of these fixes previously needed by hand. `registryDrift.test.ts` section (b) used to catalogue these as "deliberate divergences" — that framing is what hid the class, so it now asserts registry and evaluator AGREE. Deliberately left at 0: the vec constructors, eight of the nine unary maths, the comparisons, the chainable folds (they use `chainIdentity`), and `length`/`distance`. **`defaultValues` is the SOCKET LIST on PreviewNode/ClockNode/SoundNode-rendered nodes** (the 8 noise nodes, `time`, `soundNode`) — a key there becomes a wireable dead socket, so never add one for emission purposes. A unary can declare a default through the optional 4th element of the `.map()` tuple (`['log2', 'Log2', '…', { x: 1 }]`) rather than being lifted into its own def — registry ORDER is the add-menu tie-break — but `descriptionSplice.ts`'s `isStringTuple` must keep accepting that arity or the Node Designer silently loses the ability to rename it.

### `select`'s condition is a TRUTHINESS test, like Output.discard.

- **`select`'s condition is a TRUTHINESS test, like Output.discard.** three builds it as `bool(cond)` (ConditionalNode), so `0.2` takes the TRUE branch on the GPU; `cpuEvaluator` used `>= 0.5` and therefore showed the OPPOSITE branch for any condition in (0, 0.5) — a window noise sources land in constantly now that the editor remaps them to 0…1. Second instance of the trap already documented for Discard; if a third appears, look for a `>= 0.5` beside a `bool()`.

### `resolveExposedParam` consults the registry before its hardcoded `?? 1`.

- **`resolveExposedParam` consults the registry before its hardcoded `?? 1`.** It is the OTHER resolution path (noise `pos`/`scale`, the uv params) and never read `def.defaultValues` at all, so a node whose stored `values` are missing a key emitted `uv(1)` plus a full 1-radian rotation while the evaluator assumed 0. Unreachable from today's creation paths (both `newNodeValues` and codeToGraph seed `values` from defaultValues) — it is hardening for legacy graphs and hand-edited `.fastshader` input, and it matters more the more defs declare defaults.

### Emit `mix(a, b, t)` as a FUNCTION — never the `a.mix(b, t)` chain.

- **Emit `mix(a, b, t)` as a FUNCTION — never the `a.mix(b, t)` chain.** TSL registers the method as `mixElement = (t, e1, e2) => mix(e1, e2, t)` (three's `MathNode.js`), so **the RECEIVER lands in the FACTOR slot**. `color(lo).mix(color(hi), t)` therefore built `mix(highColour, t, lowColour)` — the low colour used as a per-channel blend factor and the scalar `t` as an endpoint. Verified by dumping the built node (`.mix` wraps its result in a VarNode; unwrap `.node`): the chained form gives `a=#ffd24d, b=SplitNode, c=#1b2a4a`, the function form `a=#1b2a4a, b=#ffd24d, c=SplitNode`. With a dark low end the output sat within ~2% of the high colour across the whole range, so **the Data Stripes / Data Viz ramp was effectively a constant and the low swatch did nothing**; the Stripes and Isolines moiré fades were inverted the same way. All four sites emit the function form now, `dataVizTslContract.test.ts` pins the operand ROLES structurally against the real `three/tsl` (a text assertion cannot catch this — the buggy source looks perfect), and `mix` is imported wherever they emit. **`mix` is NOT the only one** — this line used to claim it was, and that was wrong. Measured against the shipped r184: `a.smoothstep(b, c)` builds `smoothstep(b, c, a)` and `a.step(b)` builds `step(b, a)`, i.e. all THREE displace the receiver, while `a.clamp(b, c)` and `a.pow(b)` really are positional. (Nothing was broken by the error — Isolines' `.smoothstep(float(0.0), hw)` means `smoothstep(0, hw, d)`, which is what it wants — but the guidance was.) `dataVizTslContract.test.ts` now pins the free-vs-method operand roles for all three as executable fact. The safe rule when emitting a named function you have not measured: **write the free-function form**, which is positional for every one of them; that is why `utils/dataRangeFormula.ts`'s emitter never chains a named function at all. Check `addMethodChaining` before assuming any other one is positional.

### Alpha comes ONLY from the `opacity` channel.

- **Alpha comes ONLY from the `opacity` channel.** Everything that can leak into it is normalised in graphToCode: a source whose shape is `!== 3` wired to an ALPHA-BEARING channel (`color`, `emissive` — the two that reach `diffuseColor`; `emissive` counts because the loader copies emissiveNode→colorNode when no colour is wired — a rule from 0.5 that 0.6 and 0.8 carry (0.8 is the only vendored one)) is emitted as `vec3(ref)`. Both ends leak: `vec4(float)` SPLATS (alpha = the scalar) and `vec4(vec4)` is an IDENTITY (alpha = the source's `w`, and a fresh Vec4 node's w is 0 → fully transparent). Shape is read from the PORT the edge leaves (`shapeOfEdgeSource`, honouring `dynamicOutputs`), not the node — Data Viz is out:vec3 + value:float, so node-level inference reported 3 for its scalar `value` socket and skipped the widen. `normal`/`position` are deliberately NOT widened: they never reach alpha, and widening `position` would break the Data Viz `value`→Displacement flow, where normal-mode displacement needs the height to stay scalar. Other alpha traps closed at the same time: `depthWrite:false` used to LATCH (its checkbox renders only while Transparent is on, so unchecking Transparent stranded it) and is now cleared on that transition AND gated on `transparent` at emission — on an opaque mesh it self-occludes into cutout-looking holes; `alphaTest` is coerced+clamped to ≤0.99 (three discards on `alpha <= alphaTest`, so 1.0 erases everything) and never interpolated raw from an untrusted project block. The old both-directions import leak (previous graph's settings carried onto an imported plain `.js`, the incoming file's own settings stripped) is FIXED: `scriptToTSLWithSettings` returns the imported file's sanitized settings, `projectImport` applies them before the sync pass, and `mergeMatch` keeps old settings only when the new node carries none — with one deliberate consequence: a bare editor-TSL import (no return-object settings) now CLEARS the previous shader's material settings instead of inheriting them. What a bare-script import (Load Script) recovers is every `PART_SETTING_KEYS` key plus `mergeVertices`: `scriptToTSL`'s `MATERIAL_KEYS` is DERIVED from `PART_SETTING_KEYS` plus `'mergeVertices'`, so a key joining one joins both — the hand-written list had drifted when `flatShading` joined on 2026-09-18, and a top-level `flatShading: true` was neither read back nor stripped from the rebuilt return (`scriptToTSL.test.ts`). An explicit `mergeVertices: false` is read back (absent still means true), and offset `displacementMode` is recovered from which `positionNode` form the module spells, since both collapse to the same `position: x`.

### Discard is a TRUTHINESS test, not a 0/1 switch

- **Discard is a TRUTHINESS test, not a 0/1 switch** — `0.2` culls. It is emitted as a statement (`Discard(cond);` between the definitions and the return), lifted out by `extractDiscards` and routed through the tiny `__pixel` Fn, because `Discard()` needs an active TSL stack. Six things are load-bearing, each measured against three r184's real GLSL/WGSL builders (`bool(0.0)` is false, so a Float 0 correctly culls nothing — verified end-to-end in the app on both backends). (1) **The condition is shape-coerced to a scalar** (`scalarRefOf`) for every source EXCEPT the `logic` category: three compiles the condition as `bool(<ref>)` and widens a non-1-channel float to `all(<vecN>)`, which is declared only over bvecN/`vecN<bool>` — a real WebGL2 context answers `ERROR: 'all' : no matching overloaded function found`, so the whole fragment program fails to link and the mesh vanishes at EVERY value with nothing surfaced. Nothing validates connection types, so a Colour/Vec3/vec3-noise/Image source lands there routinely. Logic nodes are exempt because their vector output really IS a bvecN and `all(greaterThan(a, b))` correctly means "every channel passed"; narrowing it to `.x` would silently change the test. Scalars keep the plain ref, so every existing export is byte-identical. (2) **`cond.discard()` — the method-chaining spelling** (`addMethodChaining('discard', Discard)`) — is lifted too. It used to survive verbatim into the module, landing at plain-function scope where `.toStack()` has no stack and is a silent no-op: ZERO `discard` instructions in the compiled shader, in the preview AND the downloaded `.js`, with `codeToGraph` then dropping the line with no diagnostic so the next graph edit erased it. (3) **`extractDiscards` scans `maskNonCode(body)`** and slices from the original, so a discard inside a comment or a string is not code: scanning raw text ate the body of `/* Discard(a); */` while injecting a live cutout, and turned `const s = 'Discard(1)';` into `const s = '';` plus an unconditional cull — the mesh vanished because of a string literal. (4) **Only STATEMENT-level discards are lifted**; `const k = Discard(n);` is left verbatim (inert) instead of being sliced into a dangling `const k =` (a SyntaxError that took the module down). (5) **A bare `Discard()` is unconditional and carries NO Fn parameter and NO call argument** — passing the empty condition through emitted `__pixel(, …)`; `scriptToTSL`'s reverse walks the wrapper BODY rather than correlating args to params, or the unconditional form would vanish on Load Script. (6) The wrapper's fallback colour is `channels.color ?? channels.emissive ?? vec3(1,1,1)` and `Discard` is force-imported: the loader copies emissiveNode→colorNode only when colorNode is undefined and the wrapper always defines it, so white washed out an emissive-only shader the moment a discard was added. The graph has ONE discard socket, so `codeToGraph` warns (never silently drops) on a second `Discard()` or an unconditional one.

### Scalar→vec3 widening on Output channels

- **Scalar→vec3 widening on Output channels**: a 1-channel source wired to a vec3-typed channel (`color`, `emissive`, `normal`, `position`) is emitted as `vec3(ref)`, NOT bare. three's `NodeMaterial.setupDiffuseColor` does `vec4(this.colorNode)` and TSL splats a 1-channel node across all FOUR components, so a bare `mx_noise_float(...)` on Color silently became the ALPHA too (`diffuseColor.a = noise`) — the surface flickered/vanished as if Opacity or Discard were wired when neither was. Scalar-ness comes from `getNodeOutputShape` (cpuEvaluator), not the registry port type, so an `any`-typed arithmetic chain is caught as well. codeToGraph MUST mirror this: `unwrapScalarWiden` collapses a single-argument `vec3(<identifier|member>)` in a channel position back to a direct edge — unambiguous because a real Vec3 node always emits three arguments — or the round trip grows a Vec3 node with y/z = 0 and re-emits `vec3(x, 0, 0)`, turning a grey ramp red. Both sides are pinned (`graphToCode.test.ts` + a `roundTrip.test.ts` case). Vec3-shaped sources emit byte-identically to before.

### Unknown nodes

- **Unknown nodes**: unrecognized TSL functions in code→graph parsing create `unknown` nodes that store `functionName` and `rawExpression` in values. These round-trip through graphToCode: the stored text, with every identifier the call reads that named an existing node at the parse BOUND (one edge per name into socket `ref<i>`, the names in `values.refs`) and re-emitted as what its edge resolves to today (`float(0)` unwired), so deleting or reordering a node can no longer make the expression silently read another one (it also fixed the Wireframe node, whose `dFdx`/`dFdy` read undeclared names after any Apply); the text is parsed as JS, never TypeScript, and the rewrite is validated again before it is emitted; a graph with no `refs` emits verbatim, byte-identical. Every NAME in the text is on an allow-list (`engine/unknownExpression.ts`, rule 5) — a callee is a three/tsl export (less `NOT_SHADER_MATH`: the exports that call a JS function, read a string as a property path or take raw source) or a module helper, a member a swizzle or a TSL method, a name read one of those or a name the emitting module declares (the nodes the pass emits, plus the references it splices in) — because the deny-list before it let `Reflect.get(float, 'constructor')`, `'constr' + 'uctor'`, a property descriptor's `.value` and `float.call.bind` reach `Function` (review 2026-10-27, the payload ran); a made-up callee (`myHelper(…)`), which could only ever throw a ReferenceError, now makes the whole call `float(0)` too, while a READ of a name the module does not declare reads `float(0)` in its token's place (`neutralizeUndeclaredReads`): such a name is a global or a dangling one — the one-way Image node's Apply left `normalMap(image3)` reading an `image3` nothing declared, a ReferenceError that killed the shader — and in place the rest of the text survives and the next Apply is a fixed point, where the whole-call fallback became a Float node and relaid the graph out. A bound `out` wire whose reference is a member of the source's own variable (Fresnel `.x`, Color Ramp `.rgb`, a wide Image `.rgb`) re-emits the BARE variable: the parse binds `fresnel1` in `fresnel1.y` to `out`, so splicing `fresnel1.x` in grew `.x.y`, `.x.x.y`, … one per Apply (`unknownBinding.test.ts` sweeps every socket of every type for the fixed point). They render as magenta `vec3(1,0,1)` fallback in live preview, and show as orange warnings (not errors) in the code editor. The `unknown` definition lives in `NODE_REGISTRY` but is excluded from `allDefinitions` (hidden from content browser/search)

### `hsl`/`toHsl` are NOT `three/tsl` exports — graphToCode emits its own branchless helper `Fn` at module scope

- **`hsl`/`toHsl` are NOT `three/tsl` exports — graphToCode emits its own branchless helper `Fn` at module scope**, and force-imports the `mul`/`add`/`sub`/`abs`/`mod`/`clamp`/`select`/… that only the helper BODY uses (`HSL_HELPER_LINES`/`TO_HSL_HELPER_LINES`; the import collector explicitly skips these two defs, since importing the node's own name would fail). `codeToGraph`'s visitors run over the WHOLE Program, so it `path.skip()`s a `const hsl|toHsl = Fn(…)` declarator BY NAME — without it the helper's own mul/sub/clamp statements parse back as standalone nodes and every Apply grows the graph. Emitted name and skip name are a DRIFT PAIR the guard test cannot catch: `codeToGraph.test.ts` feeds a synthetic `const hsl = Fn(…)`, so renaming the emitted helper keeps it green while real round-trips explode. The general rule: **anything graphToCode emits at module scope is graph content to codeToGraph until explicitly excluded** — the same class as the image node's ban on an async IIFE (its ReturnStatement visitor would hijack the output), and the next hand-emitted helper needs its own skip.

### Module-scope helpers live in ONE table — `engine/moduleHelpers.ts`

- **Module-scope helpers live in ONE table — `engine/moduleHelpers.ts`** (2026-09-02, keyed by helper NAME since 2026-09-03). The hsl/toHsl drift pair above is now structural: a helper is a `{ lines, imports }` entry whose name is either a def's `tslFunction` (with `tslImportModule` `''`) or a VARIANT of a def carrying `alias: { type, ports?, values? }` — the helper a MODE selects (`values.mode`, see the helper-variant convention) or one picked by the wired position's WIDTH (Box). graphToCode records every CALLEE it emits and then emits those helpers in table order, force-importing their `imports`; codeToGraph skips any `const <name> = Fn(` declarator whose name is in `MODULE_HELPER_NAMES` and resolves a call to a variant (or to a LEGACY name of a folded node — `smoothUnion`) through `HELPER_ALIASES` to its owning def, stamping the alias's `values` and mapping the arguments by its `ports`. **Every helper name is RESERVED from the variable namer** (`usedNames` is seeded with `MODULE_HELPER_NAMES`): a node variable is `<base><n>` and `sdBox2`/`sdBox3` are helpers, so a second Box node used to be named `sdBox2` — `const sdBox2 = sdBox2(…)` shadows the Fn it calls and throws a temporal-dead-zone ReferenceError at runtime (measured). `moduleHelpers.test.ts` Babel-parses each body and fails on a free-function call the `imports` list omits, checks every key resolves to a def (directly or through its alias), and round-trips every distance-field node byte-identically. Bodies use FREE functions only — the `.mix()`/`.smoothstep()`/`.step()` receiver-displacement rule. Since 2026-10 the table also holds PLAIN-JS rows (`kind: 'js'`, next section), and the codeToGraph skip covers them by NAME whatever their initialiser — the `= Fn(` shape test alone would have walked straight into `fsLut`'s body.

### Plain-JS module helpers and canonical-string arguments

- **Plain-JS module helpers (`kind: 'js'`) are ONE `const` declarator each, skipped BY NAME, and their text may hold no three/tsl identifier outside their `imports`** (2026-10-08/09, Color Ramp and RGB Curves; text in `engine/lutHelperText.ts`, rows in the ONE table). `fsLut` is a shared core (`support: true` — no def names it; emitted only through another row's `requires`, which graphToCode expands before the table walk), `fsColorRamp`/`fsRgbCurves` call it. They are not TSL `Fn`s: they run ONCE at module load in every surface that runs a module (the sandboxed preview and its hot-swap, the export `.js`/`.zip`, podest, the XR popup), bake a 257×1 HalfFloat RGBA DataTexture per distinct key (cached, so equal ramps share ONE texture and ONE binding) and return the TSL sample node, `.level(0)` through the half-texel inset (`.level(0)` keeps Firefox's WebGPU uniformity analysis quiet inside non-uniform control flow; there are no mips, so the picture is the same). New rows are APPENDED, so no older module moves a byte. The constraints, each found by a probe through the REAL `buildShaderModule` + loader transforms, and each pinned (`moduleHelpers.test.ts`, `lutHelpers.test.ts`, `lutHelperLoaders.test.ts`, `codeToGraphJsHelper.test.ts`):
  - **One top-level `const <name> = …;`.** codeToGraph skips the declarator and `path.skip()` stops every visitor, so the helper's nested `return`s, assignments and calls are never graph content. A user's own `const fsLut = …` is replaced by ours on re-emit — the `fs` prefix (never a three/tsl export, never a trailing digit, which the variable namer could mint) is the mitigation, and every name joins `MODULE_HELPER_NAMES`, so it is reserved from the namer.
  - **No identifier-like token that is a three/tsl export outside `imports` — strings INCLUDED.** Loader 0.8's `autoInjectTSLImports` scans the whole text, strings and all: `typeof x !== 'string'` injected a spurious `string` import in the first probe (`string` IS an export). Local names must avoid exports too (`ior` is one — Fresnel's parameter is `eta`). `tslTokenHits` (`src/lutHelperHarness.ts`) is only a fast LINT; the binding pin runs the real `transformsOf(v)` for every `ACTIVE_LOADERS` version and asserts nothing is injected and `fixTSLShadowing` is a no-op.
  - **No `import {`, `params.<ident>`, `const X = uniform(`, `Fn(() => {`, regex literal, `uv(` or geometry global**, no declared `THREE`, and three is reached only as `globalThis.THREE.*` (rewritten to the imported namespace like the Colormap setup lines) — the loader's own scans and the splat sweep key on those spellings.
  - **No SHORTHAND object property** (`{ half }`): `fixTSLShadowing` renames value references with a regex that also hits a shorthand key, so a future three/tsl export named `half` would silently turn `fsLut.half` into `undefined`. Always `{ half: half }` (a Babel walk pins it).
  - **The text must parse cleanly with codeToGraph's EXACT options** (`errorRecovery: true`, `typescript`): an `a < b … >` run goes through the type-argument lookahead and a recovered error is SILENT, so a round trip alone would not show it; `codeToGraphJsHelper.test.ts` asserts `ast.errors` is empty.
- **Color Ramp and RGB Curves round-trip through a canonical STRING argument RE-FORMATTED from the parse** — `fsColorRamp(fac, "0 #000000 1,1 #ffffff 1", "linear")`, `fsRgbCurves(col, fac, "0 0,1 1", …, "extrapolate")` — the Data Range formula's parse-then-re-emit design. The stored string is parsed by the ONE grammar (`utils/pointListCodec.ts`, mirrored char for char by `fsLut.unit/hex/word/rows`), and the emitted string is ALWAYS `format(parse(stored))`, whose alphabet is `[0-9.#a-f, ]` — it cannot close the `"…"` literal or a comment, or carry `</script>` or U+2028 (fuzz-pinned), so injection is unrepresentable rather than filtered. `hexToken` tests EXPLICIT code ranges: the `charCode | 32` shortcut accepts U+0010–U+0019 as digits and would have emitted `\u0010` into the module. A string the reader rejects bakes the default and the generated code SAYS so in a comment. The editor-side readers compare CANONICAL to canonical, so a valid but non-canonical stored string (uppercase hex, `0.50`) never costs an empty undo entry.
- **`HELPER_ARG_READERS`** (codeToGraph): a per-type reader takes the call's non-socket arguments (Fresnel's implicit geometry, the canonical strings), stores them in `values` and returns only the SOCKET arguments, in port order, to the generic loop. Every message quotes at most 80 characters of user text (`argReporter`) and is a WARNING — Apply is never blocked. A helper called as a method (`x.fsColorRamp(…)`) warns and reads no settings.
- **Own-member sockets**: Fresnel (`.x`/`.y`) and Color Ramp (`.rgb`/`.a`) address their sockets as members of ONE call, like toHsl. graphToCode's `FRESNEL_HANDLE_TO_MEMBER`/`COLOR_RAMP_HANDLE_TO_MEMBER` and codeToGraph's inverse `OWN_MEMBER_TO_HANDLE` are a drift pair (Maps, so a tampered `__proto__` handle reads the head member); `resolveMemberExpr` consults the inverse before swizzle validation, EXCEPT for an alias (`const f = fresnel1.y; … f.x`), which already names one socket and is a swizzle of it (`varToHandle`). `ownMemberConsumers.test.ts` sweeps every consumer socket against every own-member source and fails on a wire an Apply drops.
- **`scriptToTSL` keeps every table helper** (the `.js → editor` path): it used to keep only `hsl`/`toHsl` declarations, so an imported module calling Brightness/Contrast, a distance-field helper or `fsColorRamp` referenced an undefined helper. It now matches every `MODULE_HELPER_NAMES` declarator (`= Fn(` or `= (`) and counts braces on the MASKED line. A kept plain-JS helper stays verbatim, so it reads `THREE.*` and the `three/webgpu` namespace import is kept with it.
- **Remaining costs, accepted**: the helper text is large in the code panel (~230 lines with both LUT nodes); each distinct ramp/curve set spends one sampled-texture binding (16 per stage on WebGPU, shared with Image/Colormap/Data/env) — counted PER MATERIAL by `engine/textureBudget.ts` — only what each material reads, through the body's definitions, so an unconnected node or another material's table never counts; a table by its `fsLut.make` key, which graphToCode takes from `rampTableKey`/`curvesTableKey`, the ONE TS spelling of the key the helper text computes (`lutHelpers.test.ts` runs the emitted helpers and finds each texture under it; graphToCode had re-spelled both keys) — and announced by a comment above the shader Fn from 16 on (three binds its own DFG lookup table on a lit material, so 16 module textures already bind 17), so no module under the limit moves a byte; hot-swaps create DataTextures nothing disposes (as Colormap). GPU compilation of `.level(0)` and the six-fetch curve expression is proven only in a real browser (WebGPU and WebGL2), never in vitest — three's node builder needs a renderer.

### Imperative TSL (`Loop`, `If`, `.assign`) needs an ACTIVE STACK, and the module the loader runs has none

- **Imperative TSL (`Loop`, `If`, `.assign`) needs an ACTIVE STACK, and the module the loader runs has none** (measured 2026-09-02 against singularity's black-hole raymarcher). `buildShaderModule` strips the outer `Fn(() => {` and shaderloader calls the default export as a PLAIN FUNCTION, so a `Loop(...)` or `acc.assign(...)` at body level is a silent no-op — three warns "No stack defined for assign operation" only in Node; the preview just shows the un-looped constant. That is the same fact the `__pixel` Discard wrapper already encodes. An imperative block therefore has to be a **self-invoked `Fn(() => { …; return v; })()`** — one const in the flat chain — and that is the shape a future raymarch/loop node must emit. Two things were fixed to let that shape live: `parseBody` used to match `^return` on EVERY line and so hijacked the nested Fn's return as the colour channel (deleting it from the body and leaving the Fn void — a `getTypeFromLength` crash in the minified bundle); it now counts brace depth on the masked body (`nestedFnReturn.test.ts`). And `codeToGraph` used to drop a `Loop`/`If`/`Switch` statement in SILENCE while walking INTO its callback — the body's `const`s became flat top-level nodes, every accumulator aliased to its initial value, and the next Apply re-emitted a constant with `errors: []`; it now warns and `path.skip()`s the whole block (root callee resolved through an `If(...).Else(...)` chain) and warns on `.assign`-family statements naming the variable (`loopStatements.test.ts`). Still true and deliberate: the GRAPH cannot hold a loop (`isSafeExprNode` refuses arrow functions in an `unknown` node — unknown = pure data expression), so pasted imperative code survives in the preview only until the next graph→code sync overwrites the panel. Known side bug, unfixed: an `unknown` node's `rawExpression` keeps the ORIGINAL local names (`step(rLen, 0.13)`) while the re-emit renames `rLen` → `length1`, so the module throws `rLen is not defined`.

### A zero-input node's `defaultValues` KEY ORDER is a positional codegen contract in BOTH directions, and nothing…

- **A zero-input node's `defaultValues` KEY ORDER is a positional codegen contract in BOTH directions, and nothing in `nodeRegistry.ts` says so.** graphToCode's generic `inputs.length === 0 && def.defaultValues` branch emits `Object.keys(def.defaultValues)[0]` as the sole constructor argument (`graphToCode.ts`), and codeToGraph maps call argument `i` onto `Object.keys(def.defaultValues)[i]` — using that key as a real port id, so an identifier argument gets an EDGE wired to it. So the constructor value must stay FIRST: `slider`'s `{ value, min, max }` and `property_float`'s `{ value, name }` are the two multi-key defs riding on it today, and any future zero-input def joins them. Alphabetizing the literal or prepending a key is a tidy-up edit that silently changes what the node emits and what a parsed literal is stored under — `slider` would emit its `min`. The test pin covers float/int/slider/color only, so a reordered `property_float` passes CI. Order-INDEPENDENT and not to be confused with these: `property_color` is matched by name in a dedicated branch on both sides, the noise family's `{ pos, scale }` is wired by name in `processNoiseCall`, and `uv` declares real `def.inputs` so it never reaches `defaultKeys`.

### A baked lookup texture that is SAMPLED LINEARLY must be `HalfFloatType`, never `FloatType`

- **A baked lookup texture that is SAMPLED LINEARLY must be `HalfFloatType`, never `FloatType`**: WebGPU refuses to filter 32-bit float textures without the `float32-filterable` device feature, which the A-Frame bundle never requests — so a float32 LUT looks right on the WebGL2 preview and breaks only on WebGPU (exactly the split the WGSL/GLSL toggle exists to expose). `bakeHalfFloatTexture` (graphToCode) is the shared emitter for every linearly-sampled bake — the Stripes phase ramp, the Data-Viz value ramp, the 256-texel colormap LUT — and the phase ramp is normalized to [0,1] before encoding so float16's ~11-bit mantissa stays smooth. The Data node is the deliberate exception: it wants EXACT per-column values, so it keeps `FloatType` + Nearest, which needs no feature flag.

### `codeToGraph` is reached through DYNAMIC imports from the sync engine, the store and the import path

- **`codeToGraph` is reached through DYNAMIC imports from the sync engine, the store and the import path**: `useSyncEngine.doCodeSync`, the store's `instantiateBuiltinTexture` / `instantiateBuiltinPreset` (building either library runs every snippet through `codeToGraph`, and the store is loaded by every page, `node-editor.html` and the Node Designer included), `engine/projectImport.ts`, and the parser alone in `engine/unknownExpression.ts`. codeToGraph is `@babel/parser` + `/traverse` + `/types`, ONE `vendor-babel` chunk. The dynamic imports keep Babel out of those CALLERS, not out of `index.html`'s entry wave — ContentBrowser imports the built-in libraries statically; the measured sizes and preload lists are the bundle bullet of platform-and-release.md. Three details are load-bearing. In `doCodeSync`, `setSyncInProgress(true)` stays ABOVE the await, so a graph edit inside the fetch window cannot regenerate the text being parsed. The import is caught APART from the parse: a rejected chunk fetch (a connection drop, a redeploy swapping hashed assets) would otherwise be an unhandled rejection with Apply silently doing nothing. And the two store actions use `.then`, not an async body, so they still return `undefined` and the failed fetch is caught there; the drop is not visibly deferred, since the content browser has already rendered the tile out of the same module and the import resolves in a microtask.

### The code panel shows only the nodes that feed an Output, and an Apply carries the rest

- **The TSL panel shows only the nodes that FEED AN OUTPUT** (owner, 2026-10-27; `engine/panelCode.ts`, `utils/panelCarry.ts`). A chain wired to nothing stays on the canvas but is not in the panel's text — and so not in `previewCode`, the preview, or the module a save writes, which is the same picture without dead code (a Time node in a dead chain no longer keeps the preview drawing continuously, and an unwired Image no longer crosses into the sandbox). "Feeds an Output" is `feedsAnOutputIds`: every sink, parked ones included, and everything upstream of one on the UNWRAPPED edges — EXPORT's `connectedExportIds` is that set plus the expansions that keep a FILE intact (frames up the parent chain, a collapsed group whole, board notes), which emit nothing. A node an `unknown` expression reads is upstream through its bound-reference edge (`ref<i>`), so it counts. No sink at all shows the whole graph, as EXPORT keeps everything then. **A study session keeps the whole panel** (`panelCodegen(…, isEvalMode())`): a running study measures the editor its participants started with.
- **It is an EMISSION scope, never a pruned graph.** `graphToCode(nodes, edges, registry, { emitOnly })` claims every name over the whole graph first and only then narrows `nodes`, `edges`, `sorted` and the graph index to the kept set. Generating from a pruned graph (EXPORT's way) RENAMES survivors — `speed2` becomes `speed` once the node holding `speed` is hidden — so every wire or unwire of an unrelated chain would move the canvas headers (`nodeVarNames`), the `fs:previewUniformValues`/`Bounds` keys, `fs:uniform-authored` and the Sound pump's `sound1_*` names. The narrowing is sound because the set is upstream-closed: every feeder of a kept node is kept, so no in-edge read changes. Only out-edge reads change, and each SHOULD forget a hidden consumer — the imports, an orphaned property, an Image's wide sample and its sky-only test (a picture wired to Environment and to a dead node is now uploaded the sky way, as `'connected'` EXPORT already did), the Data columns and Sound channels emitted, and the custom-sink partition (a scope node that also fed a dead consumer no longer gets a flat copy). A shared Image texture moves to the first KEPT node (`_image2_tex`, `fs-asset:imgB-…`), which is safe because the asset feed maps every node. The guard `sorted.some(n => !emitOnly.has(n.id))` makes a set that hides nothing a no-op; a set that leaves out only frames and notes narrows and still emits the same bytes (both pinned over every built-in by `engine/panelCode.test.ts`, which also pins identical `varNames` and a clean parse with a dead chain added). `result.varNames` is always the whole graph's map.
- **EXPORT's equality check accepts the panel's text.** `planExportGraph` regenerates a pruned module only when the panel holds the graph's own codegen; it compared against the WHOLE pass alone, so the pruned panel failed it and EXPORT silently exported the whole canvas with `omitted: 0`. It now accepts either text, and keeps re-keying uniforms from the whole graph's names — which are the panel's names too.
- **An Apply carries every node the text never held.** The store's `codeEmitted` is the emitted set, written in the SAME `set()` as `code` by `setCode(…, 'graph', …, { emitted })`; typing keeps it, a study and a graph with no sink write null, and the bare-script import nulls it (that text was not generated from this graph). `doCodeSync` reads it before pairing: `panelCarryIds` is every old node outside it except frames (the group block keeps those) and sinks (all emitted; a parked one is `carryInactiveSinks`'). Those ids are excluded from `pairResyncNodes` — the type-only pass otherwise handed a parsed Perlin the id of a HIDDEN Perlin listed first, and the connected one was deleted — and `carryPanelHidden` brings them back with the wires INTO them from a carried or parsed node (unwrapped; one per socket; a wire whose feeder was deleted from the code is dropped and the socket left unwired, not spliced). The carry sits BEFORE the layout decision: a node typed in the panel relayouts the graph, and the hidden nodes are laid out with it, losing their frames (positions are absolute then) — unlike the orphan, parked-sink and light carries, which stay inside the `unpositioned.length === 0` gate because they cannot tell a typed node from a different document. This one does not need to: a carried wire is bound BY NAME (below), so a shader pasted over the panel keeps the hidden nodes and binds their wires as if their lines were still in the text — a feeder name the paste does not declare leaves the socket unwired; only an import nulls `codeEmitted` and carries nothing. Notes are carried too, which ended the old "Apply deletes every note" outside a study. After a successful Apply `codeEmitted` becomes the PARSE's ids: nothing regenerates the panel on purpose after an Apply (`syncSource` is `'code'`), so with the pre-Apply set a node typed in one Apply and deleted before the next would be carried back. `mergeMatch` also keeps a paired node's `selected`, so a selection survives an Apply (not in a study, whose Apply stays the one its sessions met).
- **The text's names are its nodes' identities** (review 2026-10-27). The store's `codeNames` is written with `codeEmitted` — the pass's `varNames`, hidden nodes' too (names are claimed over the whole graph); after an Apply, each parsed node's label, which is its declared name. `pairResyncNodes` pairs by them FIRST (pass 0: a parsed node declared under the name an old node of its type had), so ids follow the lines rather than the array — two Adds no longer swap ids when the array lists them out of text order. `carryPanelHidden` re-attaches a carried wire through `panelFeederResolver`: the parsed node declared under the name its OLD feeder had, whatever its type now (`add` retyped to `sub` still feeds the hidden Multiply; a retyped feeder must still have the socket), never the old id, which type-only pairing may have handed to another node or to a pasted shader's. The final array goes back to the old order (`inOldOrder`, before the group block): it is the namer's order (`topologicalSort` queues roots by it), and appended carried nodes renamed the parsed ones on the next pass — an unchanged Apply changed the panel's text. All three are off without a scope, so a study's Apply is untouched.
- **A keystroke on an older pass's text takes that text's scope back.** Monaco shows the SETTLED text, up to `CODE_SETTLE_MS` behind the store; a keystroke inside that window edits the older text while `codeEmitted` describes the newer one, so an Apply duplicated the nodes the newer pass hid and deleted the ones it revealed. The store keeps the last four passes' scopes (`codeScopes`, `{ code, emitted, names }`), CodeEditor passes the text Monaco showed as `setCode`'s `base`, and a typing write whose `base` is one of them swaps `codeEmitted`/`codeNames` back to it. An Apply and an import clear the ring.
- **What it does not do.** A hidden node's name typed into the panel parses as an unwired node with no warning (it is shown on its canvas header, so it is typeable). A line the user types that feeds no Output disappears from the panel at the next regeneration (it stays on the canvas, carried). Pasting a whole different shader keeps the old unconnected nodes — they were never in the text, so the paste cannot have deleted them. The A-Frame and Three.js tabs derive from the pruned module, but their uniform rows still come from the whole graph's property list, deliberately: `buildShaderModule`'s dedupe mirrors `claimName`, and filtering the list would declare `speed` for a node whose variable is `speed2`.


### `nodeSpans` is bookkeeping, never emission

- **Every pass also says which part of the module each node wrote** (owner, 2026-10-27: "highlight the whole code for the node"; `GeneratedCode.nodeSpans`, `engine/codeSpans.ts`), for the code panel's node → code highlight (graph-and-store.md, `codeNodeSpans`). It changes no byte: the module is assembled line by line instead of from one array literal, and the same text comes out (every byte-stability snapshot and `engine/nodeSpans.test.ts`'s sweep over every built-in and every registry type, wired and unwired, hold it).
- **A line belongs to the plan iteration that PUSHED it** — never to a name scan, which cannot tell `float1` from `float10`, a node from a property of the same name, or the march's own `pos` from a node's. Each turn of the body loop opens a mark over `bodyLines` and `setupLines` at its top (every `continue` passes through there) and the next turn closes it. A shared Image's module-scope setup is pushed in its OWNER's turn, so the sharer owns its sample line alone. The marks are taken AFTER the `emitOnly` narrowing, so a node the panel hides has no entry at all, and neither does a node that wrote nothing (an orphaned property, an unconsumed Sound or Data node, a non-contributing Output).
- **A custom-sink scope counts only where `pushScopeFn` copied it.** `pushScopeFn` records where each scope array's chain landed (`scopeAt`); the splat's shade passes its ORIGINAL array as the origin, because its chain is a copy with the Splat Output's own `sp<n>Light` line appended, so that line is the sink's. A scope whose Fn was never emitted (a Field wired from a dead Split) gives its marks no span. The sink owns its program MINUS those chains, plus its discard and return lines.
- **The return line is shared once `parts` exist**: each Output owns its COLUMNS of it (the default's channels, each `"name": { … }` and `"<index>": { … }` entry), found by a forward search from a running cursor — exact, since every entry starts with its key's `"` and nothing between two entries holds one. Without `parts` the default Output owns the whole return line; the red sentinel of a module with no Output is nobody's.
- **A Split owns its READS** (`use` spans): it emits no line, its swizzle is inlined into each consumer, so each occurrence of the reference it resolves to inside the consumer's own text is marked (a whole reference only — `x.x` is not the start of `x.xy`). Split → Split resolves to nothing, so it reads nothing.
- **Positions are counted in the JOINED module by Monaco's line rule** (`\r\n`, `\r` or `\n`, one break each), from offsets, never from array indices: an `unknown` node's verbatim `rawExpression` may hold line breaks of its own, and every later line would be off by that many.
