### The supported browser floor is Chrome 111 / Safari 16.4 / Firefox 126, and each engine is held there by a DIFF…

- **The supported browser floor is Chrome 111 / Safari 16.4 / Firefox 126, and each engine is held there by a DIFFERENT feature** (measured 2026-09-08 against the built `dist/`, not inferred from caniuse). `build.target` is `esnext` with no polyfills and nothing transpiled down, so the floor is simply the newest thing actually used — which means it MOVES the first time someone reaches for a newer CSS function or JS syntax, silently, with a green build. The three that set it today: **`color-mix()`** (CostBar.css, Chrome 111 / Safari 16.2 / Firefox 113) — the newest CSS in the codebase and the ONLY thing holding Chrome that high, but it carries an explicit `rgba()` literal on the line above, so below 111 the app is whole and a drop-target tint is flat; **ES2022 class static blocks**, which `monaco-editor` 0.55 ships and Safari did not take until 16.4 — the one HARD break; and the non-standard **`zoom`** (NodePreviewCard.css / ContentBrowser.css / GraphsPage.css), which Firefox did not implement until 126, below which every asset tile renders at 1/0.67 and is clipped by the strip (that file's head comment explains why no `@supports` fallback was attempted). A fourth rides AT the floor without setting it: the preview pane's fullscreen styling is the unprefixed `:fullscreen` alone (ShaderPreview.css carries no `:-webkit-full-screen` twin), which Safari has from 16.4, while the JS keeps the webkit-prefixed request/exit/element fallbacks. **The Safari case is the one to remember, because it does not look like a browser problem**: `static {}` appears ONLY in the `monaco` chunk and the editor worker — verified by grepping every built chunk — and CodeEditor is `lazy()`-imported (AppLayout.tsx), so nothing on the boot path needs ES2022. Safari 16.2 therefore boots the app, renders the canvas, and fails when the CODE PANEL is opened. index.html's boot watchdog cannot help there: it speaks only while `#root` is still empty, and React mounted. That watchdog (a bilingual "the browser is too old" note, shown after 15 s and taken back down if a slow boot arrives) is the ONLY enforcement anywhere — nothing feature-detects, deliberately, because every candidate test has browsers where the app boots and stays useful and blocking those would be a regression. The numbers are stated for READERS in three places and are a drift set: index.html's fallback text (bilingual, user-facing), README's Browser support table, and here. `public/eval/index.html` deliberately restates NONE of them — it `location.replace`s to the app, so a study participant on an old browser gets index.html's note by construction, and a fourth copy of the numbers would only rot.

### Offline/desktop

- **Offline/desktop**: the app must run with NO network. Monaco is bundled locally (`CodeEditor/monacoSetup.ts` — `loader.config({ monaco })` + Vite `?worker` workers; never reintroduce the jsdelivr CDN loader) and fonts are self-hosted (the `@fontsource/inter` + `@fontsource/jetbrains-mono` weights are ONE import list, `src/styles/fonts.ts`, imported by every entry — `main.tsx`, `nodeEditor.tsx`, `nodeDesigner/main.ts` and, since 2026-10-23, `compare/main.tsx` — and it is LATIN + LATIN-EXT ONLY: the bare `@fontsource/inter/400.css` entry declares all seven Google subsets (cyrillic, cyrillic-ext, greek, greek-ext, latin, latin-ext, vietnamese), which put 24 woff2 files / 162 KB into dist that no user downloads — uploaded by psftp on every deploy, committed to gh-pages and bundled into both installers. Latvian diacritics are U+0100–U+017F, inside latin-ext; the accepted trade is that a Cyrillic or Greek mesh name or note falls back to a system font. The `fs-fontsource-woff2-only` vite plugin strips the legacy `.woff` fallback `src` from the vendored @fontsource CSS at build time so only the woff2 subsets ship — never reintroduce a jsdelivr/Google-Fonts CDN link). `FS_DESKTOP=1` — set automatically for `tauri dev`/`tauri build` via the CLI's `TAURI_ENV_*` env — switches vite to the desktop profile: base `/`, CSP meta suppressed, ShaderCarousel excluded from dist (it ships instead as a Tauri resource staged in `src-tauri/carousel-dist/`, served over LAN by the in-app bench server — see the src-tauri bullet under Subprojects), and the `__FS_DESKTOP__` define hides the "Download app" button + SC link and shows the "VR" bench popover. The desktop build also raises the size caps — 6M chars per image (the one figure still under the unchanged 8M per-image hard ceiling, which bounds every single payload on both builds), 32M per project and library, a 256 MiB zip read — through `utils/platformCaps.ts` and zipReader's `READ_*` constants. vitest always runs the WEB profile, so desktop values are tested only through the `DESKTOP_CAPS` table or an explicit parameter, and every web cap is pinned unchanged. Preview-iframe asset URLs resolve via `new URL(base + path, location.href)` (`resolveAssetUrl` in `tslToPreviewHTML.ts`) so they survive non-http schemes (tauri://) — don't revert to `location.origin` concatenation.

### Bundle chunks and what each entry preloads

- **Bundle chunks and what each entry preloads** (measured in the built `dist/`, 2026-09-29). Vendor code is split by package prefix (`manualChunks`, `vite.config.ts`), so a release rehashes the app chunk and not the vendor ones. **`vendor-babel` is 805 KB raw / 204 KB gzip, and NO entry modulepreloads it**: every path the app has to `@babel/*` is an `import()` — `codeToGraph` (`hooks/useSyncEngine.ts`, `engine/projectImport.ts`), `scriptToTSL` (`engine/projectImport.ts`), the parser (`engine/unknownExpression.ts`), and the two built-in libraries, which build through `registry/codeGroupBuilder.ts` → `codeToGraph` (the store's `instantiateBuiltin*`, and the content browser, which fetches both when the Presets or Textures tab opens or a search settles: 229 KB gzip in five chunks, once). **A lazy import buys nothing while ONE static path to the same module survives**: until 2026-09-29 the content browser imported the libraries statically, which put `vendor-babel`, `codeGroupBuilder` (then holding `codeToGraph` AND `graphToCode`), `builtinPresets` and `builtinTextures` on the entry wave — 244 KB gzip of 760 — while every other caller carried a comment saying its `import()` kept Babel off it. 228 KB of that left the wave; `graphToCode` is boot-path and stays, as a chunk of its own. `src/bootWave.test.ts` now walks the static import graph from `main.tsx` and fails, printing the chain, on any path to a Babel-bearing module; the one thing the content browser needs at module scope (the texture ids) lives in the leaf `registry/builtinTextureIds.ts`. `index.html` modulepreloads `vendor-react`, `vendor-xyflow`, `preload`, `vendor-dagre`, `tokens`, `graphToCode` and `builtinTextureIds`: 532 KB gzip / 1611 KB raw with the entry chunk. `vendor-dagre` (42 KB raw / 15 KB gzip) STAYS on it: `engine/layoutEngine.ts` has three static importers (the store's `organizeSelection`, `useSyncEngine`, `gltfSectionBuilder`), so `projectImport`'s `import('./layoutEngine')` defers nothing. Two costs of the move: the first open of either tab, or the first search, waits for that fetch with the strip EMPTY (no message: nothing has been searched yet), and a failed fetch leaves it empty. The content browser asks again on the next tab or query, but Chrome answers a module URL that failed once from its module map, without a request (measured), so there a reload is what recovers. `node-designer.html` modulepreloads `vendor-react`, `preload`, `vendor-xyflow`, `vendor-dagre` and `tokens` only; it reaches `vendor-babel` solely through dynamic imports (`descriptionSplice` for a folder-link rename; `builtinTextures`/`builtinPresets` via `codeGroupBuilder`). **A third input moves the shared chunks** (measured 2026-10-23, `FS_BASE=/` builds before and after the device-comparison entry): the chunk the app and the Designer had shared splits, so `index.html` now also modulepreloads `NodeVisual` and `reset` (and their stylesheets) as chunks of their own, about +2 KB gzip on the boot wave, and `node-designer.html` gains `NodeVisual`, about +1 KB; `compare/index.html` loads `vendor-react`, `tokens`, `reset` and its own chunk — 7 files, about 150 KB gzip — and none of them holds a store string (next section).

### The device-comparison page is its own Vite entry at `<base>compare/`, and it never boots the store

- **`compare/index.html` is the THIRD Vite input** (`compare` in `rollupOptions.input`, beside `main` and `designer`; owner request, 2026-10-23): a DIRECTORY entry at the repo root, built to `dist/compare/index.html`, so every host serves it at `<base>compare/` — `https://fs.sferas.lv/compare/`, `https://alvismisjuns.lv/fastshaders/compare/`, `https://alvis1.github.io/FastShaders/compare/`, and `http://localhost:5173/FastShaders/compare/` in dev. It lists, for every node a user can add, what a fresh one costs on each chosen device, in points of a budget that prints as 100 everywhere (storage-and-limits.md), beside a smaller signed difference from the first column. A real entry and never a `public/` copy: Vite copies `public/` verbatim, so a `public/compare/` would ship beside the built page and shadow it (the Node Designer's lesson; `compareEntry.test.ts` fails if one appears). Both HTML plugins transform every entry — their `transformIndexHtml(html)` hooks take the html alone, so no per-entry filter can creep in and skip it (pinned) — so the page carries the same CSP meta and `%APP_VERSION%` version meta as index.html. Its pre-paint guard stamps theme and language by index.html's rules (dark only for `fs:codeEditorTheme` `'vs-dark'`, `lang="lv"` only for the exact stored `'lv'`), with tokens.css's `--bg-app` as the inline background. It imports `styles/fonts.ts`, tokens and reset like every entry and needs no `nodeEditorBootstrap`, since it never imports the store. The desktop build EMITS it too (the input is unconditional), but nothing in the desktop app links to it.
- **The slash-less URL redirects.** Static hosts redirect `<base>compare` to `<base>compare/` natively (GitHub Pages, nginx on fs.sferas.lv, Apache on alvismisjuns.lv). Vite's dev server served the slashed URL from `compare/index.html` but answered the bare one from its SPA fallback — a 200 with the EDITOR, the same silent dev-only miss `publicEntryDevIndexPlugin` exists for on the study redirectors. The serve-only `entryDirDevRedirectPlugin` (`ENTRY_DIRS = ['compare']`, a drift pair with the input, both pinned by `compareEntry.test.ts`) answers it with a 301 that keeps the query — a redirect rather than a rewrite, because a page answered at the slash-less URL would resolve its relative links one directory too high.
- **It never boots the store** (CLAUDE.md, Platform). The store's module scope applies the selected device to the shared price table (`setCostOverrides`, `setDeviceBudget`) and arms the graph autosave, and `utils/nodeCost.ts` sits in the store's import cycle — so `compareModel.ts` (the pure half; the page is `ComparePage.tsx`) prices each column with its OWN table: `freshNodeCostUnder(type, costOf)` (`utils/typeCost.ts`, the store-free half of the type price) over the shipped table with that device's sanitized prices laid over it, divided by that device's own `maxPoints` (`toBudgetPoints`), never `getDeviceBudget()`. The device rows come from the leaf `registry/vrHeadsets.ts` (moved out of the store, which re-exports it) and from this browser's `fs:costProfiles` through `parseStoredCostProfiles`, the ONE reader the store boots from too. `bootWave.test.ts` walks `src/compare/main.tsx`'s static imports, checks that the walk really reaches the pricing modules (so the guard is not vacuous), and fails, printing the chain, on any path to `store/useAppStore.ts`, `utils/nodeCost.ts`, a Babel-bearing module or `@babel/*`.
- **A cell is exactly the editor's palette tile** for that device: a FRESH node's price, as its share of the device's 100 (`compareModel.test.ts` pins the equality for both built-ins and a stored profile), printed through `<Points>`. Every non-reference cell carries a smaller signed difference from the first column, the reference: red `+x` for more, green `−x` (U+2212) for less, taken from the UNROUNDED values and rounded and marked like any figure, with a signed exact tooltip; |d| ≤ 1e-9·max(1, |a|, |b|) counts as equal and prints nothing. A device whose budget is not 200 differs on every priced node. The two colours are page-local (`--cmp-more`/`--cmp-less` in compare.css: #BF360C/#33691E light, #FFAB91/#AED581 dark) — the cost gradient's poles darkened to at least 4.5:1 for 10 px text, since tokens.css has no green and `--cost-high` is 3.2:1 on white. A row whose CANVAS price is not the fresh one carries a `*` and a tooltip saying why: Add/Subtract/Multiply/Divide (base × (operands − 1)), Image (a resolution discount down to ×0.5), RGB Curves (1 as identity, more once a curve bakes) and the SDF Output (its fields are charged again on every ray step) — each note pinned against `nodeCostPoints`. Rows are every node a user can add that the table prices, minus the plain Output, plus the Data node (a CSV drop makes it), whatever this browser's optional-category switches say, grouped in `CATEGORIES` order (the Add-node menu's); a search matches names, TSL functions, the `Also:` alias tail and category names, and "Only differences" keeps only the rows where some column differs from the reference.
- **Choosing devices**: the built-in headsets (no mark; Steam Frame's tooltip names its run), this browser's stored profiles (◆ measured, ⚠ invalid run, ✎ hand-authored, as in the cost bar's dropdown; the first of an id wins, a stored id equal to a built-in's is left out, at most 100 are listed, and labels are stripped of control and format characters and cut to 60 code points), and profile files dropped on the page or picked with "Add a profile file…" — `parseCostProfileBundle`, then `parseCostFile`, then `profileFromParsed` against every listed profile, so a bench export inherits `VR_HEADSETS[0]`'s budget; session-only, at most 20 files per drop, 4 MB each and 100 file devices. A device chip toggles its column (at most 8, `MAX_COLUMNS`; chips past the cap are `aria-disabled` with a tooltip that says so), and "Make reference" moves a column first. **The selection is the LINK**: `?d=<id>,<id>` — each id `encodeURIComponent`'d, since a derived profile id can hold a comma; the first `d` wins; unknown, malformed or over-200-character ids are ignored, and no usable id means every built-in — written with `history.replaceState` only when the viewer changes the selection, so arriving on a link never rewrites it. A dropped file never rides the link.
- **It writes NO storage key** (`compareEntry.test.ts` fails on a `setItem`/`removeItem`/`clear`, `sessionStorage` or `indexedDB` under `src/compare`): it READS `fs:costProfiles`, `fs:lang` and `fs:codeEditorTheme`, and a `storage` event from an editor tab updates the profile list live and drops a deleted profile's column.
- **How it is reached and verified**: the cost bar's "Compare devices…" row opens it in a new tab, in the web build and outside a study session only (storage-and-limits.md, Profiles). Pages publishes it with the rest of `./dist`, and **both host deploy scripts curl `<base>compare/` after the upload** (`scripts/deploy-sferas.sh`, `scripts/deploy-alvismisjuns.sh`) and fail unless it answers 200, carries its OWN title text — "Device comparison", because a host falling back to index.html would answer 200 at the right version too, which is why the static `<title>` stays English — and serves the version just built; `compareEntry.test.ts` pins both scripts' checks.

### Feedback ("!" toolbar button)

- **Feedback ("!" toolbar button)**: the red `!` in the toolbar's right cluster opens `Modals/FeedbackModal` — a composer that assembles a plain-text report and hands it to the user's own mail client via `mailto:`, with a clipboard fallback. **Nothing is uploaded, and that is a constraint rather than a preference**: the build CSP is `connect-src 'self' blob: <deploy origin>` + `form-action 'self'` (`vite.config.ts`), so a POST to Formspree / Google Forms / any hosted endpoint is blocked by the app's OWN policy; the desktop build must work with no network at all; and a third-party form would make someone else a data processor for grant-funded research feedback. A `mailto:` navigation is CSP-exempt (navigation, not a fetch) and works in every build. If a server-side endpoint is ever wanted, it needs a `connect-src` widening plus the mailto path kept underneath for the offline case — don't quietly swap one for the other. Report assembly is PURE and tested in `utils/feedbackReport.ts` (the DOM reads live in the modal): the opt-in technical block carries version/build, **graph counts (nodes, how many are connected, connections, groups, notes), cost points vs the selected device — printed as the cost bar prints them, `<total> / 100 pts · <device>` plus `OVER BUDGET` past it (2026-10-23; the device is resolved through `resolveDeviceBudget`, so a selected profile reports its own name and budget where a headset-only lookup fell back to Quest 3) — and the preview mesh (built-in geometry name, or a custom model's name + vertex count + size)**, then browser/platform/renderer/display. Counts only — no graph content leaves. Edges are counted on the UNWRAPPED graph (`unwrapCollapsedGroupEdges`), or the same project would report differently depending on which frames happened to be collapsed. `previewMesh.countMeshVertices` (and the compressed-glTF pre-check `inspectGltfCompression`, which reads only the two top-level extension-name arrays) is a **deliberate, narrow exception** to that module's "bytes are never parsed on the trusted side" rule: it counts OBJ `v` lines or reads integers out of a length-capped glTF JSON header — no geometry built, no URI resolved, no buffer touched, every path bounded, every failure returning null. The glTF MODEL reader (`utils/gltfReader.ts`) is the separate, larger documented exception, and the feedback report does not use it. It reports the AUTHORED vertex count, not what THREE ends up with (the OBJ loader emits non-indexed geometry and `fit-bounds` then welds duplicates), so don't reason about GPU cost from it. Also: `MAILTO_SAFE_CHARS` steers over-long reports to "Copy report" because Windows' shell truncates `mailto:` URLs around 2000 chars — a silently truncated bug report is worse than none, since the user believes they sent it. `previewBackend()` RESTATES the `__fsForceWebGL2` rule that `tslToPreviewHTML` emits as source text into the iframe (it can't be imported and called); `feedbackReport.test.ts` extracts that emitted function from the generated HTML, evaluates it, and fails if the two disagree — so a change to the WebKit-forcing rule can't silently make feedback reports lie about which renderer the user was on.

### Centralized vendoring (single source + sync)

- **Centralized vendoring (single source + sync)**: the A-Frame IIFE bundle (`a-frame-180-a-01.min.js`), the shaderloaders, orbit-controls and the Gaussian-splat runtime (`fs-splat-0.1.js`) live ONLY in `a-frame-shaderloader/js/`. `scripts/sync-generated.mjs` (`VENDOR_TARGETS`) — run by the `fs-vendor-sync` vite plugin when the config RESOLVES, i.e. at every dev/build/test start and before the dev server snapshots `public/` (a write at buildStart came too late: a fresh clone's first `npm run dev` served index.html for every generated file), and by hand as `npm run sync:generated` — writes **the bundle, loader 0.8, orbit-controls, `fs-splat-0.1.js` and the `decoders/` set** into the GITIGNORED `public/js/` (plus the bundle into `ShaderCarousel/components/three/`) and prunes every file its tables do not name — never through a symbolic link: an output folder that is a link, or lies under one, stops the start before anything is touched (pruning through `public/js -> ../a-frame-shaderloader/js` would delete the submodule's frozen loaders, measured in a scratch checkout), and a stray link inside one is removed, never followed (one at a generated file's name is compared through and, when it differs, replaced by the file, never written through). It writes only what changed, through a temp file in `node_modules/.cache/sync-generated/` and a rename, so a reader never sees half a file (where the rename is refused — a file held open on Windows, another volume, a restricted mount — it falls back to the in-place write it always did); a second start running at once (two test runs) is harmless; and `public/models/teapot.obj`, its one costly output, is rebuilt only when a content stamp in that cache folder says the teapot's inputs, the Node version or the file changed, so a start costs ~22 ms rather than ~95 (measured 2026-10-10). `src/syncGenerated.test.ts` pins all of that, and that the stamp's `TEAPOT_INPUTS` name every module the real teapot loads (an unlisted one could change, or stop loading under plain Node, with no start noticing). `src/vendorSync.test.ts` runs AFTER the sync, so under `npm test` a hand edit to a copy never reaches it (the start already overwrote it; only a `vitest` watch session can catch one made since it started); what it pins is the TABLES — the script's rows equal its `COPIES`, every script the submodule ships is either copied or carries a `NOT_VENDORED` reason, and a dropped script could only come back through a new row. **0.4, 0.5 and 0.6 are deliberately NOT vendored** (0.4/0.5 since 2026-08-31, 0.6 since the loader switch): nothing resolves them same-origin — the preview and podest load 0.8, while older exports name them on the jsdelivr CDN, i.e. from the SUBMODULE — so a copy is dist nothing can load. They stay FROZEN in the submodule, because that is what already-exported shaders fetch. **A dropped copy leaves the hosts diverged**: the sync prunes it from every local build, GitHub Pages deploys with `force_orphan` and loses the file, while alvismisjuns and sferas upload with psftp `put -r`, which never deletes, and keep it — and an app tab opened before a Pages deploy fails its next preview rebuild against the removed file until it is reloaded. index.html carries NO `<meta http-equiv>` cache directives: `Cache-Control`/`Pragma`/`Expires` are not HTML pragma directives and browsers ignore them for an HTTP-served document, so stale HTML on a psftp host is fixed by a `Cache-Control` response header in the host config. **Never hand-edit the copies** — the next start overwrites them; edit the submodule source and re-run vite. Everything runs **Three.js r184**: the bundle (super-three 0.184), `node_modules/three` (`^0.184.0`), and the carousel's standalone ESM `ShaderCarousel/lib/three/*.min.js` (the official minified builds copied from `node_modules/three`, used by static/microplane benches via import map). The glTF decoders live in `a-frame-shaderloader/js/decoders/` — three r184's glTF Draco build and `meshopt_decoder.module.js` for MESHES, and `basis_transcoder.{js,wasm}` (the Basis Universal transcoder three's `KTX2Loader` runs) for KTX2 TEXTURES, plus a README carrying their provenance and the Apache-2.0 text Draco's and Basis's licences both require to travel with them. They are synced to `public/js/decoders/`, and `vendorSync.test.ts` also pins them byte-identical to `node_modules/three/examples/jsm/libs` and the README's size/sha256 table to the files. A three bump therefore fails until they are re-copied — which for the basis pair matters more than it looks, since a transcoder built for a different `KTX2Loader` worker protocol fails INSIDE a Worker, where nothing surfaces. Loader 0.8's `FastShaders.decoders` section (13b) is what installs them; exports fetch them by URL beside the loader, so push the submodule and purge all six files on jsdelivr, and never move them. The two committed Draco/meshopt test fixtures under `src/engine/fixtures/compressed/` are ENCODED by `scripts/gen-compressed-fixtures.mjs` from encoders already on disk (three's `draco_encoder.js`, and `meshoptimizer`, which is only a transitive dev dependency of `@types/three`), so the script is documentation-grade and CI never runs it.

### Push the `a-frame-shaderloader` submodule BEFORE the release tag, and PURGE jsdelivr when the pushed file is n…

- **Push the `a-frame-shaderloader` submodule BEFORE the release tag, and PURGE jsdelivr when the pushed file is new.** Exported `.js` reference the loader at `cdn.jsdelivr.net/gh/Alvis1/a-frame-shaderloader@master` (`CDN_BASE`, `tslToShaderModule.ts`) — as does the A-Frame tab's generated `index.html` (bundle + loader, the same two files the header names), while the app's own preview reads the same-origin `public/js/` copies (`resolveAssetUrl`) — so a loader pushed after the app deploys 404s for **every recipient of an exported shader while working perfectly for the author**, and jsdelivr caches branch refs (~12 h) AND caches the 404, so it does not self-heal on the next request. Force it: `https://purge.jsdelivr.net/gh/Alvis1/a-frame-shaderloader@master/js/<file>` — for the loader switch that is `js/a-frame-shaderloader-0.8.js` plus the five `js/decoders/` files (the Draco pair, meshopt, and the basis transcoder pair, whose sha256s must start `8478b5b6d6b74e7d` / `6cf17dc889352c42`), each checked with `curl -sL <cdn url> | shasum -a 256` against the local file. The full order: push the submodule → commit the parent's pointer bump and run `npm test` → purge → `npm version patch && git push --follow-tags` → `npm run deploy:alvismisjuns` → `npm run deploy:sferas` (held while a study cohort runs — the participant's preview changes loader). Push from the MAIN checkout's `a-frame-shaderloader/`, fast-forwarded from wherever the work was committed: a worktree's `--shared` submodule clone has the main checkout's submodule as its `origin`, whose checked-out `master` refuses the push. Order matters for a second, independent reason: `release.yml` checks the submodule out at the pointer RECORDED here (`submodules: recursive`) and the generated `public/js/` is written from it, so CI ships the recorded loader whatever the author's working tree holds. Since the copies are no longer tracked, nothing in CI can notice an un-bumped pointer — `scripts/check-submodule.sh` is the gate, run by `npm version` (`preversion`), `npm run deploy` and both host deploy scripts: it refuses a submodule checkout that differs from the pointer HEAD COMMITS (a staged-only bump is in no tag), uncommitted changes under the submodule's `js/`, and a recorded commit that is not on the submodule's `master` as fetched from the `.gitmodules` URL (what jsdelivr serves as `@master`) — so the release, not a recipient, finds a loader pushed only to a side branch.
