### Sync engine

- **Sync engine**: `syncSource` field in zustand (`'graph'` | `'code'`) prevents infinite sync loops. `useSyncEngine` hook manages bidirectional sync with `lastSyncedCodeRef` to skip no-op updates

### Node values

- **Node values**: always use `getNodeValues(node)` from `@/types` — never cast `node.data as ...`

### Edge IDs

- **Edge IDs**: always use `generateEdgeId(source, sourceHandle, target, targetHandle)` from `@/utils/idGenerator`

### Single ShaderNode

- **Single ShaderNode**: one component handles all TSL node types dynamically via registry

### Decorative surfaces tick together, at 15 Hz

- **Decorative canvas surfaces tick TOGETHER on ONE 15 Hz frame ticker** (`utils/frameTicker.ts`, reached through `hooks/useFrameLoop.ts`; owner decision 2026-10-11). The surfaces: LiveEdgeValue, the sin/cos card (MathPreviewNode), the Time hand (ClockNode), the animated noise thumbnails (PreviewNode), the Sound meter and EdgeInfoCard. Every frame in which ANY canvas element is written pays Chrome's whole-canvas layerization pass (`PaintArtifactCompositor::Update`). MEASURED on graph-150 (one Time node, ants off): the six per-frame writers cost 8.8 ms/frame at 1x and kept a 4x-throttled CPU 100% busy, and freezing any ONE writer saved at most 8%, because the other five still dirtied the same frames. A shared 30 Hz gate measured 4.9 ms/frame at 1x but nothing at 4x; 15 Hz measured 2.6 ms/frame and 69% busy. So `frameTicker` is ONE rAF loop that calls every subscriber on the SAME frames, with `appTime(ts)`, at `FRAME_TICK_HZ` = 15, the one rate constant. The gate is a MINIMUM interval, not a phase-locked cadence, so a saturated machine ticks every other frame instead of two frames in three. The loop exists only while something is subscribed; it schedules its next frame first and wraps each subscriber in try/catch, so one throwing surface neither stops the loop nor starves the others. ONE IntersectionObserver skips subscribers whose element is off-screen or `display: none` (a collapsed group's members stay MOUNTED, see canvas-interaction.md, Groups) and calls their `onHidden` instead. Chrome does not skip the cost for cards panned out of the pane (4.1 ms/frame vs 0.23 with their writes stopped), and the per-loop `offsetParent` read this replaced forced one layout per label after the previous label's write (5.2 layouts/frame). Skipping is safe because the clock is absolute: the first tick after a card comes back draws the true current value. A one-shot STATIC draw (PreviewNode's static thumbnail) must never be gated: it has no later tick to catch up on, and a hidden canvas keeps its bitmap. PreviewNode's thumbnails ran their own 30 Hz budget, judged the floor below which a translating pattern reads as stepping; the owner traded that for the shared rate. The implementation, measured on the dev server (graph-150, ants off): 9.5 → 2.6 ms/frame at 1x, 99.9% → 61% busy at 4x, 4.2 → 2.0 ms/frame panned off-screen with zero writes, node resizes 10/s → 0. With marching kept on the time-varying wires (19 of 195 on graph-150) the canvas still costs 7.1 ms/frame at 1x and stays 99.9% busy at 4x, against 2.5 ms/frame and 53% with those animations off: on a graph with a Time node, the live wires hide most of the 15 Hz saving.
  **Ticks write the DOM imperatively from refs and read the graph with `useAppStore.getState()`**, never a mirror ref of a subscription, which would freeze the surface on the graph it started with. That retired the old "rAF ref pattern" note (PreviewNode/MathPreviewNode/EdgeInfoCard overwriting refs for animation): there are no mirror refs left to keep fresh and no stale closure to avoid. `useFrameLoop(enabled, elRef, makeTick, deps, { onHidden, onStop })` calls the `makeTick` FACTORY on every (re)start, so per-run state (the last string written, the last phase drawn) starts fresh when `deps` change; `elRef` names the element whose visibility gates the tick. `frameLoopSurfaces.test.ts` fails on a `requestAnimationFrame` or `.offsetParent` in any of the six surfaces, because a surface with a loop of its own brings the cost back. The 3D preview's Sound pump (`useSoundPump`) drives the SHADER, not a canvas surface, and stays on its own loop.
  **A surface that renders through React STATE commits inside the tick** — EdgeInfoCard, with `flushSync(() => setRange(next))`, and it skips an unchanged value (`sameRange`). React renders a frame callback's plain `setState` in a later scheduler task, after the tick frame has painted, so the write lands on a frame of its own. MEASURED 2026-10-11 on graph-150 with a Time wire selected: 0 of 30 chip writes inside the tick; 2.51 → 3.98 ms/frame at 1x and 56% → 90% busy at 4x; with `flushSync`, 30 of 30 inside, 2.67 ms/frame and 55%. The effect-time first draw stays a plain `setState`, because `flushSync` cannot commit inside an effect. `frameLoopSurfaces.test.ts` pins the `flushSync` commit and `sameRange`.
  **A ticking label never resizes its node.** LiveEdgeValue's opt-in `reserveWidth`, passed ONLY from ShaderNode's row layout, holds a px `min-width` at the widest the text has reached (`scrollWidth + 1` on growth; never `ch`, which resolved to 0.5em there; never a rounded `offsetWidth`, which left a 0.34 px wobble) and clears it when the label stops ticking. `fmtEdgeNum` trimming a trailing zero moved a node 40↔44 px about 9 times a second and re-routed its wire. Never in an Output, Raymarch or Splat cell: those are the same span at a FIXED 20px width (OutputNode.css), and `frameLoopSurfaces.test.ts` pins where the prop may appear. `WaveformSvg`'s `applyWaveFrame` also skips an attribute write whose value did not change, comparing against the DOM rather than a cache, so a value React patched back is still rewritten.

### Canvases inside the React Flow viewport MUST be CPU-backed

- **Canvases inside the React Flow viewport MUST be CPU-backed**: the `getContext('2d', { willReadFrequently: true })` in PreviewNode is deliberate — an ACCELERATED canvas becomes its own compositing layer in Safari, WebKit's overlap compositing then promotes the surrounding nodes into layers rasterized at 1×, and the whole zoomed canvas goes blurry (empirically bisected 2026-07-11 via the `?fsdbg=nocanvas` switch in `main.tsx`, which stays available for renderer triage). Never add a plain-context or WebGL canvas to anything rendered inside `.react-flow__viewport` — and prefer SVG outright for VECTOR content: the sin/cos waveform is `nodes/WaveformSvg.tsx` and the Time node's face is `nodes/ClockFaceSvg.tsx` (each the ONE renderer behind its live node AND its asset-card tile; `utils/waveform.ts` / `utils/clockFace.ts` are the pure tested models), because a fixed-resolution canvas bitmap blurs under the viewport zoom no matter how it's backed, while the per-frame work drops from a full repaint to one or two transform writes. Only raster content (the noise previews) still earns a canvas — PreviewNode is the last one in the viewport.

### Animated editor surfaces read ONE clock

- **Animated editor surfaces read ONE clock** (`utils/appClock.ts` — `appTime(rafTimestamp)`): the rAF loops in MathPreviewNode, PreviewNode and EdgeInfoCard used to mint a private epoch at first frame, so `t` meant "seconds since THIS loop started" — a sin card showed sin(48.3) while the freshly-hovered edge chip evaluated the same wire at t≈0.15, and no two surfaces could agree except by coincidence. All loops now derive t from the shared module epoch; the frame ticker hands every subscriber `appTime(ts)` of the same frame, so every surface evaluates the identical t and cpuEvaluator's per-time cache buckets coalesce (one per tick, not one per surface). **On-node connected-input labels tick too**: `edgeValueLabel` returns an `animated` flag (time-driven on the UNWRAPPED graph, and not a noise source — a ticking probe of a noise field would still be one arbitrary sample, so noise keeps its range) and all four label surfaces (ShaderNode rows, Output channel cells, the Sound node's params, the Time node's wired speed) render through `nodes/LiveEdgeValue.tsx`, which overwrites textContent from the shared 15 Hz frame ticker on the shared clock — imperative writes, NOT per-frame React re-renders, with `utils/edgeValueText.ts` as the shared pure formatter so the ticking path can't format differently from the resting one. The `animated` bit must ride each surface's cheap string key (wiring Time into an existing upstream chain can leave text/live unchanged — sin(0) is 0 either way — and a stale flag keeps the label frozen). **"Time-driven" is asked of `getTimeUpstreamSet` (cpuEvaluator), never of the per-node `hasTimeUpstream`** (`utils/graphTraversal.ts`, the tests' oracle only): ONE forward BFS from every Time node, memoized on the evaluator ctx and rebuilt only when a new ctx is minted, i.e. when `sameGraphSemantics` says the graph changed. The per-node form rebuilds two whole-graph Maps on every call and measured 85-93% of all per-notify selector work on a 150n/220e graph. The set walks `ctx.edges` (UNWRAPPED), so a Time node feeding INTO a collapsed group stays visible — EdgeInfoCard and PreviewNode were live instances of the raw-edges bug (`timeUpstreamSet.test.ts`). **`getLiveUpstreamSet` (cpuEvaluator) is its sibling**: the same ctx-memoized forward BFS over the UNWRAPPED edges, seeded by Time AND Sound (`soundNode`), and it answers "does this wire march?" for TypedEdge and PreviewLink (node-visuals-and-designer.md, "A wire marches only when it is LIVE"). Sound is seeded whether or not a capture is armed: the armed state lives in `soundSession`, outside the store, so a Sound-fed wire marches with no capture running. `liveUpstreamSet.test.ts` pins it, a Time feeder inside a collapsed group included. Two deliberate exceptions: the ClockNode HAND integrates `dt × speed` instead of reading appTime (wall-clock × speed lands on an unrelated `% 60` residue every speed-scrub pointermove — the hand would teleport; it shows RATE, not absolute time, and after a speed change its angle intentionally diverges from the shader's `time.mul(speed)`; its dt comes from the ticker's app-clock t, clamped at 0.25 s (`MAX_HAND_DT`, raised from 0.1 because 15 Hz ticks on a loaded machine can be ~0.1 s apart, which made the hand run slower than real time); since 2026-10-11 it also PAUSES while panned off-screen, not only when collapsed, and resumes where it stopped, because `onHidden` keeps its dt tracker moving), and the 3D preview stays on three's own clock (sandboxed iframe, rebuilt on edit). Never reintroduce a per-loop `startTime = timestamp` epoch.

### An import auto-frames the canvas

- **An import auto-frames the canvas**: importing a shader replaces the nodes but NOT the viewport, so a project whose nodes sit anywhere but where the user is looking lands off-screen and reads as a failed import (an empty canvas). Every import surface funnels through `projectImport.ts`, which dispatches **`fs:graph-imported`** whenever the graph is actually replaced — deliberately NOT `fs:project-imported`, which also fires for a model-only zip where the graph never changed and re-framing would throw away the user's viewport. NodeEditor **ARMS** a fit on that event rather than fitting on it: a project block writes its nodes in the same tick the event fires (React hasn't rendered them), and a bare script has NO graph at all until `useSyncEngine`'s code→graph pass finishes a commit or two later — so the fit runs from the `[nodes]` effect, on the next graph the editor actually renders, behind the same double-rAF measurement guard `startNewShader` uses (`fitView` frames the MEASURED box; unmeasured nodes fit as zero-size points at maxZoom). Two details are load-bearing: the pending rAF is held in a REF torn down only on unmount, never by the effect's own cleanup — the cost pass writes the Output node's new total straight back into `nodes`, so an imported graph re-renders inside the two-frame window and a cleanup-owned rAF would be cancelled by exactly the change proving the import landed — and the arm carries a `IMPORT_FIT_TIMEOUT_MS` disarm, so an import that never yields a graph (parse errors, a byte-identical re-import that the sync engine skips) can't leave a fit primed to hijack a later unrelated edit. **The fit is armed on THREE events.** `fs:graph-imported`; `fs:graph-new`, because EvalGate's `cleanSlateForStudy` calls `newGraph()` on the store directly, with no NEW button to frame the blank document — with the viewport remembered, a study session could open on the previous participant's pan with the document off-screen (on the NEW button itself it is two fits to the same box); and `fs:graph-merged`, for `commitGlbImport` and `addDroppedShader` (nodes arrived, the document did not change). **The BOOT graph is framed through the same arm**: React Flow's `fitView` init prop runs before App's seeding effect (child effects run first), so it fits an EMPTY canvas, and `seedFromStored` dispatches `fs:graph-imported` — skipped when `saved && readStoredViewport()` (the `fs:viewport` bullet in storage-and-limits.md). Desktop Work-folder loads get the FRAMING for free — same `importShaderText`/`importShaderZip` — but they do two things on top of the shared path (adopt the file's name, track it as the Save target), so "for free" is a claim about the fit only.

### A dropped shader ASKS: Open or Add

- **A dropped shader ASKS, and the second answer is what makes the question worth asking** (`Modals/ShaderImportModal.tsx`, raised through the store queue `pendingShaderImports` by the ONE gate `utils/shaderDropRequest.ts`; the two answers live in `engine/projectImport.ts` as `openDroppedShader` / `addDroppedShader`, the additive plan in `engine/shaderGroupImport.ts`, the names in `utils/shaderDropName.ts`). Until 2026-09-19 dropping a `.js`/`.mjs`/`.tsl`/`.zip` on the canvas, the 3D preview or the code panel REPLACED the whole project with no warning — the most destructive thing a drag can do in this app, reachable by accident, recoverable only by noticing in time. A bare confirm would have been a speed bump; **ADD** is the feature: the dropped shader's chain is parked beside the graph already on the canvas, in one group frame named after the file, so "open someone else's shader next to mine and take a piece of it" stops being a two-window clipboard exercise. Nine rules. (1) **The gate is one function and it is skipped in a study session** — `isEvalMode()` returns false from `requestShaderImport`, so `/eval`, `/evalpro` and `/evalp` keep today's drop byte for byte (the GLB dialog's rule, and it also keeps `fs:graph-imported` firing where the telemetry chokepoints expect it). The three surfaces each RETURN when the gate took the file; falling through would run the old import as well and overwrite the answer the user gave. (2) **"Load Script…" and the desktop Work folder do NOT ask** — they are already explicit instructions to open a file. Only a DROP asks, which is why `importScriptFile` in the code panel takes a `fromDrop` flag rather than the two callers sharing one behaviour. (3) **The forwarded-shader `window.confirm` stays on the surface**, ahead of the gate: sandboxed shader code can forge `fs:preview-drop`, and a dialog it forged is one the user might answer. (4) **OPEN is today's import plus the NAME.** The authored name inside the file still wins; the file's STEM is the fallback, and that is new — a bare shaderloader script, and a project block shipping no name, used to leave the PREVIOUS shader's name on a graph that has nothing to do with it, which is the name the next export would then have been written under. `nameFallback` is threaded through `importShaderZip` → `importShaderText` → `applyProjectToStore` and defaults to absent, so every other caller is byte-identical. OPEN also replaces what the file is SILENT about (`applyProjectToStore`): `fs:previewUniformValues` / `fs:previewUniformBounds` are written even when the block ships none (the uniform bullet in storage-and-limits.md), and an ABSENT palette block sanitizes to `[]` and REPLACES the palettes, or the previous shader's are re-exported inside an unrelated one. `importShaderText` announces `fs:graph-imported` BEFORE the bare-script conversion: the converter chunk may land a tick later, and the Work folder reads the event inside its own synchronous `loadingRef` bracket. The Work folder answers the same question the OTHER way on purpose (`adoptShaderName` lets the name on DISK win, because there the file is the document's identity and Save must find its way back to it). (5) **ADD drops every sink.** Plain Outputs and Raymarch Outputs alike (`isSinkNode`) leave with the edges that fed them — that is what "not attached to output" means, and it is not tidiness: among untargeted plain Outputs exactly one contributes and a DRIVING Raymarch Output suppresses every plain one, so an arriving sink can silently take over the render of the shader it was added to. Because no Output arrives, the unfold/active-sink repairs `instantiateSavedGroup` must re-run over the COMBINED list have nothing to do, and the planner never reads or rewrites a live node. A file that is nothing but an Output is REFUSED (`nothing-to-add`) rather than dropping an empty frame. (6) **Every id is re-minted.** A `.fastshader` carries the ids it was saved with and the live graph usually holds the very same ones — it is typically an export of a shader this one descends from. (7) **A singleton is redirected, not duplicated**: a Sound node already on the canvas keeps its place and the arriving copy's wires are re-pointed onto it (`SINGLETON_NODE_TYPES`, the same "glide to the node that is already there" rule both add surfaces follow); a fold that would leave a self-edge drops it. (8) **NESTING survives** — groups and notes the dropped file carried keep their `parentId` links, only ROOT-level nodes become members of the new frame, and the result is emitted parents-first because React Flow requires a parent before its children. A child whose parent was a dropped sink, or whose `parentId` names nothing in the file, is re-rooted into the frame; a parent CYCLE in a hand-edited file does not hang the walk. (9) **ADD announces `fs:graph-merged`, never `fs:graph-imported`** — the document did not change, so the desktop Work folder must not forget the open file and turn the next Save into a Save-as, and the study telemetry must not log an import. It is ONE undo entry, the image budget is counted against the LIVE graph plus the arrivals and checked BEFORE `pushHistory` (so a refusal leaves none), the preview mesh is untouched (an Add is not a new document, so a zip's `models/` entry is not installed), and the arriving nodes go through the same sanitizers every other ingestion path runs. The frame parks clear to the RIGHT of everything on the canvas rather than at the pointer — two of the three surfaces have no canvas coordinates to offer, and `fs:graph-merged` frames the result anyway. The dialog itself is the model-drop dialog's shape (file name, one warning line only when there is work to lose, two EQUAL plates, red text Cancel), remembers nothing, and focuses ADD so Enter is the answer that cannot throw work away. Verified in Chrome 2026-09-19: the dialog, Add (6 → 16 nodes, one Output, the import note), Open (the graph replaced and the name adopted), Cancel, Escape, the code-panel drop, and the picker NOT asking.

### History

- **History**: circular buffer (50 entries) with undo/redo via `structuredClone`, Cmd+Z/Cmd+Shift+Z shortcuts (`useSyncEngine`; they do nothing while an aria-modal dialog is open; in a text field — the Name box, a textarea, a canvas Note, Monaco — they are the field's own native undo, per `keepsNativeUndo` in `utils/isTypingTarget.ts`, while number fields (`role="spinbutton"`: NumberField, LazyNumberField) and selects keep graph undo, because their edits are graph edits. Fixed 2026-10-11: Cmd+Z in the Name field had undone the last graph edit. Measured in Chrome: Cmd+Z in the Name box restores the text and leaves the graph alone, Cmd+Z in a node's number box brings back a deleted node. In a canvas Note, Chrome's native undo steps one character at a time — "hello" became "hell"), plus visible Undo/Redo buttons in the canvas's bottom-LEFT bar (`.fs-canvas-bar` — one pill also holding the Draw tools and the zoom −/+ / fit / canvas-bg controls that replaced the React Flow Controls stack; the buttons call `undo()`/`redo()` directly — equivalent to the keyboard path, since the graph→code effect re-runs on any nodes/edges identity change regardless). **Continuous gestures must be bracketed**: `beginInteraction()`/`endInteraction()` snapshot ONCE up front and suppress `pushHistory` until the gesture ends, so a DragNumberInput scrub is one undo entry instead of one per pointermove frame — and, just as importantly, the whole graph isn't `structuredClone`d 60×/s (megabytes once images are embedded). `beginInteraction` deliberately ignores `isUndoRedo` (that flag guards the sync engine's post-undo reconciliation; a pointer gesture is always a real mutation, and honouring a stale flag would silently swallow the gesture's history). DragNumberInput brackets on first move — not pointerdown, since a press that becomes a click-to-edit would push a no-op entry — and closes the bracket on pointerup, pointercancel, and unmount. **A no-op `set` returns `state`, never `{}`**: zustand skips the merge and the notify only on an identity hit, `pushHistory` runs on every pointermove of a bracketed scrub, and returning `{}` MEASURED exactly 2 notifications per frame (60 scrub frames → 120) against ~1,400 selectors on a 100-node graph (`historyPayloadSharing.test.ts`). **`recordHistory(state)` is the UNGUARDED record**, spread into the same `set` as the mutation; `pushHistory` is the guarded one (`isUndoRedo`, an open bracket). `newGraph` and `beginInteraction` record unguarded because a stale `isUndoRedo` (an undo whose sync reconciliation has not run yet) would swallow the entry, and `newGraph` snapshots and clears in ONE `set` so no subscriber sees a cleared graph without its history. The four palette CRUD actions do too: the colour picker's `useHistoryBracket` holds the bracket open for a 600 ms idle window AFTER a pick and `pushHistory` bails inside it, so "pick a colour, then Add palette" would go unrecorded and the next Cmd+Z would jump past the pick. Closing the bracket first is not the fix — it would split the pick's single undo entry (`palettes.store.test.ts`). A LESSON's takeover (`startTutorial` / `confirmTutorial`, `src/tutorials/`) records UNGUARDED like `newGraph` — one entry even while `isUndoRedo` is still set, pinned by `tutorialStore.test.ts` — replaces the graph with a lone Output, keeps the DOCUMENT (name, palettes, tuned uniforms, the preview model) and announces `fs:graph-merged`, never `fs:graph-new`; over a canvas that holds work it ASKS first (`phase: 'ask'`), because the autosave writes the lesson graph over `fs:graph` 300 ms later and the old graph then lives only in in-memory history. The `tutorial` slice itself is session-only like `nodePreview`: never in `HistoryEntry`, `graphPayload` or a file.

### `setCode(code, 'code')` — the user typing in the TSL panel — writes `code` ONLY; `previewCode` advances on a g…

- **`setCode(code, 'code')` — the user typing in the TSL panel — writes `code` ONLY; `previewCode` advances on a graph→code sync or on Apply (`requestCodeSync`).** ShaderPreview subscribes to `previewCode`, so half-typed TSL never swaps `srcDoc`: without the split every keystroke would re-fetch and re-parse the ~1 MB A-Frame bundle under a fresh opaque origin — the same cost the 200 ms rebuild debounce exists to collapse. It is also the reason the preview looks frozen while you edit code until Apply; collapsing `setCode`'s two branches into one write is the accidental way to lose it.

### Deleting a node SPLICES the chain, it does not cut it

- **Deleting a node SPLICES the chain, it does not cut it** (`utils/edgeUtils.ts` → `bridgeEdgesAcrossDeletedNodes`): each outgoing edge of a deleted node re-parents onto the live source reached by walking its first incoming edge upstream, crossing whole runs of deleted nodes — `X → A → B → C` with A+B selected becomes `X → C`. Single-input-per-port is preserved (first bridge to a `(target, targetHandle)` wins, later ones drop), an edge whose TARGET is deleted is dropped, and a chain that dead-ends upstream is dropped. React Flow's own delete is disabled (`deleteKeyCode={null}`) precisely so that every user-facing deletion path goes through that ONE helper — NodeEditor's keydown handler, `store.removeNode`, and the group-delete run. A fourth deletion path that skips it silently redefines what Delete means: the graph disconnects, the generated code changes, and nothing errors.

### A node component that mounts or unmounts handles at runtime MUST call `useUpdateNodeInternals(id)` in an effec…

- **A node component that mounts or unmounts handles at runtime MUST call `useUpdateNodeInternals(id)` in an effect keyed on the handle SET** — `exposedPorts.join('|')`, the collapsed group's boundary-socket ids, the grown-operand count. React Flow never refreshes its handle-bounds map on its own, so an edge to a freshly mounted handle stays in the store and still emits correct code but simply never DRAWS, and existing edges snap to stale anchors when a socket count shifts. The symptom actively misleads: a page reload fixes it (every handle is measured on first mount), so it reads as a React Flow rendering glitch rather than a missing effect. All nine dynamic-handle components already do it — ShaderNode, OutputNode, RaymarchOutputNode, SplatOutputNode, PreviewNode, GroupNode, SoundNode, ClockNode, ColorNode — so a TENTH node type is the only way to reintroduce the bug. **The same stale map follows a change of a card's drawn SCALE** (2026-10-23): the five cost-scaled cards (`COST_SCALED_TYPES` — ShaderNode, PreviewNode, MathPreviewNode, ClockNode, SoundNode) scale with their price as a share of the selected device's budget, by a `transform` on the card inside React Flow's wrapper, and React Flow re-measures handle bounds only when that wrapper's box resizes. Once points followed the device, picking another one rescaled every such card and left its wires short of the sockets (measured: a Perlin card's out-wire 4.3 px off its socket on Quest 3, 9.1 px after picking Steam Frame, 4.5 px again after a reload). `useRemeasureOnScale(id, costScale)` (nodes/useCostChrome.ts) calls `updateNodeInternals` when the drawn scale moves — a device change, an RGB Curves bend, an Image resolution — and skips the mount, which React Flow measures anyway.

### A seam drag re-renders AppLayout, and ONLY AppLayout

- **A seam drag re-renders AppLayout, and ONLY AppLayout** (`components/Layout/AppLayout.tsx`): it hands SplitPane MODULE-SCOPE elements — `TOOLBAR`, `CANVAS_PANE`, `PREVIEW_PANE`, `CODE_PANE`, `OVERLAYS` — so the per-pointermove re-render skips Toolbar, NodeEditor, ShaderPreview, CodeEditor and the modals by element identity. Giving any of them a prop that changes per render means un-hoisting that element, which brings the per-move re-render of its whole subtree back. The code pane's idle-mount gate lives in AppLayout's `CodePane` component. The bail-out is React semantics, not a browser measurement.
