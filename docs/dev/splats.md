### What was built, and what deliberately was not (2026-09-24/25)

- **Splat SHADING lives in FastShaders; splat DATA editing lives in neither this app nor a new one.** The owner asked for cutting a splat scene with planes, boxes and spheres (keep inside or outside), displacement and a colour overlay, and then whether that belongs here or in a separate app. Shading a splat from a node graph is the app's own pipeline — graph → TSL → module → loader — with one new sink, and it reuses the distance-field family as the cutters, the noise/time/sound nodes for animation, the sandboxed preview, the export and loader 0.8 as the distribution channel; a separate app would have to copy the editor, the codegen, the preview and the loader to get there, and every copy is a drift site (the podest twin is the cost of one). Editing the DATA — selecting, deleting, painting and re-saving individual splats — needs picking, a selection model, a data undo stack and full trusted access to large files, which is the opposite of this app's architecture (dropped model bytes are adversarial and live in an opaque-origin sandbox the app cannot read). SuperSplat (PlayCanvas, open source) and splat-transform already are that tool; FastShaders takes their `.splat`/`.spz` output as input. The optional CPU "bake" (evaluate the cut per splat and write a new `.splat`) was planned and DROPPED for the same reason: it is the first step from shading into data editing and needs a fourth exception to the no-parse rule. Owner decisions (2026-09-24): v1 covers the preview, the XR popup, the export AND podest; the Splat Output is **always offered** on the Output tab (not a companion of the Distance-fields switch); Move ships in v1 as "small smooth fields".

### The runtime file `fs-splat-0.1.js` — three r186's splat addon on the r184 bundle

- **A separate vendored IIFE, never a rebuild of `a-frame-180-a-01.min.js`.** The renderer is three r186's `examples/jsm/objects/GaussianSplat.js` (+ `gpgpu/CountingSort.js`, `utils/GaussianSplatUtils.js` and the SPLAT / SPZ / Gaussian-PLY (+ `PLYLoader`) / KSPLAT loaders) — eight files copied BYTE-IDENTICALLY into `a-frame-shaderloader/splat/`, each pinned by size + sha256 in `splat/README.md` (with three's MIT text), and `vendorSync.test.ts` fails on drift. The app runs r184 (A-Frame 1.8.0 pins super-three 0.184), and the addon imports exactly ONE name r184 lacks, `unpackUnorm4x8` — so `build/build-splat.mjs` resolves the bare `three` / `three/webgpu` specifiers to `globalThis.THREE` and `three/tsl` to `THREE.TSL` spread into a fresh object plus a six-line `Fn` polyfill named `fs_unpackUnorm4x8` (the spread is required: esbuild's `__toESM` copies OWN properties only). That is loader 0.8's GLOBAL_SOURCE mapping applied at bundle time, and it keeps the addon text unedited. Rebuilding a-01 instead would re-ship 1.65 MB to every page built from an export — retroactively, through jsdelivr `@master` — for a feature only splat pages use. A document loads the runtime only when it shows a splat, after the a-01 tag; it throws a named error when `THREE`/`THREE.TSL` is absent. Same CDN rule as the loader: additive-only after its first push, and real for a recipient only after the submodule push and a jsdelivr purge of `js/fs-splat-0.1.js`.
- **`FastShadersSplat.parseBytes(kind, buffer)` is the ONE parse chokepoint**, and it runs only inside the sandbox (or podest's stage). Order: cap BEFORE allocation, parse, then drop the SH bands. `.splat` = length % 32 and the count cap; `.ply` = a bounded 64 KiB header decode that refuses a non-splat PLY, SuperSplat's chunked PLY, any `f_rest_*` (training output with SH — the loader would materialise 180 B/splat), ASCII PLY (PLYLoader turns an ASCII body into one string per number), more than one element (PLYLoader walks EVERY element's declared count, and a row of a property-less element reads 0 bytes — a 1 KB `element junk 99999999999999` was a 1e14-row loop no cap bounded; 3DGS training, SuperSplat and splat-transform write one `vertex` element), a second `format` line, an unknown property type, an `end_header` that is not the header's first exact `end_header` LINE (PLYLoader ends the header at that line, GaussianSplatPLYLoader at the first substring — a `format ascii` after `comment x-end_header` reached PLYLoader unseen) and a truncated body (count × row bytes against the bytes after the header, from where `extractHeaderText` starts it); `.spz` = gzip inflated by `DecompressionStream` behind a streamed byte counter (fflate's `gunzipSync` PRE-ALLOCATES the attacker-written ISIZE trailer, so it is aliased to a throwing stub), the count read from the first decoded bytes and refused before the rest is buffered, then the public `SPZLoader.prototype.parseRawSPZ`; SPZ v4 (`NGSP`, zstd) is refused because the vendored zstddec initialises by `fetch("data:application/wasm…")`, which the production CSP's `connect-src` blocks inside the srcdoc iframe (it would work in dev and on desktop and fail on every deployed host); `.ksplat` = the header count. A count of 0 is refused (a 0-instance splat allocates zero-size GPU buffers).
- **SH degree 0 is MANDATORY, not a simplification.** `parseBytes` deletes `sphericalHarmonics1..3` before `new GaussianSplat(...)` — the constructor derives the degree from exactly those attributes, so no band is ever allocated. MEASURED 2026-09-25: a degree-1 splat wrapped on the WebGL backend throws at shader build ("Cannot read properties of undefined (reading 'element')") — the wrapper pins the precomputed-SH vertex variant, whose contribution buffer only the WebGPU compute pre-pass creates. The loader also refuses to edit a splat whose `_sphericalHarmonicsVertexNode` is non-null (`WARN_SPLAT_SH`) rather than crash on one built by other code.
- **`normalize(geometry, size)` bakes the preview frame into the SOURCE arrays** (position − c, × s; covariance × s²; s = size / the longest 2σ-expanded extent — `GaussianSplat.computeBoundingBox`'s own rule), so a splat's `p` lands in the same ±0.8 frame `fit-bounds` bakes for a mesh and an SDF cutter tuned on a preset keeps its units. Object scale would render correctly (the addon projects centre and covariance through the model-view matrix) but would leave the shader reading AUTHORED units — the Vertex-Wave-on-a-180-unit-statue class of bug. `size: 0` keeps the file's units (a page that wants them).
- **The `splat-model` A-Frame component** (registered by the IIFE when the name is free): `src` through `THREE.FileLoader` (so the document's `setURLModifier` allow-list applies; the bytes are dropped from `THREE.Cache` after the load), `parseBytes`, `normalize`, `setObject3D('mesh')`, then `model-loaded` (what loader 0.8 and `fit-bounds` listen for — the `teapot-mesh` contract) and `splat-loaded { count, shDropped }`; any failure is `model-error { src, message }`; a stale generation drops a late parse. **It guards its own material**: an A-Frame `material` attribute on the same entity assigns ITS material to whatever lands in the `mesh` slot, and a GaussianSplat drawn through a MeshStandardMaterial is one flat grey quad per splat (measured in the editor preview, whose entity carried `material="color: #808080"`); the component re-asserts its NodeMaterial right after `setObject3D` — before `model-loaded`, so the shader component wraps the real one — and on every tick, with one warning. Never compile the material before its first `onBeforeRender`: on WebGL the PBO program is reached only through `updateSort`, and `setPBO` does not bump `material.version`.

### The no-fork hook — wrap the addon's `vertexNode`, replace its `onBeforeRender`

- **The 2026-09-09 study's "per-splat vertex edits need a fork" is WRONG.** The addon's `onBeforeRender` is a PUBLIC Object3D property assigned as an instance arrow (GaussianSplat.js:202-223); its only lines that read `material.vertexNode` re-impose the addon's own node when the material's differs, and then it calls two public, documented methods, `updateSphericalHarmonics(renderer, camera)` and `updateSort(renderer, camera)`. So a consumer wraps `material.vertexNode` in a `Fn` whose first statement is `inner.toVar()` (the addon's whole projection runs first), then edits the clip position and the named varying `vSplatColor` (a `varyingProperty` — aliased by name, one declaration per stage, GLSL and WGSL), and replaces `onBeforeRender` with an arrow that calls only the two public methods. `colorNode` is never touched (the Gaussian kernel and its `r² > 4` discard stay the addon's). Verified in real Chrome on both backends, on the r184 bundle.
- **What that costs and what it must not do.** Per INSTANCE, never shared: a wrapper built from instance A and assigned to B silently renders A's data (it closes over A's buffers). It reuses the addon's node OBJECTS `_buffers.centerRead` and `_sort.orderRead` (a second `storage()` over the same attribute without `setPBO` silently reads UNSORTED data on WebGL); those two private names — plus the varying names, `onBeforeRender`'s shape and the SH early return — are pinned by `fsSplatBundle.test.ts` against the vendored text, and a missing one degrades to "no edit + `WARN_SPLAT_SHAPE`", never a throw. On the real WebGL frame (the PBO program) the wrapper's two reads cost **two extra `texelFetch` per vertex** (7 vs the addon's 5, measured on r184 and r186) — the headless "reads merged, zero extra fetch" GLSL seen first was the NON-PBO program (autoSort off, no `onBeforeRender`), which drops the sort index entirely and is never what a frame runs. `splatRouteW.test.ts` builds the PBO configuration on purpose.

### Displacement — the clip rebuild, and the naive form that fills the screen

- **Adding `P·MV·(d, 0)` to the returned clip position is WRONG near the camera.** It moves the centre exactly and scales the footprint by z/z′, but it inherits the addon's near clamp, its 1024 px size clamp and its cull — all evaluated at the UNDISPLACED centre — so a splat moved into the 5 mm shell in front of the eye (A-Frame's `near` 0.005) is neither culled nor clipped and grows 100–250× (MEASURED 2026-09-25: a plane moved to view z −0.005 covered the whole screen). The wrapper instead REBUILDS: `centerOld = P·MV·(p,1)`, `offset = clip − centerOld` (the addon's clip-space corner offset), `centerNew = P·MV·(p + move, 1)`, `clip = centerNew + offset·s` — keeping the offset in clip units IS the physical z/z′ growth — with `s = min(size, 2048 / pxNew)`, the addon's own bound (a corner sits at 2σ, σ ≤ 1024 px), and the addon's cull predicate re-run on the NEW centre. A quad the addon already culled (snapshotted with `toVar` before the rebuild — `toVar` pins at declaration) stays culled. A first cut capped the growth at a flat 8× and left visible gaps between splats moved toward the camera; the pixel cap does not. Checked against ground truth: splats displaced by the wrapper cover the same pixels as data genuinely placed at that depth, pixel IoU 0.974–0.988 on both backends.
- **Accepted limits, documented rather than fixed.** The 2D covariance and the 0.3 px anti-alias dilation stay those of the undisplaced depth (shimmer for large depth changes); a splat culled at its undisplaced position stays culled. **Both sorts order by UNDISPLACED centres** (the CPU sort reads the source array; the GPU bin node reads `centerRead`): zero error for a translation, within the addon's own ~1.8° re-sort tolerance for a local view-depth tilt ≲ 0.03, visibly wrong beyond (5 cm on a 1 m wave ≈ 18° → boiling at the crests). So Move is for SMALL, SMOOTH fields. A WebGPU-only sort-follow through the public `sort.setBinNode` is feasible but needs a re-expressed bin node (no attribute or object-scoped nodes in a compute pass) and a forced per-frame sort through private fields, and it never helps the XR popup (always WebGL) — deferred.

### Loader 0.8's `splat` key — additive, inert, and why today's 0.8 drew a splat black

- **Before this change, loader 0.8 rendered a GaussianSplat opaque BLACK with no error.** `applyMaterialToMesh` replaced every `isMesh` node's material, and a module returning only an unknown key took the Simple-API branch (`material.colorNode = <the plain return object>`). The additive edit set (header delta 10): `hasSplat` joins `isObjectAPI` in `buildMaterials` (the `materialParts` precedent), `isGaussianSplat` guards in `storeOriginalMaterials`, `applyMaterialToMesh` (incl. the sole-mesh count), `restoreOriginalMaterials`, `syncBary` (a `toNonIndexed()` would lose `instanceCount`) and `syncWeld`'s root path; `wrapSplats`/`unsplat` (section 9b) with `unsplat` on every undo path (apply's catch, `Binding.dispose`, the component's remove, every re-apply through `disposeShaderMaterial`); `_splatWraps`/`_splatStatus` on both state shapes; `Binding.splats`; `SPLAT_PARAMS`; the event `shader-splat { src, splats }` BEFORE `shader-applied`. `isGaussianSplat` is undefined on every three Mesh and `shaderResult.splat` on every existing module, so every existing export renders as before (the parity suites run unchanged). A GaussianSplat under a module WITHOUT `splat` keeps its own material — it renders unshaded, which is correct. Spec functions are called directly, never through `.apply()` — a TSL `Fn` is a Proxy whose `.apply` reads the FnNode and is undefined.
- **The contract** (`return { splat: { shade?, shape?, size?, feather?, invert? } }`): `shade(p, pw, n, c) → vec4(rgb, opacity)`, `shape(p, pw, n, c) → vec4(move, cut)`, `size` and `feather` each a Fn / number / node; `p` = the object-space centre, `pw` = its world position, `n` = `normalize(cameraPosition − pw)` (the billboard's facing direction — a splat has no normal), `c` = the addon's `vSplatColor` (rgb clamped, alpha × alphaScale). `cutS = invert ? −cut : cut`, `keep = clamp(1 − cutS / max(feather, 1e-6), 0, 1)`, the quad collapses to `vec4(2,2,2,1)` when `cutS > feather`, and `vSplatColor = vec4(shade.rgb, c.a · shade.a · keep)`.

### The Splat Output (`splatOutput`) — sockets, the Cut SIGN rule, emission and parse

- **The node** — category `output`, its own flow type and component (`nodes/SplatOutputNode.tsx`, sections Shade [Color, Opacity] / Cut [Cut, Feather] / Shape [Move, Size], `SPLAT_DEFAULT_EXPOSED` = Color, Opacity, Cut, Move), `menus/SplatSettingsMenu.tsx` (the Raymarch menu shape + "Invert cut" as ONE history entry + the loaded scene's splat count from `previewSplatFacts`, shown only while the pane shows the splat — the CostBar's own `previewShowsModel` gate), the tile branch in `NodePreviewCard`. An absent `values.color` means the splat's OWN colour (emitted as `c.rgb`); `invert` counts only as the literal `true`. **Always offered** (owner decision) — it is also the 17th type the Designer cannot edit. Cost: `complexity.json` `"splatOutput": 2`, a flat UNCALIBRATED placeholder with no multipliers — the work is per vertex (4 per splat) plus the sort, which ShaderCarousel's per-pixel plane bench cannot price; the loaded splat COUNT is shown as a figure, never as points.
- **Cut is a SIGN test, a deliberate deviation from Discard's truthiness**: `cut > 0` removes, `≤ 0` keeps. The app's Discard culls on ANY non-zero value, negative included, and every distance field is negative inside — so a truthiness Cut wired to an `sdBox` would remove inside AND outside. With the sign rule an SDF on Cut keeps its inside and Invert keeps its outside; Feather fades the band just OUTSIDE the surface (the `sdfMask` shape).
- **Emission is up to FOUR `Fn(([p, pw, n, c]) => …)`, never a struct, never a Discard.** r184 cannot return a struct from `Fn`, and Color(3) + Opacity + Move(3) + Cut + Size is nine floats, so `sp1Shade` → `vec4(rgb, opacity)`, `sp1Shape` → `vec4(move, cut)`, `sp1Size` only when Size depends on a splat root, and `sp1Feather` only when Feather does — the loader reads Feather per VERTEX inside its cut test and fade, so a splat-dependent Feather emitted flat was read at each quad CORNER (a cell noise or a non-lattice scale tore the quad; `length(position)` gave every splat the same 2.83). A Size or Feather that does not depend on the splat rides the return object as the captured node or the stored number, Invert as the literal `true`; each Fn is omitted when it is the identity, and an active empty sink emits `return { splat: {} };` (the splat as loaded). **No `Discard(` is ever emitted into a splat program**: `tslCodeProcessor.extractDiscards` tracks no brace depth and LIFTS a statement-level Discard out of a nested Fn body into the module's `__pixel` (verified: an inner `Discard(cut…)` became a module-scope ReferenceError and `If(c, () => { Discard(); })` an unconditional cull) — cut is a returned VALUE. `buildShaderModule` carries the key through `translateSplatBody`, a whitelist (bare identifiers for the Fns, an identifier / member chain / finite literal for size and feather, the literal `true` for invert; everything else dropped); `CHANNEL_TO_PROP` is untouched. Names: `claimName('sp', aliases Shade/Shape/Size/Feather)`; `p`/`pw`/`n`/`c` are reserved from the namer only while a Splat Output DRIVES (a property is public API — schema key, A-Frame attribute, persisted-uniform key — so a parked or unwired Splat Output renames nothing; a property named `n` becomes `n2` exactly while the splat program is the module); codeToGraph reads `^sp\d+(Shade|Shape|Size|Feather)$` and the `splat` return object back, and FLAGS the parsed node active when no primary socket ends up wired (only a flagged sink emits such a program — unflagged, a fresh parse re-emitted the red sentinel); `scriptToTSL` keeps the `sp<n>` Fn blocks its nested-Fn skip would otherwise drop. A scope member also read outside every Fn is copied into the flat body TOGETHER WITH its in-scope ancestors (`marchPartition` closes `mainAlso` upward): a flat line names its inputs, and `remap(noise1, …)` with `noise1` declared only inside `sp1Shape` was a ReferenceError that failed the whole module (the march's depth-2 case too) — `splatOutput.test.ts` RUNS every emitted module and builds its Fns through loader 0.8's wrapper to catch that class.
- **The partition is the Raymarch Output's, generalised** (`utils/sdfPartition.ts`): `ScopeSpec { handle; sockets; params: { name, roots }[]; constants?; implicitRoots? }` — one scope may serve several sockets (Shade = Color + Opacity) and several parameter names; `MARCH_SCOPES` is restated with one socket and one `p`/`dir` param and emits byte-identically. `isCustomSink` (march or splat) is the shared predicate the sink sites use (`activeSink`, `normalizeActiveOutput`, `carryInactiveSinks`, `costSeeds`, the Output suppression, `previewWires`, `connectedUniforms`, `textureMemory`, `glbExportPlan`); march-only behaviour (the window sphere, double side, per-step cost) still asks `isMarchOutput`. Unlike the march, a feeder emitted in two splat Fns (or a Fn and the flat body) parses back as ONE node. **Preview mode on a splat document** routes the previewed socket to a clean flagged clone of the active Splat Output's Color (`nodePreview.ts`, `previewTargetId`; the always-mounted route line asks `previewRouteTargetId` in `activeSinkSelector.ts`, which reuses the memoised active sink and is pinned to agree with it) — a plain Output would paint nothing, because the loader never replaces a splat's material.

### Implicit geometry defaults inside a splat program

- **An unwired position default reads the QUAD CORNER in the splat vertex stage.** A noise with its position unwired emits `positionGeometry`, which in the instanced splat quad is the ±2 corner — identical for every splat and different per corner, so a noise on Cut would tear the collapsed quad and a noise on Color would not be per-splat at all. Inside a splat scope such a node is an IMPLICIT ROOT (`implicitRootOf`): it is emitted inside the Fn with its default replaced by the splat parameter (`mx_noise_float(p)`), while any flat-body copy keeps today's text, and codeToGraph folds the scoped form back to an UNWIRED position (never a stored `p`, which would re-emit a bare `p` outside the Fn). `SPLAT_CONSTANTS` binds the other quad-dependent roots per splat: `uv` → the front projection of the centre and `screenUV` → its place on screen (both since 2026-09-27; they were `vec2(0.5)`; a UV node's tiling/rotation/channel are dropped there — the screen binding reads its clip position through an arrow's parameter, `((clip) => clip.xy.div(clip.w))(…)`, so TSL computes the matrix product once instead of twice), `positionView`, `positionViewDirection`, `positionWorldDirection` and `rayDirection` from the centre, and `normalLocal` → `n` back in OBJECT space (`modelWorldMatrix.transpose().mul(vec4(n, 0)).xyz.normalize()`, the inverse of the normal matrix the loader applied). `n` itself is Normal (World) only: bound to both, Normal (Local) read a world normal that stayed put while the model turned under it, so a model-space pattern slid across a turning splat (review 2026-09-27). Known and accepted: the fragment-only derivatives of `stripes`/`isolines`/`wireframe` silently become their argument in a vertex stage (three emits `/*dFdx*/( x )`), and `tangentLocal` is unbound.

### React to light — the surface normal from the covariance, and the key light (2026-09-27)

- **What the owner asked for**: splats that react to light, the way Blender 5.3's do once the implicit Emission material is swapped for a Diffuse BSDF (Blender 5.3 was in alpha on 2026-09-26, beta from 09-30, release 11-10; its splats render with an emissive `radiance` material, and relighting is its "rudimentary" route). Until this change a splat could not react to light at all, and the 2026-09-26 assessment said so: the addon's material is a bare `NodeMaterial` (`lights = false`), scene lights never reach it, and the `n` a splat program read was the direction to the camera. A proposal to derive a normal from each splat's flattest axis had been judged "loader edit, unmeasured, not simpler" — against the checker-texture symptom, where a normal solves nothing. For RELIGHTING the flattest axis is the only orientation the data carries, and it is exactly what Blender shades with in Cycles and EEVEE alike (the "pancake" normal, flipped toward the viewer), so the rejection was reopened as an opt-in feature and built.
- **One key, two halves** (`utils/splatLight.ts`, the leaf every site reads). `values.lit` — only the literal `true`, the absent-key rule `invert` follows, and "off" DELETES the key — makes the module's return carry `lit: true` and puts ONE line inside the shade Fn:
  `const sp1Light = add(mul(<colour>, max(dot(n, normalize(add(vec3(<x>, <y>, <z>), 1e-9))), 0)), <ambient>);` and `return vec4(mul(<rgb>, sp1Light), <opacity>);`. The LOADER half is `lit: true`: loader 0.8 then passes each splat's own surface normal as `n`. The GRAPH half is the light line, visible in the code panel like the Raymarch Output's lambert. A graph that reads Normal inside a lit program reads the real normal too — Normal (World) as `n`, Normal (Local) in object space — so fresnel-style chains (`1 − dot(normal, view)`), which were identically zero on a splat, now work there. The `1e-9` (`SPLAT_LIGHT_DIRECTION_EPSILON`) is the zero-direction guard: all three numbers dragged to 0, or `sin(time)` wired to Light X with Y = Z = 0 on a paused preview (time 0), made `normalize` return NaN, which reached every lit splat's colour; with it the zero vector lights from the (1, 1, 1) diagonal and a real direction does not move in float32 (1e-9 is under half a float32 step of any component above 1/32 in magnitude). A guard in the SHADER, because a wired direction can pass through zero at runtime, where no emit-time check reaches (review 2026-09-27).
- **The normal: inverse power iteration on the covariance, started from the camera direction** (loader 0.8 section 9b, `splatSurfaceNormal`). The addon folds rotation and scale into `Σ = R·S²·Rᵀ` at load (the quaternion is gone on the GPU), packed `covA = (xx, xy, xz, yy)`, `covB = (yz, zz)`; the thinnest axis is the eigenvector of its smallest eigenvalue. Rather than an eigen-solve with a threshold, the wrapper takes three normalised steps of `adj(Σ/trace) + 1e-9·I` applied to the OBJECT-space direction to the camera, then the normal matrix, then a flip toward the camera. Measured in float32 over 20,000 random orientations per shape: a 10:1 disc 0.003° mean error, 100:1 0.003°, 3:1 0.6°, splat sizes 1e-9 m to 1 m identical (the trace division), no NaN for a zero, line or flat covariance. The START is the fallback, continuously and with no threshold to pop across: a round splat has nothing to converge to and keeps facing the camera (0.005° from the view direction), and a needle converges to the camera-facing normal of a cylinder (0.04°). The error is large only for a moderately flat splat seen within a fraction of a degree of edge-on, where it covers almost no pixels. It reads the addon's own `covarianceARead`/`covarianceBRead` node objects (setPBO'd by the addon — the `centerRead` rule); without them `n` stays the camera direction with ONE warning and the rest of the spec still applies. Cost: two storage reads and about 60 flops per vertex.
- **The light is WORLD space and MULTIPLIES the captured colour.** World, so a turntable moves the model under a fixed light (the Raymarch Output's light is object space — the two Light sections share names, not frames). The captured colour is radiance that already holds the light of the capture, so any Lambert double-lights, Blender's included ("albedo could be extracted … for better quality relightable splats" is still their TODO). The defaults therefore sum to 1: key 0.6 + ambient 0.4, so a splat facing the light keeps exactly its captured colour and the far side darkens to 40% — never brighter than captured. The direction defaults (0.6, 0.8, 0.5) are the Raymarch Output's and live in the registry's `defaultValues`; the two colours default to an emitted `vec3(l, l, l)` literal (which the parse reads back as UNSET), and their swatches are the sRGB hex of the same linear value (`#cbcbcb` = 0.597, `#aaaaaa` = 0.402), so picking the shown default emits what was already rendering.
- **The five Light sockets** (Light X/Y/Z, Light colour, Ambient — the march's labels, already in `lv.json`) come LAST in `def.inputs`, so a drop-connect still lands on Color, and belong to the SHADE scope while the node is lit (`splatScopes`), so a light that depends on the splat is read at its centre per splat. They are not primary sockets: a light never makes an unflagged Splat Output drive. **React to light** heads the Light section of the Splat Settings menu (`setSplatLit`, testable against the store): ON is one `updateNodeData`; OFF deletes the key, hides the five sockets and drops their wires in ONE bracket and keeps their stored values, so no wire points into a light that no longer exists and switching back on restores the same light. OFF writes the exposed list only when it listed a Light socket, so a node on the implicit default that is switched on and off again stays the node that was never touched. Two other paths had to agree, both found by the review: **Reset Values** keeps `lit` (`PRESERVED_KEYS`, the noise `signed` rule — it restores the light's numbers, not the mode; dropping `lit` there left a wired Light socket on an unlit node, a dead row whose wire the next Apply deleted silently), and **a code-panel Apply** carries the light values the module cannot hold (`carrySplatLightValues` in useSyncEngine's `mergeMatch`: all of them while the parsed node is unlit, a wired socket's value while lit — an unlit light is not in the code, so the parse reset it to the defaults). The Light rows are listed in the menu while lit or while a wire reaches one, and on the node while lit AND exposed (the standard opt-in rule) or wired — a file can still carry a wire into an unlit node, and no edge may point at an unmounted socket, nor be impossible to untick. The node's re-measure key is the SET of shown handles (exposed list, `lit`, and which Light sockets a wire reaches while unlit), so an undo that brings such a wire back re-measures and the edge draws. **A light wire with the light OFF is DORMANT**: an unlit node's scopes hold no Light socket (`splatScopes`), so its feeder is emitted in the flat body like any node nothing reads, and the resync CARRIES the wire (`carryDormantLightEdges` in useSyncEngine): carried only when the node was unlit before the Apply and is unlit after it, from a surviving source, into a socket the parse left unwired — and, like every resync carry, only inside the `unpositioned.length === 0` gate: a first cut ran outside it, and the second review showed a bare-script import (the previous document as the old graph, type-only pairing) wiring the new shader's Light socket from the old one's feeder. So an Apply that also adds a node drops a dormant wire, the gate's documented limit. The layout estimate counts a listed Light row lit or not (an unlit node draws a wired one, and wires are invisible there — over-estimating is the safe side). The first cut emitted the feeder as a dead line inside the shade Fn (forcing that Fn whenever the shade scope held a node) and still deleted the wire on every Apply with `errors: []` — the review's probe, positionWorld → length → Ambient on an unlit node.
- **Emission and parse are a pair.** The light line's name `sp<n>Light` is reserved with the Fns (a property already called `sp1Light` moves the splat to `sp2`), `translateSplatBody` whitelists `lit` as the literal `true` in the fixed order `shade, shape, size, feather, invert, lit`, and codeToGraph recognises the line by NAME and by exact SHAPE inside a shade Fn only. Lit is set only for the PAIR — the line, used by the shade's `mul(<rgb>, sp<n>Light)`, and `lit: true`; either half alone is dropped with a warning rather than guessed (the line never becomes a Multiply node). The default grey is recognised numerically, however it is spaced; the direction is read with or without the `1e-9` guard (a hand-written bare `vec3` re-emits guarded). The line's operands are read at the module's return but resolved with the SHADE Fn's bindings installed (`inSplatFn`, as the shade's own return is): without that, an inline `mx_noise_float(p)` typed into the light parsed to a STORED `p`, which re-emitted a bare `p` in the flat body — a ReferenceError at load that killed the preview (review 2026-09-27). The Ray Direction binding became `pw.sub(cameraPosition).normalize()` — it was `n.negate()`, the same number only while `n` was the camera direction (no splat program had shipped, so nothing moved for a user).
- **Verified in real Chrome, 2026-09-27** (headless Chrome with `--enable-unsafe-webgpu`, which gives a real Metal WebGPU adapter; plain headless has none and silently runs WebGL2): a synthetic sphere of 30,000 discs whose thin axis points outward. Normal wired to Color reads as a normal-map ball when lit (red right, green top, blue front) and one flat camera-facing blue when unlit; the default light shades the sphere from the upper right; WebGPU and WebGL2 give pixel-identical probes. At 1,000,000 splats, 20 synchronous renders drained on the GPU queue: WebGPU 23.9 ms lit against 24.1–25.7 ms unlit, WebGL2 18.4 ms lit against 17.4 ms unlit — no cost beyond run-to-run noise (the fragment blend dominates). A rAF measurement in the sandboxed frame with the frame cap off is meaningless (WebGL2 reported 0.1 ms frames); time renders synchronously. **Not run on a real capture yet** (none is in the repo) and not on a headset: real scenes mix discs with fuzzy volumes and needles, where a relit splat is only as good as its fitted shape.

### Simpler for non-technical users — projected UV, tint not paint, and the Normal notice (2026-09-27)

- **Why**: the owner wired the Checker preset to a Splat Output's Color and the whole scene went near-white, then asked how to mix a splat's colours with procedural textures "so non-technical people can play around". Reproduced in Chrome (mean RGB 188 with zero saturation). Two causes: inside a splat Fn `uv` was the constant `vec2(0.5)`, so every splat evaluated the same tile (#FAFAFA), and a wired Color REPLACED the captured colour, so even a working pattern erased the photo. The splat feature was committed (main 3687d7f) but not RELEASED (no tag after v0.3.33, the 0.8 loader still 404s on jsdelivr), so no user file could depend on either behaviour: both are changed as plain DEFAULTS, with no mode key to seed on fresh nodes and infer on every Apply — the earlier proposals' byte-stable variants (`uvFrom`/`uvSource` and `tint: true` stamped by `initialNodeValues`) were designed for shipped files and are unnecessary here.
- **UV is a front projection of the splat centre** (`SPLAT_CONSTANTS`): `p.xy.div(1.6).add(0.5)`. `splat-model`'s `normalize(geometry, size)` bakes the scene centred to a longest 2σ side of `size` (1.6, `utils/splatFrame.ts` — its own leaf, because `splatLimits.ts` must equal the runtime's frozen `LIMITS` export for export and `fsSplatBundle.test.ts` fails on a new key there), so `p.xy` spans ±0.8 and the projection maps the front of the scene to 0–1, u left to right and v bottom to top (three's uv convention), attached to the model as it turns. A Checker tiles across the splats, a Gradient ramps up them, an Image lands on them like a slide — the right way round seen from the front (+Z of the splat's own frame), since the Image node stopped baking a `1-u` into every picture (2026-10-08; until then the slide read mirrored, as on every primitive); from the side the pattern is extruded into streaks — the honest limit of a projection onto something with no surface. **Screen UV** is the centre's own place on screen, `clip.xy / clip.w · (0.5, −0.5) + 0.5` with clip = P·MV·(p, 1) — top-left origin, because three's `screenUV` follows WebGPU on both backends (ScreenNode flips `gl_FragCoord` on WebGL). Uv and screen UV used to share one constant and now have one each, so the parse's inverse (`implicitIdentifierOf`) maps each back to its own root. A UV node's own tiling, rotation and channel are still replaced by the binding; downstream math (the Checker's count) is what scales the board. A page running the export with `size: 0` (file units) gets every position- and UV-driven pattern laid out in those units instead — the export header and README say so, since the page author is the one who picks `size`.
- **Color tints, it does not paint** (`utils/splatColor.ts`): a wired or stored Color emits `vec4(mul(c.rgb, <colour>), <opacity>)` — a coloured gel, white keeps a splat as captured, black darkens it — and `values.replaceColor` (the literal `true`; off deletes the key) emits the colour alone, as before. The parse reads the mode off the return: `mul(c.rgb, X)` is a tint (no key), a bare `X` sets `replaceColor`, and the tint is matched BEFORE the own-colour test or it would parse as a Vertex Color → Multiply chain and grow the graph on every Apply. With nothing wired or stored the return is `c.rgb` in both modes, so the parse cannot see the key: the resync carries it then and only then (`carrySplatReplaceColor`, after `carrySplatLightValues`, in useSyncEngine's `mergeMatch`). Reset Values keeps it (`PRESERVED_KEYS`, a mode like `lit`). **Preview mode's clean clone REPLACES** (`values: { replaceColor: true }`): previewing a node means seeing its value, not the photo tinted by it. A LIT node's clone stays lit with an IDENTITY light (`lightColor` black, `ambient` white — `color(0xffffff)` is exactly 1.0 linear, so the light line is 1): the review found that dropping `lit` handed a previewed Normal chain the camera direction instead of the surface normal the real shader reads. The menu row "Replace own colour" follows the Invert rule (one `updateNodeData`). The price of the default: a Color the user builds FROM Vertex Color (the old way to keep the photo) now applies the captured colour twice (`c · f(c)`), so the Replace hint, the Vertex Color tooltip and README say to tick Replace for such a chain; detecting it automatically was weighed and declined, because a checkbox that stays unticked while the node replaces is worse than a sentence. The parse accepts the tint in every commutative spelling a hand edit produces (`mul(X, c.rgb)`, `c.rgb.mul(X)`, `X.mul(c.rgb)`) — the review found each of them silently flipping to replace with the `c.rgb` operand dropped.
- **The notice now covers what still fails silently.** With UV projected, a UV pattern no longer comes out flat, so the planned "no texture coordinates" notice would have nothing true to say. The remaining trap is a Normal-based effect — a rim, a fresnel, Toon Ramp, Edge Glow, Iridescence, Studio Shine — on an UNLIT splat, where both Normal nodes read the direction to the camera and the effect is flat with no error. `sinkModelIssue` returns `'splat-normal-faces-camera'` when a splat is shown, the Splat Output drives, it is not lit, and a node the splat program reads `n` through feeds it (`SPLAT_NORMAL_ROOTS` — Normal (World) is `n`, Normal (Local) the constant built from it — over the node's type AND over `implicitRootOf`: a noise whose stored position is `normalWorld` reads `n` too; one upstream walk, cycle-safe, that skips the Light sockets an unlit node reads nowhere). The walk runs from an always-mounted selector on every notify in the ordinary splat workflow, so its answer is kept while `sameGraphSemantics` holds — a drag frame reuses it instead of building maps per frame. The existing plumbing does the rest: the pane's standing notice, the canvas note on a graph-caused change only, never over another note, silent in a study session (which refuses splats anyway). "Graph-caused" excludes a React to light change in the same step (`litSplatCount`, a number selector): the review found that unticking the box posted a note telling the user to tick it.
- **Honest tooltips, both languages**: Vertex Color says it is the splat's captured colour (aliases "splat colour, own colour", so a search finds it); UV says it is projected from the front on a splat; both Normals say they point at the camera until React to light; the Splat Output's description states the tint, the projection and the normal rule. README carries the recipes. The UV presets (Gradient, Stripes, Checker, Circle, Color Ramp) needed no warning after all: they now work on a splat.

### Ingest — four kinds, the third trusted-side reader, caps, refusals, the study session

- **`PreviewMeshKind` gains `splat | spz | ply | ksplat`** (the kind stays the file extension), and every "glb means bytes, everything else means text" ternary became a per-kind predicate (`isGltfKind`, `isTextKind`, `isBinaryKind`, `isSplatKind`): a 30 MiB `.splat` is never `TextDecoder`-decoded, never offered the GLB dialog, never run through the glTF readers. `PreviewMesh.splat` carries the sniffed facts (derived, never persisted — the IndexedDB mirror keeps `{ name, bytes }` and every restore re-sniffs).
- **`utils/splatSniff.ts` is the THIRD documented trusted-side reader** (after the two JSON-header readers and `gltfReader.ts`): synchronous, bounded, never throws — `.splat` from the length alone (the pre-read gate refuses a misaligned or over-count `.splat` from `File.size` before any allocation), `.ply` from a ≤ 64 KiB header, `.spz` from its gzip header and ISIZE trailer or its `NGSP` header, `.ksplat` from its 4096-byte header and section headers at KSPLATLoader's real offsets. It refuses what the sandbox parse would refuse (ASCII PLY, `f_rest_*`, chunked PLY, more than one element, a truncated body, SPZ v4, zero counts), each with a sentence naming the conversion, so a user reads a localized pre-read refusal rather than a late sandbox error. **The `.ply` rules are ONE rule set implemented three times** — `splatSniff.ts` (where they are listed, in order, with the `extractHeaderText` lines they mirror), the runtime's `sniffPlyHeader` and podest's twin — and the three are held to one corpus (`SPLAT_SNIFF_CASES`): `podestSplat.test.ts` for the twin, `fsSplatBundle.test.ts` for the runtime (its gate AND `parseBytes` on every accepted case). Before 2026-09-26 each copy read the header its own way (first vs last `format` line, 16 vs 10 count digits, properties pooled across elements), so a hand-made header could be persisted by the editor and refused in the sandbox on every reload. `KHR_gaussian_splatting` GLBs are refused in `inspectParsedGltf` (r184's GLTFLoader only warns on the unknown extension and would hand the loader raw Points).
- **Caps** (`utils/splatLimits.ts`, a zero-import leaf; the same literals in the runtime's `LIMITS` and in podest, drift-tested three ways): `SPLAT_MAX_COUNT` 1,000,000 (refusal), `SPLAT_HEADSET_ADVISORY_COUNT` 250,000 (an info line, never a refusal — derived from the M4 Max sort timing and a GUESSED ~4× Quest-class factor; a Quest 3 has not been measured), `SPZ_MAX_DECODED_BYTES` 96 MiB, `PLY_HEADER_SCAN_BYTES` 64 KiB. **`MESH_MAX_BYTES` stays 64 MiB for every kind** — the zip SUM cap, podest's `MAX_SAVED_MODEL` and the export pre-flight all derive from it, so a per-kind byte cap would cascade.
- **A splat dropped on a graph with NO Splat Output asks whether to clear the node graph** (owner, 2026-10-01; `Modals/SplatGraphModal.tsx`, `Preview/useSplatGraphAsk.tsx`, `utils/splatGraphStart.ts`). Every other sink is wrong for a splat (a plain Output is a material, a Raymarch Output cannot march through one — `sinkModelFit.ts`), so the graph on the canvas cannot shade the scene that just arrived. The answers: **Keep graph** (the splat loads, the graph stays), **Clear graph** (`startSplatGraph` — nodes, wires and board drawings become ONE Splat Output flagged as the active sink, the DOCUMENT stays: name, palettes, tuned uniforms, the Work-folder file; one undo entry; `fs:graph-merged`, never `fs:graph-imported`, exactly like `commitGlbImport`) and Cancel (nothing loads). The starter is flagged so it drives from the start (the identity program until something is wired) and a plain Output added later arrives inactive. It asks only for a splat `createPreviewMesh` ALREADY accepted — a refused file never asks — and never on an empty canvas (nothing to clear), never when any Splat Output is present (active or not), never for a splat paired with a shader (`offerBuild: false`: the drop, a zip's `models/` entry), never on the IndexedDB boot restore, and never in a study session (splats are refused there before the read). Clear runs BEFORE the splat loads, in the same click, so the pane and the sink-fit note never see the cleared graph without it. While the question is open every other model or shader drop is refused with the model-import busy notice, the GLB dialog's rule (`glbFlow.busy() || splatAsk.busy()`). No "don't ask again".
- **A study session refuses splats on every entry path** — the drop (before the pre-read gate), a zip entry (`zipModelOutcome`) and the IndexedDB boot restore — so the study host never serves the runtime file. The Splat Output TILE is still offered there (owner decision); with no splat allowed, the pane notice says why it cannot render.

### The preview documents, the XR popup, export and podest

- **A splat document differs from a mesh document only where it must.** The runtime `<script>` right after the a-01 tag, `splat-model="src: url(<blob>); kind: …; size: 1.6"` set by the feed (`splatFeedScript(kind)`, the splat twin of `MESH_FEED_SCRIPT` in `engine/tslToPreviewHTML.ts`; one `MODEL_FEED_KINDS` table shared with the parent), `fit-bounds` with `regen: false`, no `gltf-anim`, no decoder config, and **no `material` attribute on `#preview-entity`** (see the component's material guard). The ONE change every other document carries is `FIT_BOUNDS_SCRIPT`'s early return on `isGaussianSplat` (it is registered unconditionally so a primitive can hot-swap into a model) — never clone the instanced quad, never `Box3.setFromObject` it (that measures the ±2 template). A splat is cold only through `custom:<id>`; a module edit hot-swaps (`fs:shader`) and re-wraps the same GaussianSplat. The inventory reports a splat as ONE nameless row on `MeshInventory.splat`, never in `meshes`, so it can never become a part target; the highlight never lights it. **Up-message** `fs:model-splat { geometry, count, shDropped }` — accepted only from the iframe's own window, for the current mesh id, with a safe integer count ≤ the cap and `shDropped` 0–3 — lands in the session-only, display-only `previewSplatFacts` (cleared by every `setPreviewMesh`), which drives the headset advisory, the dropped-SH line, the CostBar figure and the menu's count line. **Opening a shader clears a loaded model** (the existing text-import rule — a stale mesh must not satisfy the new document or ride into its export zip), so the flow is: open the shader, then drop the splat, or drop both together.
- **The XR popup** sets the same `splat-model` with the parent-minted blob URL and loads the runtime same-origin; it is always WebGL, so it is the CPU-sort path.
- **Export**: the bundle's `models/<name>.<kind>` is the original file; the README pairing snippet adds the runtime `<script>` and a `splat-model` entity; the module header gains a GAUSSIAN SPLATS block (only when the module returns `splat` — every other export byte-identical) naming the runtime and the entity; the single-GLB export is refused for a splat mesh (`GlbExportUnavailable` 'splat') and for a splat-DRIVEN graph ('splat-driven', at build time with "Export as .zip instead"). The A-Frame tab is unchanged: it is defaults-only and describes no model.
- **Podest** carries a hand-written ES5 twin of the sniff (`sniffSplatHeader`, same literals and sentences — `podestSplat.test.ts` runs it against the SAME fixture corpus as `splatSniff.test.ts`, the builders living in `src/test-utils.ts`), includes the runtime only while a splat is loaded (the stage is rebuilt once by `reloadStageForSplat` when a splat lands on a runtime-less document), and its `fit-bounds` twin carries the same early return.

### Measurements, and what is deferred

- **Phase 0 spike, 2026-09-25** (headless real Chrome on the dev origin, the vendored r184 bundle; M4 Max, 60 Hz cap): 100k and 500k splats hold 16.7 ms median on both backends, 1M ≈ 21–27 ms; the WebGL CPU sort ≈ 0.8 ms per 100k per re-sort (one per ~1.8° of accumulated view change); the wrapper adds no measurable frame time; parse ≈ 55 ms per 1M rows. **No headset has run any of it** — the 250,000 advisory is a guess until a Quest 3 does.
- **Deferred, each a real feature rather than a tweak**: SH degree ≥ 1 (a third private handle and the per-backend vertex variant), a WebGPU sort-follow for Move, SPZ v4 (a wasm-from-bytes zstd or `data:` in `connect-src`), `KHR_gaussian_splatting` GLBs (the r186 extension loader plus the trusted-side reader learning the primitive), per-fragment effects inside a splat (a `colorNode` wrap over `vSplatUv` — which is also what per-pixel lighting of a splat would need), deformations that rotate the covariance (a shadow copy of the projection), and a calibrated price.
